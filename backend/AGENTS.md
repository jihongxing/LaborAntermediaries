# 后端代码注释规则

本规则适用于 `backend/` 全部新增或修改代码，不能因为代码位于基础设施包、配置类或测试目录而省略注释。

- Java 类、接口、枚举、record 及嵌套类型必须有中文 JavaDoc，说明职责、使用边界与必要的安全约束。
- 所有手写方法和构造器必须有中文 JavaDoc，包括 private、接口方法、重写方法和 record 紧凑构造器。
- 方法注释说明行为、前置条件及副作用；有参数、类型参数、返回值时写 `@param`、`@return`，显式声明的异常写 `@throws`；
  重要的运行时异常、权限拒绝、事务回滚及资源释放责任也应说明，不能只重复方法名。
- 字段、常量、配置项必须说明含义；配置项补充默认值、单位和限制。record 组件使用类型 JavaDoc 的 `@param` 说明。
  Lombok/编译器生成的方法不要求展开成手写代码，但对应字段或组件必须有说明。
- 安全校验、组织隔离、加密协议、幂等、事务、资源清理、并发锁、租约和重试等不直观逻辑必须就近解释原因与边界。
  不要求逐行翻译赋值语句，也不使用无意义占位注释。
- 测试应说明场景和预期；其他语言、脚本和配置采用各自支持的注释语法。JSON 等不支持注释的格式在相邻 README 说明，不能破坏格式。
- 修改实现时同步更新注释；禁止在注释中写入真实密钥、凭证或个人敏感数据，禁止承诺实现并不保证的行为。
- 提交前检查类型、方法、字段和关键逻辑的说明，并运行 `mvn validate`。当前 JavaDoc 缺失自动检查覆盖
  `src/main/java/com/company/labor/foundation/` 和 `src/main/java/com/company/labor/common/`；
  其他目录同样遵守规则，自动检查范围应在其历史缺口补齐后扩大。

详细规则入口：仓库根目录 `CLAUDE.md` 的“注释规范（强制）”；运行与验证说明见 `backend/README.md`。
