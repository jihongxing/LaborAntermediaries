## 目录规划与新增文件规则

本节与各端 README 的“目录规划与新增文件规则”是后续新增文件的放置依据；其余历史技术栈版本、功能示例和启动命令不因此成为已批准选型或当前可运行能力。目录模板按需落地，不预建空模块、空分层，不在本次规划中初始化工程。

### 共同原则

- **先业务、后分层**：Web 和小程序使用 `modules/<module>`，Flutter 使用 `features/<feature>` 归集业务代码。页面、业务请求、状态和模型跟随业务，不建立汇集全系统业务文件的 `api`、`store`、`models` 或 `utils` 大目录。
- **公共代码有准入条件**：不含具体业务语义的 UI、纯工具可以进入 `shared`；网络、会话和平台访问等基础能力在 Web、小程序放 `platform`，在 Flutter 放 `core`。只服务一个业务的代码留在业务内部，不因“以后可能复用”而上提。
- **依赖保持单向**：应用装配引用业务模块与基础能力，业务模块引用公共能力；公共能力不直接引用业务模块。平台能力需要业务策略时，通过注入回调或小接口接入，不反向导入业务实现。
- **跨模块显式调用**：通过模块公开入口或小接口协作，不深层导入其他模块的页面、内部状态或数据访问实现，不建立循环依赖。路由入口和跨模块契约只公开必要内容，避免把所有内部文件统一导出。
- **跨端不直接导入源码**：三端可共享需求、接口契约、设计规范和合成测试样例，不互相引用另一端的页面、状态或运行时实现。出现真实跨端复用需求后，再评估独立共享包、版本与验证策略，不预建 `frontend/shared`。
- **安全规则不随目录变化**：客户端环境配置可被用户获取，不存放服务端密钥；不以路由守卫或界面隐藏替代后端授权。日志、测试数据和本地存储不得包含真实令牌或个人敏感资料。

### 新增与拆分流程

1. 先确认属于哪个端、哪个已批准业务；属于已有业务时放进现有模块，不按每张页面或每个接口新建顶层模块。
2. 再选择模块内职责目录；局部 UI、样式、状态、请求模型及测试优先与业务就近组织，不集中到公共目录。
3. 只有出现独立业务职责才新增模块；出现稳定且无业务归属的复用需求才提取公共能力，不为了保持三端目录对称而创建文件。
4. 当一个目录承担多种独立职责、一次修改通常只涉及其中一组文件，或文件名频繁使用 `helper`、`manager`、`misc` 时，按职责拆分。文件数只是评审信号，不设置机械上限，也不强制为每个实现配接口。
5. 新增模块时同步放置测试与必要资源；新增顶层目录、改变模块职责或工程源码根时，更新对应端 README。复杂模块按需补充局部 README，说明公开入口与依赖限制。

### 分端指南

| 端 | 业务组织 | 特有约束 | 详细放置规则 |
|---|---|---|---|
| Web 管理端 | `src/modules/<module>/` | 应用装配、路由汇总和布局与业务代码分离 | [Web 目录指南](web-admin/README.md#目录规划与新增文件规则) |
| Flutter App | `lib/features/<feature>/` | 业务与平台插件隔离，测试镜像 `lib` 结构 | [App 目录指南](mobile-app/README.md#目录规划与新增文件规则) |
| 微信小程序 | 源码根下 `modules/<module>/` | 页面注册、主包入口与分包归属需要共同设计 | [小程序目录指南](mini-program/README.md#目录规划与新增文件规则) |

## 禁止事项

- 禁止将旧 SaaS 功能列表视为当前交付范围，或因某端方便实现而擅自缩减其他端范围。
- 禁止提交真实 Token、生产配置和用户资料；前端权限隐藏不得替代服务端授权。
- 禁止在客户端固化待审奖励费率、支付资格或以界面展示作出无条件收益承诺。

## 📋 项目概述

本项目包含三个前端应用：

1. **Web管理后台**：Vue 3 + Element Plus（管理员、财务、项目经理使用）
2. **移动App**：Flutter（驻场人员、项目经理使用）
3. **微信小程序**：uni-app（经纪人、员工使用）

## 🎨 设计规范

### 通用规范

- **命名规范**：Vue 文件与 Dart 文件分别遵循各端约定；类型使用大驼峰（PascalCase），变量使用小驼峰（camelCase）
- **代码风格**：Web、小程序按各端配置使用 ESLint / Prettier；Flutter 按 `analysis_options.yaml` 与 Dart 格式约定检查
- **注释规范**：重要逻辑必须添加注释

### 接口调用规范

所有端统一使用RESTful API：

```javascript
// 基础URL
const API_BASE_URL = 'https://api.example.com'

// 统一响应格式
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "timestamp": 1697520000000
}
```
