## 🚀 项目概况

### 核心价值

通过统一交易流程和可核验数据，连接用工单位与合规劳务公司，降低需求发布、供应商选择、项目履约协同及结算对账成本。

### 业务模式

交易网络参与方：
- **用工单位**：定义真实需求、选择供应商并确认约定履约结果
- **劳务公司**：应标并依据实际合同组织合规供给与履约
- **个人经纪人/招聘渠道**：按劳务公司授权协助人员供给，不直接替代劳务供应商
- **工人**：参与岗位履约并形成可核验的工时与报酬记录
- **平台**：提供交易组织、数据核验、计费、对账及状态追溯基础设施

### 产品形态

连接用工单位与合规劳务公司的多边交易平台，围绕真实需求、供应商应标、履约核验、分类结算和资金状态构建完整交易链路。

> 当前业务需求以[自主推进需求基线 v0.4](01-售前阶段/需求分析/requirements-draft-v0.4.md)和配套 PRD 为准；商业模式与收费规则只以[唯一商业模式文档](02-开发阶段/产品设计/商业模式与收费标准-v0.1.md)为准。人天管理费采用用工方主导的0.5–5.0元固定档位（每0.5元一档），0.5元为平台基准，超额分账档次见唯一商业模式文档（默认平台40%/用工方60%）；实际收取结算仍按获批合同及结算规则执行。100元线索解锁价格已批准，但收取结算规则批准并配置前不得实际上线收费。v0.3 中“只从用工方回款分账扣收”“统一管控账户/T+0”仍为历史方案，不作为当前默认决定。

### 技术端口

- **Web**：平台运营审核与组织管理、复杂配置、批量考勤核对及结算工作台
- **独立 App**：项目经理、驻场和授权人员的现场履约、考勤异常核验与协同，属于完整平台范围
- **微信小程序**：工人本人班次、上下班打卡、工时查看/补正；经纪人授权岗位分享、提报与归属/返费查询
- **多端范围**：各端建设顺序按业务依赖安排，不以暂缓某一端缩减产品范围
- **考勤闭环**：平台排班 → 工人小程序打卡 → 平台计算工时 → 异常/补正/复核 → 按规则确认并形成计薪/结算依据；外部考勤仅作独立比对，不覆盖平台原始事件

## 📁 文档使用指南

### 如何查找文档？

1. **按阶段查找**：先确定当前处于哪个阶段（售前/开发/交付/运维），进入对应的阶段目录
2. **按类型查找**：需求、报价、设计、测试等，在各阶段目录下的子目录中
3. **按关键词搜索**：使用IDE的全局搜索功能（Ctrl+Shift+F）

### 如何贡献文档？

1. **遵循命名规范**：
   - 英文文件名小写+连字符（如 `requirements-draft-v0.2.md`）
   - 中文文件名可直接使用中文（如 `劳务中介管理系统-模块化报价方案.pdf`）

2. **遵循目录结构**：
   - 按阶段分类，放到对应的子目录
   - 会议纪要、变更记录等放到 `00-项目管理/`

3. **版本管理**：
   - 重要文档更新时增加版本号（如 v0.1 → v0.2）
   - 旧版本移动到 `归档文件/`

4. **更新索引**：
   - 新增重要文档后，更新各阶段的 `README.md`
   - 更新本文档（主索引）的快速导航
