### P0-1：闪电发薪的技术实现方案

**问题描述**：
"劳务公司账户充值后发工资"这个模式，在技术和法律层面有三种实现方式，需要明确选择哪一种。

**选项对比**：

| 方案 | 技术实现 | 资质要求 | 资金风险 | 开发成本 | 推荐度 |
|---|---|---|---|---|---|
| **A. 虚拟账户 + 资金托管** | 平台开银行账户，劳务公司充值到平台，平台代发 | **需要支付业务许可证** | 平台承担资金风险 | 高（需要支付系统） | ❌ 不推荐 |
| **B. 第三方支付通道** | 劳务公司充值到微信商户/支付宝商户，系统调用API代发 | 不需要牌照，但需要商户资质 | 第三方承担 | 中（对接API） | ✅ 推荐 |
| **C. 银行代发接口** | 对接银行企业网银API，劳务公司在银行开户 | 不需要牌照 | 银行承担 | 中（每家银行接口不同） | ✅ 可选 |

**关键问题**：
1. 是否已有支付业务许可证？
   - [ ] 有（可选方案A）
   - [ ] 没有（只能选B或C）

2. 更倾向于哪种方案？
   - [ ] 方案B：第三方支付（微信/支付宝）
   - [ ] 方案C：银行代发
   - [ ] 方案A+B：先用第三方，未来申请牌照

3. 如果选方案B，支持哪些支付渠道？
   - [ ] 微信支付（企业付款到零钱）
   - [ ] 支付宝（批量转账到支付宝账号）
   - [ ] 两者都支持

4. 充值方式？
   - [ ] 对公银行转账（T+1到账）
   - [ ] 企业网银实时充值
   - [ ] 预充值 + 消费

5. 发薪到账时间要求？
   - [ ] 实时到账（成本高）
   - [ ] T+1（常规）
   - [ ] T+N（低成本）

**影响范围**：
- 系统架构：是否需要独立的支付模块
- 财务模块：账户体系设计
- 合规风险：是否需要申请牌照
- 开发周期：3-8周不等

**问题描述**：

| 方案 | 业务模式 | 资质要求 | 合规风险 | 收入模式 | 推荐度 |

| **A. 系统仅做费用管理** | 劳务公司自己去保险公司买，系统只记录费用 | 不需要 | 无 | 无（只是功能） | ⚠️ 最安全但无增值 |

   - [ ] 方案B：自己做（需要先申请牌照）

### P1-5：返费达标档次的配置规则（新增）

**问题描述**：

- 标准档次：3天、7天、15天、30天、60天、90天

| 场景 | 配置 | 员工情况 | 结算结果 | 待确认 |

### P1-6：日结工和月结工的系统差异（新增）

**问题描述**：
员工分为日结工和月结工，两者在工资计算、发放、借支等方面都有差异，需要明确系统如何区分和处理。

**差异对比**：

| 维度 | 日结工 | 月结工（劳务派遣） |
|---|---|---|
| **发薪周期** | 当日或次日 | 按月（每月固定日期） |
| **工资计算** | 当日工时 × 日工价 | 月度总工时 × 工价 + 补贴 - 扣款 |
| **扣款项** | 简单（一般无扣款） | 复杂（借支、住宿、保险等） |
| **借支** | ❓ 是否允许？ | 允许 |
| **工资条** | 每日一条？还是月度汇总？ | 月度工资条 |
| **发薪频次** | 每天都有（高频） | 每月1次（集中） |
| **返费规则** | ❓ 按天算还是按工时？ | 按天数或工时 |

**关键问题**：
1. 员工类型如何标记？
   - [ ] 岗位级别（岗位标记日结/月结，入职时继承）
   - [ ] 员工级别（每个员工可以单独标记）
   - [ ] 两者都支持（岗位有默认值，员工可覆盖）

2. 日结工是否允许借支？
   - [ ] 不允许（当日即结算，无需借支）
   - [ ] 允许（但额度计算逻辑不同）

3. 日结工的工资条如何展示？
   - [ ] 每日一条（员工可查看每日工资明细）
   - [ ] 月度汇总（每月1条，汇总当月所有日结记录）

4. 日结工的返费规则？
   - [ ] 按在职天数计算（如满7天给¥100）
   - [ ] 按工时计算（每工时¥2）
   - [ ] 不给返费（日结工流动性强）

5. 闪电发薪的资金压力？
   - 假设5000人中，日结工占比30% = 1500人
   - 每人每日工资¥200，每日需要发薪 1500 × ¥200 = ¥30万
   - 劳务公司账户需要保持多少余额？是否需要预警？
   - [ ] 需要余额预警（低于¥50万时提醒充值）
   - [ ] 需要自动充值（余额不足时自动从绑定账户划款）
   - [ ] 不需要（人工充值即可）

6. 日结工的工时管理？
   - [ ] 也需要双数据源对比（工厂考勤 + 员工自报）
   - [ ] 简化流程（只要工厂考勤，或只要员工自报）

**对系统设计的影响**：
- 员工/岗位表需要增加"工资类型"字段
- 工资核算逻辑需要分两套（日结逻辑 + 月结逻辑）
- 闪电发薪需要考虑日结工的高频发薪
- 借支模块需要判断员工类型，控制是否可借
