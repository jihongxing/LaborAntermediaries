# 劳务中介管理系统 · 配置层级与作用域

**核心设计原则**：运营策略不写死在代码里，通过配置实现灵活运营。

---

## 一、配置层级体系

```
┌─────────────────────────────────────────┐
│   平台级配置（Platform Config）          │
│   作用域：整个SaaS平台                   │
│   管理者：平台运营方                     │
└─────────────────────────────────────────┘
              ↓ 继承 + 覆盖
┌─────────────────────────────────────────┐
│   租户级配置（Tenant Config）            │
│   作用域：单个劳务公司                   │
│   管理者：劳务公司管理员                 │
└─────────────────────────────────────────┘
              ↓ 继承 + 覆盖
┌─────────────────────────────────────────┐
│   项目级配置（Project Config）           │
│   作用域：单个项目/岗位                  │
│   管理者：项目经理                       │
└─────────────────────────────────────────┘
```

**继承与覆盖原则**：
- 下层可以继承上层配置（如果不设置，使用上层默认值）
- 下层可以覆盖上层配置（在权限范围内）
- 上层可以限制下层的配置范围（如平台限制租户只能设置3-90天的返费档次）

---

## 二、平台级配置（Platform Config）

**作用域**：整个SaaS平台，全局生效

**管理权限**：平台超级管理员（你们公司运营人员）

**管理入口**：超级管理后台（独立于租户后台）

---

### 1. 增值服务配置

| 配置项 | 说明 | 默认值 | 客户答复 |
|---|---|---|---|
| 基础版项目配额 | 免费项目数量上限 | 5个 | ✅ 5个 |
| 基础版是否收费 | true/false | false | ✅ 免费（但可设置） |
| 基础版年费金额 | 如果收费，年费多少 | ¥0 | ✅ 暂时¥0，未来可调整 |
| 基础版功能清单 | 包含哪些功能模块 | 见下方 | ✅ 已确认 |

**基础版功能清单（平台定义，不可修改）**：
- ✅ 账号权限管理
- ✅ 客户/项目/岗位管理
- ✅ 员工档案管理
- ✅ 考勤工时管理（双数据源）
- ✅ 工资核算（计算工资，但不能发薪）
- ✅ 工资条查看（员工小程序）
- ✅ 返费自动计算（计算返费，但不能发薪）
- ✅ 基础财务台账
- ✅ 保险管理
- ❌ 招聘管理（需要开通"发布岗位"增值包）
- ❌ 借支管理（需要开通"借支功能"增值包）
- ❌ 闪电发薪（需要开通"发薪功能"增值包）

**增值服务定价表（平台可随时调整）**：

| 增值服务 | 计费方式 | 默认价格 | 说明 |
|---|---|---|---|
| 超出项目配额 | 按项目/年 | 可设置 | 超过5个项目，每增加1个项目收费 |
| 发布岗位功能 | 按项目/年 或 按公司/年 | 可设置 | 开通后才能使用招聘管理模块 |
| 借支功能 | 按项目/年 或 按公司/年 | 可设置 | 开通后才能使用借支申请和审批 |
| 发薪功能（闪电发薪） | 按项目/年 或 按公司/年 或 按笔收费 | 可设置 | 开通后才能系统内发薪 |
| 保险代购服务 | 按人头 或 按保费比例 | 可设置 | 差价收入 |

**设计要点**：
- 所有价格都是可配置的，不写死在代码里
- 计费方式也是可配置的（按项目、按公司、按笔数、按人头）
- 平台运营方可以随时调整价格策略
- 新租户注册时，自动应用当前的价格策略
- 老租户不受影响（除非手动调整）

### 3. 返费政策配置（重点！）

#### 3.1 返费模式选择

| 配置项 | 说明 | 客户答复 |
|---|---|---|
| 返费模式 | 纯人头费 / 纯工时费 / 混合模式 | ✅ 按项目配置 |

#### 3.2 人头费配置（多档位）

| 档位 | 达标天数 | 返费金额 | 是否累加 |
|---|---|---|---|
| 档位1 | 3天 | ¥50 | |
| 档位2 | 7天 | ¥100 | |
| 档位3 | 30天 | ¥500 | |
| 档位4 | 60天 | ¥800 | |
| 档位5 | 90天 | ¥1000 | |

**累加模式选择**：
- 方案A：累加（达到30天给¥50+¥100+¥500=¥650）
- 方案B：取最高（达到30天只给¥500） ✅ **默认方案**

**客户答复**：
- ✅ 按项目配置（每个岗位自己决定）
- ✅ 默认选择方案B（取最高），但可配置

**未达标离职处理**：
- ✅ 给已达标的档位（如干了8天离职，给7天档位的¥100）

**配置界面设计**：

```
│                                     │
```

#### 3.4 混合模式配置

**客户答复**：
- ✅ 人头费和工时费是**分开结算**的
- ✅ 人头费是**一次性的**，达到哪个标准结算哪个标准的费用
- ✅ 如果选择"取最高"模式：
  - 达到7天给¥50
  - 达到30天再给¥300-¥50=¥250（因为已经结算过¥50了）
- ✅ 工时费与人头费无关，只要在职在岗，工时费按 工时×单价 结算

**系统实现逻辑**：
```
混合模式（人头费 + 工时费）：

时间轴：
Day 1-6:  无返费
Day 7:    人头费¥50（第一档达标）
Day 8-29: 工时费累计（但未到30天起算条件，不结算）
Day 30:   人头费¥250（¥300-¥50，第二档达标）
          + 工时费开始计算（假设8小时/天 × 30天 × ¥2 = ¥480）
Day 31+:  只有工时费继续累计，人头费已结完
```

**配置界面设计**：
```
┌─────────────────────────────────────┐
│ 返费模式：                          │
│   ○ 纯人头费                        │
│   ○ 纯工时费                        │
│   ● 混合模式（人头费 + 工时费）      │
├─────────────────────────────────────┤
│ 人头费配置：                        │
│   [展开人头费配置界面]              │
│                                     │
│ 工时费配置：                        │
│   [展开工时费配置界面]              │
│                                     │
│ 结算说明：                          │
│   • 人头费和工时费分开结算           │
│   • 人头费一次性，达标即结算         │
│   • 工时费持续结算，直到离职         │
└─────────────────────────────────────┘
```

#### 3.5 日结工返费规则

**客户答复**：
- ✅ 日结工按**天数计算**，做几天返几天的费用
- ✅ **不涉及工时**，只看在职天数
- ✅ 结算给经纪人的费用与员工工资天数一致

**配置示例**：
```
日结工返费配置：
  返费单价：¥10/天
  起算条件：入职满1天即开始
  计算公式：在职天数 × ¥10
  
举例：
  员工干了8天 → 经纪人得¥80
  员工干了15天 → 经纪人得¥150
```

## 五、配置继承与覆盖示例

### 示例1：撞单保护期

```
  允许范围：3-30天
```

### 示例2：返费政策

```
平台级配置：
  返费档次范围：3/7/15/30/60/90天
  
租户级配置（劳务公司A）：
  返费结算周期：按月
  返费发放方式：人工审核
  
项目级配置（项目1 - 普工岗位）：
  返费模式：纯人头费
  档位：7天¥100、30天¥500
  累加模式：取最高
  
项目级配置（项目2 - 技工岗位）：
  返费模式：混合模式
  人头费档位：7天¥150、30天¥800
  工时费：¥3/小时，入职满30天起算
```

## 六、数据库设计建议

### 1. 平台配置表（platform_config）

```sql
CREATE TABLE platform_config (
  id BIGINT PRIMARY KEY,
  config_key VARCHAR(100) UNIQUE NOT NULL,  -- 如'base_project_quota'
  config_value TEXT,                         -- JSON格式存储
  config_type VARCHAR(50),                   -- 'number','boolean','json'
  description VARCHAR(500),
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

### 2. 租户配置表（tenant_config）

```sql
CREATE TABLE tenant_config (
  id BIGINT PRIMARY KEY,
  tenant_id BIGINT NOT NULL,                 -- 租户ID
  config_key VARCHAR(100) NOT NULL,          -- 配置项
  config_value TEXT,                         -- JSON格式
  is_override BOOLEAN DEFAULT FALSE,         -- 是否覆盖平台默认值
  created_at TIMESTAMP,
  updated_at TIMESTAMP,
  UNIQUE(tenant_id, config_key)
);
```

### 3. 项目配置表（project_config）

```sql
CREATE TABLE project_config (
  id BIGINT PRIMARY KEY,
  project_id BIGINT NOT NULL,                -- 项目ID
  config_key VARCHAR(100) NOT NULL,
  config_value TEXT,
  is_override BOOLEAN DEFAULT FALSE,         -- 是否覆盖租户默认值
  created_at TIMESTAMP,
  updated_at TIMESTAMP,
  UNIQUE(project_id, config_key)
);
```

### 4. 返费政策表（rebate_policy）

```sql
CREATE TABLE rebate_policy (
  id BIGINT PRIMARY KEY,
  project_id BIGINT NOT NULL,
  policy_type VARCHAR(20),                   -- 'headcount','worktime','mixed'
  accumulation_mode VARCHAR(20),             -- 'cumulative','highest'
  unqualified_rule VARCHAR(20),              -- 'qualified_only','none','proportional'

  updated_at TIMESTAMP

-- 人头费档位表
CREATE TABLE rebate_headcount_tier (
  id BIGINT PRIMARY KEY,

  sort_order INT,                            -- 排序

-- 工时费规则表
CREATE TABLE rebate_worktime_rule (
  id BIGINT PRIMARY KEY,

  rate_per_hour DECIMAL(10,2),               -- 每工时单价
  start_after_days INT DEFAULT 30,           -- 入职满N天开始
```

## 八、配置校验规则

### 1. 平台级校验

- 增值服务价格不能为负数
- 返费档次天数必须递增（7天必须在3天之后）
- 借支额度比例范围必须在0-100%之间

### 2. 租户级校验

- 撞单保护期必须在平台允许范围内
- 借支额度比例必须在平台允许范围内
- 返费档次只能从平台提供的选项中选择

### 3. 项目级校验

- 返费金额必须大于0
- 人头费档位的达标天数不能重复
- 工时费起算天数不能小于0
- 日结工不能开启借支功能

## 九、总结

### 核心设计原则

1. **分层配置**：平台 → 租户 → 项目，清晰的作用域
2. **继承覆盖**：下层继承上层，可在权限范围内覆盖
3. **运营灵活**：所有策略都可配置，不写死在代码里
4. **安全边界**：平台可限制租户的配置范围，避免异常配置

### 开发优先级

**P0（MVP必须）**：
- 平台级：增值服务配置、功能开关
- 租户级：增值服务开通状态、基本业务规则
- 项目级：工价配置、返费政策配置

**P1（后续迭代）**：
- 租户级：借支利息、闪电发薪详细配置
- 项目级：工时管理细节配置

**P2（优化体验）**：
- 配置模板（快速复制配置）
- 配置历史记录（审计）
- 配置导入导出
