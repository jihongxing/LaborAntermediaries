## ✨ 模块10：外部系统对接 - 本地临工市场App（新增模块）

**价格**：¥12.0万  
**工作量**：70人天  
**优先级**：⭐⭐⭐⭐⭐（核心模块，影响招聘渠道拓展）

### 业务价值

解决劳务公司与本地临工市场App的数据互通问题，实现：
- ✅ 劳务需求自动同步，劳务公司可参与更多项目竞标
- ✅ 岗位信息推送到临工市场，扩大招聘渠道
- ✅ 报名数据自动去重，避免渠道纠纷
- ✅ 中标后自动创建项目，提高业务效率

---

### 核心子模块

#### 10.1 劳务需求管理（¥2.5万，15人天）

**功能点**：
- ✅ 接收劳务需求：临工市场通过Webhook推送劳务需求到系统
- ✅ 需求列表展示：展示用工方发布的劳务需求（工种、人数、薪资、工期）
- ✅ 需求详情查看：查看需求完整信息（任职要求、福利待遇、附件）
- ✅ 需求筛选：按地区、工种、人数、发布时间筛选
- ✅ 需求状态跟踪：待竞标、竞标中、已截止、已中标
- ✅ 需求收藏：收藏感兴趣的需求，快速查找
- ✅ 同步日志：记录每次同步的时间、状态、失败原因

**使用端口**：Web管理后台

**验收标准**：
- 临工市场推送需求后，系统能正确接收并展示
- 需求信息完整准确（与临工市场一致）
- 可按多维度筛选需求
- 需求状态实时更新
- 同步失败时有明确的错误提示

**业务场景举例**：
用工方在临工市场发布需求"某电子厂需要100名流水线工人，工期3个月"，需求通过API实时推送到劳务公司端，劳务公司在"劳务需求"列表可以看到该需求，点击查看详情后决定是否参与竞标。

---

#### 10.2 竞标管理（¥3.0万，18人天）

**功能点**：
- ✅ 在线缴纳保证金：支持支付宝/微信/银行转账缴纳保证金
- ✅ 保证金状态跟踪：未缴纳、已缴纳、已退还
- ✅ 提交竞标方案：填写投标金额、服务费率、方案描述、上传资质证书
- ✅ 竞标列表查看：查看本公司的竞标记录
- ✅ 竞标详情查看：查看竞标方案、竞标状态、结果原因
- ✅ 中标通知接收：临工市场推送中标结果
- ✅ 自动退还保证金：中标后自动触发保证金退还流程
- ✅ 中标后自动创建项目：自动创建项目和岗位
- ✅ 自动生成合同：根据中标信息生成合同模板
- ✅ 竞标数据统计：参与次数、中标次数、中标率

**使用端口**：Web管理后台

**验收标准**：
- 可在线缴纳保证金，支付状态正确
- 可提交竞标方案，上传附件
- 竞标提交后，临工市场能正确接收
- 中标通知接收后，系统自动创建项目和岗位
- 保证金退还流程自动触发
- 竞标数据统计准确

**业务场景举例**：
劳务公司看到劳务需求后，点击"参与竞标"，先在线缴纳¥10,000保证金，然后填写投标金额¥580,000、服务费率8.5%、上传公司资质证书，提交后系统自动推送到临工市场。3天后，用工方选定该劳务公司中标，系统接收到中标通知，自动退还保证金，自动创建项目"某电子厂流水线项目"，自动创建岗位"流水线装配工"，并推送到临工市场。

---

#### 10.3 岗位同步管理（¥2.5万,15人天）

**功能点**：
- ✅ 同步开关配置：岗位发布时可勾选"同步到临工市场"
- ✅ 自动同步：岗位更新后自动同步到临工市场
- ✅ 下架同步：岗位下架后自动同步下架状态
- ✅ 同步状态查看：查看岗位同步状态（待同步、成功、失败）
- ✅ 手动重试：同步失败后可手动重试
- ✅ 同步日志：记录每次同步的时间、数据快照、失败原因
- ✅ 数据脱敏：同步时自动过滤敏感信息（工价、利润、员工身份证）

**使用端口**：Web管理后台

**验收标准**：
- 岗位发布时可选择是否同步
- 同步到临工市场的岗位信息准确（不包含敏感信息）
- 岗位更新后自动触发同步
- 岗位下架后临工市场状态同步更新
- 同步失败有明确的错误提示和重试入口
- 同步日志完整可追溯

**业务场景举例**：
劳务公司中标后，系统自动创建岗位"流水线装配工，月薪5500元"，勾选"同步到临工市场"，点击发布，系统自动将岗位推送到临工市场（薪资显示为范围"5000-6000元"，不显示具体工价）。求职者在临工市场和劳务公司端都能看到该岗位。3天后，岗位招满，劳务公司下架岗位，临工市场的岗位状态同步更新为"已关闭"。

#### 10.4 报名数据去重（¥2.5万，15人天）

**功能点**：
- ✅ 接收临工市场报名：Webhook接收报名数据
- ✅ 去重检查：以身份证号为唯一标识，自动检查是否重复
- ✅ 保护期机制：首次报名后设置保护期（7天或15天可配置）
- ✅ 保护期内拒绝：保护期内其他渠道报名自动拒绝并提示
- ✅ 保护期外允许：保护期后允许其他渠道报名但需人工审核
- ✅ 渠道归属识别：临工市场报名自动识别区域（深圳/东莞/广州等）
- ✅ 重复报名提示：提示"该求职者已在XX渠道报名，保护期至XX日"
- ✅ 人工裁定入口：重复报名冲突时可人工裁定归属

**使用端口**：Web管理后台、微信小程序

**验收标准**：
- 临工市场推送报名后，系统能正确接收并展示
- 报名时自动检查身份证号是否重复
- 保护期内重复报名自动拒绝
- 保护期外重复报名允许但标记"需审核"
- 渠道归属信息准确（包含区域信息）
- 重复报名提示信息清晰

**业务场景举例**：
王小明在10月18日通过临工市场（深圳区域）报名了"流水线装配工"，系统记录渠道为"临工市场-深圳"，保护期至10月25日。10月20日，经纪人李四想在劳务公司端提报王小明，系统检测到身份证重复，提示"该求职者已在临工市场-深圳报名，保护期至10月25日"，拒绝提报。10月26日保护期结束，经纪人李四可以重新提报，但系统标记"需审核"，人事确认后决定是否接受。

- 可配置功能开关
- 未开通增值服务时，相关菜单不可见

- 到期提醒及时

### 数据库设计（新增3张表）

#### 表1：labor_demand（劳务需求表）

```sql
CREATE TABLE labor_demand (
  id BIGSERIAL PRIMARY KEY,
  tenant_id BIGINT NOT NULL,
  source_platform VARCHAR(50) NOT NULL DEFAULT '临工市场',
  source_demand_id VARCHAR(50) NOT NULL,
  demand_no VARCHAR(50) NOT NULL,
  employer_name VARCHAR(100) NOT NULL,
  job_title VARCHAR(100) NOT NULL,
  job_count INTEGER NOT NULL,
  salary_range VARCHAR(50),
  work_location VARCHAR(200),
  deadline TIMESTAMPTZ,
  status VARCHAR(20) NOT NULL DEFAULT 'open',
  created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

#### 表2：bidding_record（竞标记录表）

```sql
CREATE TABLE bidding_record (
  id BIGSERIAL PRIMARY KEY,
  tenant_id BIGINT NOT NULL,
  demand_id BIGINT NOT NULL,
  bidding_no VARCHAR(50) NOT NULL,
  bid_amount NUMERIC(10,2) NOT NULL,
  deposit_amount NUMERIC(10,2),
  deposit_status VARCHAR(20),
  bid_status VARCHAR(20) NOT NULL DEFAULT 'pending',
  project_id BIGINT,
  created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

#### 表3：job_sync_record（岗位同步记录表）

```sql
CREATE TABLE job_sync_record (
  id BIGSERIAL PRIMARY KEY,
  tenant_id BIGINT NOT NULL,
  job_id BIGINT NOT NULL,
  target_platform VARCHAR(50) NOT NULL DEFAULT '临工市场',
  sync_type VARCHAR(20) NOT NULL,
  sync_status VARCHAR(20) NOT NULL,
  error_message TEXT,
  created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

### API接口清单

#### 对外提供的接口（4个）

1. POST `/api/external/bidding/submit` - 提交竞标
2. POST `/api/external/job/sync` - 同步岗位
3. PUT `/api/external/job/sync/{jobId}` - 更新岗位
4. DELETE `/api/external/job/sync/{jobId}` - 下架岗位

#### 接收的接口（3个）

1. POST `/api/external/demand/receive` - 接收劳务需求
2. POST `/api/external/bidding/result` - 接收中标通知
3. POST `/api/external/application/receive` - 接收报名信息

### 技术实现要点

#### 1. Webhook推送机制
- 临工市场通过Webhook实时推送数据
- 系统提供接收接口（POST接口）
- 实时性高，无需轮询

#### 2. 消息队列（RabbitMQ）
- 接收数据后放入消息队列
- 异步消费，避免阻塞
- 失败自动重试（最多3次）

#### 3. 数据安全
- API签名验证（防篡改）
- IP白名单（限制访问）
- HTTPS加密传输
- 敏感数据脱敏

#### 4. 数据一致性
- 定时对账任务（每天凌晨）
- 发现不一致自动修复
- 完整的同步日志
