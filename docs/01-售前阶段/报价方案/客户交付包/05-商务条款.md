### 1.3 逾期付款

**逾期付款违约条款**：

1. **滞纳金**：
   - 若客户未按约定时间支付任一期款项
   - 每逾期1日，支付该期应付款项的**千分之三（3‰）**作为滞纳金

2. **暂停服务**：
   - 若客户逾期超过15个工作日仍未支付
   - 我方有权暂停项目服务
   - 已完成工作量按实际人天（¥1,500/人天）结算

3. **解除合同**：
   - 若客户逾期超过30个工作日
   - 我方有权单方解除合同
   - 客户已付款项不予退还

**示例**：
- 第一期开发款¥28万应于10月1日支付
- 客户于10月6日支付（逾期5天）
- 滞纳金 = ¥280,000 × 3‰ × 5天 = ¥4,200

## ✅ 二、验收条款

### 2.1 验收原则

1. **客观标准**：以《附件一：模块验收标准清单》为准，不以主观"满意度"为标准
2. **期限刚性**：每个验收阶段都有明确期限，逾期视为验收通过
3. **分阶段验收**：按5个阶段分批验收，不是一次性验收全部
4. **书面确认**：验收结果必须书面签字，口头或微信无效

### 2.2 验收标准

**功能验收**：
- 15个模块共144项验收标准
- 通过率≥95%（137项以上通过）
- 核心模块（模块4、模块6）通过率≥98%

**性能验收**：
- 页面响应时间 < 2秒
- 并发用户数 ≥ 500
- 系统可用率 ≥ 99%

**交付物验收**：
- Web管理后台（已部署到生产环境）
- 移动App（iOS + Android，已上架应用市场）
- 微信小程序（已发布到微信平台）
- 用户操作手册（PDF，约80页）
- 培训视频（约2小时）

### 2.3 验收流程

**5个阶段验收**：

| 阶段 | 验收期限 | 逾期后果 |
|------|---------|---------|
| 需求评审 | 提交文档后5个工作日 | 视为验收通过，触发付款义务 |
| 第一期开发 | 提交验收申请后10个工作日 | 视为验收通过，触发付款义务 |
| 第二期开发 | 提交验收申请后10个工作日 | 视为验收通过，触发付款义务 |
| 上线 | 系统上线后5个工作日 | 视为验收通过，触发付款义务 |
| 最终验收 | 试运行期满后7个工作日 | 视为验收通过，触发付款义务 |

**验收步骤**：
1. 开发方提交验收申请
2. 客户在验收期限内测试
3. 客户提出问题清单（如有）
4. 开发方修复问题
5. 客户重新验收
6. 双方签字确认

### 2.4 试运行期

**时长**：2周（14个自然日），不得延长

**试运行期内的问题处理**：
- 功能性Bug：免费修复
- 性能问题：免费优化（如因代码问题导致）
- 需求变更：走变更流程，需另行付费
- 使用问题：提供技术支持和培训

**试运行期满**：
- 试运行期满后7个工作日内，客户应组织最终验收
- 若客户逾期未验收，视为验收通过
- 若试运行期内发现的问题已全部修复，客户不得以"再试用一段时间"为由延迟验收

## 🔄 三、需求变更管理

### 3.1 需求变更定义

凡不在《附件二：功能清单确认书》中列明的功能、超出原功能描述的改动、新增的业务流程，均视为需求变更。

### 3.2 变更流程

1. **客户提出变更**：填写《需求变更申请单》
2. **开发方评估**：3个工作日内反馈《变更评估报告》
3. **双方协商**：就费用、工期进行协商
4. **签订变更协议**：双方签署《需求变更协议》（补充协议）
5. **支付预付款**：客户支付变更费用的50%
6. **开始变更开发**：开发方开始变更开发
7. **变更验收**：变更完成后客户验收
8. **支付尾款**：客户支付变更费用的50%

### 3.3 变更收费标准

| 计费方式 | 单价 | 说明 |
|---------|------|------|
| 人天单价 | ¥1,500/人天 | 与原开发单价一致 |
| 最低收费 | ¥5,000 | 不足3.34人天按3.34人天计 |
| 紧急变更 | ¥2,250/人天 | 要求3日内完成，单价上浮50% |

### 3.4 Bug与变更的界定

**功能性Bug**（免费修复）：
- 系统实现与《功能清单确认书》描述不一致
- 导致功能无法正常使用或结果不正确

**需求变更**（需付费）：
- 《功能清单确认书》中未明确的功能或业务规则
- 对已确认的原型图、UI设计提出的修改意见
- 提出的"体验优化"、"界面美化"、"流程简化"等改进需求
- 与第三方系统（非合同约定）的对接需求
- 因业务调整提出的流程变更、规则调整

**界定原则**：
- 清单中有明确描述且实现不符 → Bug，免费修
- 清单中无描述或描述模糊 → 变更，需付费

### 3.5 变更对工期的影响

- 因需求变更导致的项目延期，延期时间不计入开发方开发周期
- 开发方不承担因需求变更导致的延期责任

## ⚖️ 五、知识产权

### 5.1 系统所有权

- 本合同项下开发的系统，其**知识产权归开发方所有**
- 客户在全额支付合同款项后，获得系统的**永久使用权（非独占）**
- 客户有权将系统用于其自身业务，但不得转让、出租、出售给第三方

### 5.2 源代码归属

**标准合同**：
- 不包含源代码交付
- 开发方保留源代码所有权
- 客户获得系统使用权

**购买源代码**（可选）：
- 额外支付¥25万元
- 获得源代码所有权
- 可自行修改和二次开发
- 不得用于商业销售

### 5.3 数据归属

- 客户录入系统的业务数据**归客户所有**
- 开发方为客户提供数据导出功能
- 客户可随时导出自己的数据
- 合同终止后，开发方协助客户完成数据迁移（收取合理费用）

### 5.4 商业秘密保护

- 双方对在合同履行过程中知悉的对方商业秘密负有保密义务
- 未经对方书面同意，不得向第三方披露
- 保密期限：合同履行期间及合同终止后2年

**客户延期责任**：
- 若因客户原因导致项目延期（如未按时付款、未按时验收、频繁变更需求）
- 延期时间不计入开发方开发周期
- 开发方不承担任何延期责任

## 🚫 七、违约责任

### 7.1 客户违约

**未按时付款**：
- 逾期1-15日：支付滞纳金（详见第一条）
- 逾期超过15日：开发方有权暂停服务
- 逾期超过30日：开发方有权解除合同，已付款项不退

**未按时验收**：
- 逾期视为验收通过，触发付款义务
- 因此导致的项目延期，由客户承担责任

**拒绝合理的验收申请**：
- 若系统符合《模块验收标准清单》但客户拒绝验收，视为客户违约
- 开发方有权要求客户立即支付对应款项并继续履行合同

**擅自使用系统**：
- 若客户未完成付款即擅自使用系统（如复制代码、导出数据）
- 视为客户认可系统质量
- 开发方有权要求客户立即支付全部剩余款项

### 7.2 开发方违约

**未按时交付**：
- 延期15日内：书面说明原因
- 延期超过15日：支付违约金（详见第六条）
- 延期超过30日：客户有权解除合同，开发方退还已收款项的50%

**交付质量不符合要求**：
- 若系统实现与《功能清单确认书》严重不符（不符合项超过20%）
- 客户有权要求开发方限期整改
- 逾期未整改或整改后仍不合格的，客户有权解除合同，开发方退还已收款项的70%

### 7.3 合同解除

**因客户违约解除**：
- 已付款项不予退还
- 客户已使用的系统和代码归开发方所有

**因开发方违约解除**：
- 开发方退还约定比例的款项
- 已交付的系统和代码归客户所有
