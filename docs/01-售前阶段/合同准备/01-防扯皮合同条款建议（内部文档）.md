# 防扯皮合同条款建议（内部文档）

**文档性质**：内部参考文档，不给客户看  
**使用目的**：指导合同起草，确保关键条款都写进合同  
**适用客户**：可能扯皮、付款拖延的客户  
**报价方案**：方案B（折中型），总价¥140万

---

## 🎯 核心策略

**三个必须**：
1. **必须模块化验收**：不能等全部做完才验收，分批验收分批收钱
2. **必须锁定范围**：需求评审后客户签字确认，超出范围的算变更
3. **必须设定期限**：每个节点都有时间限制，逾期有后果

**三个禁止**：
1. **禁止口头承诺**：所有需求、变更必须书面确认
2. **禁止先干活后收钱**：每个阶段先验收付款，再进入下一阶段
3. **禁止无限试运行**：试运行最长2周，到期必须验收

## 📋 范围锁定条款（防需求变更扯皮）

### 必须写进合同的条款

#### 1. 项目范围条款

```
第X条 项目范围

1. 本项目的功能范围以《附件二：功能清单确认书》为准，该确认书由双方在需求评审会议上
   共同确认并签字盖章，作为本合同不可分割的组成部分。

2. 《功能清单确认书》包括但不限于：
   - 15个模块的详细功能点清单（200+项）
   - 每个功能点的输入、输出、业务规则
   - 页面原型图和交互流程图
   - 数据库ER图和表结构说明

3. 项目功能范围一经确认，即为合同约定的交付标准。乙方按此标准开发，甲方按此标准验收。

4. 超出《功能清单确认书》范围的任何需求，均视为需求变更，按本合同第X条变更管理条款处理。
```

#### 2. 需求变更管理条款

```
第X条 需求变更管理

1. 需求变更定义：
   凡不在《功能清单确认书》中列明的功能、超出原功能描述的改动、新增的业务流程，
   均视为需求变更。

2. 变更申请流程：
   （1）甲方提出变更需求，填写《需求变更申请单》（附件四）；
   （2）乙方评估变更影响，包括工时、费用、进度，3个工作日内反馈《变更评估报告》；
   （3）双方协商一致后，签订《需求变更协议》（补充协议）；
   （4）甲方支付变更费用（至少50%预付款）后，乙方开始变更开发。

3. 变更收费标准：
   - 人天单价：¥1,500/人天（与原开发单价一致）
   - 起步价：单次变更最低收费5,000元（不足3.34人天按3.34人天计）
   - 紧急变更（要求3日内完成）：人天单价上浮50%，即¥2,250/人天

4. 变更费用支付：
   - 变更评估通过后，甲方支付变更费用的50%作为预付款；
   - 变更开发完成并通过验收后，甲方支付剩余50%。

5. 变更对进度的影响：
   因需求变更导致的项目延期，延期时间不计入乙方开发周期，乙方不承担延期责任。

6. 累计变更限制：
   若累计变更工时超过原合同工时的20%（即136人天），双方应重新评估项目范围和预算，
   必要时签订补充协议调整合同总价和交付周期。
```

#### 3. Bug修复与需求变更界定条款

```
第X条 Bug修复与需求变更的界定

1. 功能性Bug的界定：
   系统实现与《功能清单确认书》描述不一致，导致功能无法正常使用或结果不正确的情况，
   视为功能性Bug，由乙方免费修复。

2. 需求变更的界定：
   以下情况不属于Bug，视为需求变更，需按变更流程处理并收费：
   （1）《功能清单确认书》中未明确的功能或业务规则；
   （2）甲方对已确认的原型图、UI设计提出的修改意见；
   （3）甲方提出的"体验优化"、"界面美化"、"流程简化"等改进需求；
   （4）甲方提出的与第三方系统（非合同约定）的对接需求；
   （5）甲方因业务调整提出的流程变更、规则调整。

3. 争议处理：
   若双方对某项问题是Bug还是变更存在争议，以《功能清单确认书》为准：
   - 清单中有明确描述且实现不符 → Bug，免费修；
   - 清单中无描述或描述模糊 → 变更，需付费。
   若清单描述模糊导致理解不一致，双方各承担50%责任，变更费用减半收取。
```

## ✅ 验收条款（防无限试运行扯皮）

### 必须写进合同的条款

#### 1. 分阶段验收条款

```
第X条 分阶段验收

1. 本项目采用分阶段验收机制，分为以下阶段：
   
   阶段一：需求评审验收
   - 验收内容：PRD、原型图、UI设计稿、数据库设计
   - 验收标准：符合甲方业务需求，与需求调研结果一致
   - 验收方式：甲方审阅文档并签署《功能清单确认书》
   - 验收期限：乙方提交文档后5个工作日内必须完成验收
   - 逾期后果：视为验收通过，进入开发阶段

   阶段二：第一期开发验收（前8个模块）
   - 验收内容：模块1-8的功能实现
   - 验收标准：详见《附件一：模块验收标准清单》
   - 验收方式：乙方演示+甲方测试+签署《第一期验收报告》
   - 验收期限：乙方提交验收申请后10个工作日内必须完成验收
   - 逾期后果：视为验收通过，触发第一期开发款支付义务

   阶段三：第二期开发验收（后7个模块）
   - 验收内容：模块9-15的功能实现
   - 验收标准：详见《附件一：模块验收标准清单》
   - 验收方式：乙方演示+甲方测试+签署《第二期验收报告》
   - 验收期限：乙方提交验收申请后10个工作日内必须完成验收
   - 逾期后果：视为验收通过，触发第二期开发款支付义务

   阶段四：上线验收
   - 验收内容：生产环境部署、数据迁移、用户培训
   - 验收标准：系统正常运行，核心业务流程可正常操作
   - 验收方式：甲方实际使用测试+签署《上线确认书》
   - 验收期限：系统上线后5个工作日内必须完成验收
   - 逾期后果：视为验收通过，触发上线款支付义务

   阶段五：试运行验收（最终验收）
   - 验收内容：系统稳定性、性能指标、功能完整性
   - 验收标准：详见《附件一：模块验收标准清单》及《附件五：验收流程》
   - 验收方式：试运行期满后，甲方签署《项目验收报告》
   - 验收期限：试运行期满后7个工作日内必须完成验收
   - 逾期后果：视为验收通过，触发验收款支付义务

2. 每个阶段的验收通过后，触发对应的付款义务，乙方继续进入下一阶段工作。

3. 若甲方在验收期限内提出问题，乙方应在合理期限内（一般问题5个工作日，严重问题10个工作日）
   修复后重新提交验收。重新提交后的验收期限重新计算。
```

#### 2. 试运行期条款

```
第X条 试运行期

1. 试运行期定义：
   系统部署至生产环境后，甲方实际使用系统的观察期，用于发现系统在真实业务场景下的问题。

2. 试运行期时长：
   自系统正式上线之日起，试运行期为**2周（14个自然日）**，不得延长。

3. 试运行期内的问题处理：
   （1）功能性Bug：乙方免费修复，修复时间计入试运行期；
   （2）性能问题：若因代码问题导致，乙方免费优化；若因服务器配置不足导致，甲方自行扩容；
   （3）需求变更：按需求变更流程处理，需另行付费；
   （4）使用问题：乙方提供技术支持和培训（工作日9:00-18:00）。

4. 试运行期满的处理：
   （1）试运行期满后7个工作日内，甲方应组织最终验收，签署《项目验收报告》；
   （2）若甲方逾期未验收，视为验收通过，乙方有权要求甲方支付验收款；
   （3）若试运行期内发现的问题已全部修复，甲方不得以"再试用一段时间"为由延迟验收。

5. 试运行期禁止事项：
   甲方不得以"试运行中"为由：
   （1）拒绝支付已到期的款项；
   （2）要求乙方无限期提供免费技术支持；
   （3）要求乙方免费开发新功能或变更已有功能。
```

#### 3. 验收标准条款

```
第X条 验收标准

1. 验收依据：
   本项目的验收以《附件一：模块验收标准清单》为唯一标准，该清单包含15个模块共200+项
   可测试的验收标准。

2. 验收标准的性质：
   （1）验收标准是客观的、可测试的，不基于"满意度"或"使用体验"等主观标准；
   （2）验收标准在需求评审阶段由双方共同确认，一经确认不得随意修改；
   （3）若甲方认为验收标准不合理，应在需求评审阶段提出，开发阶段不得以此为由拒绝验收。

3. 验收通过标准：
   符合以下条件之一，视为验收通过：
   （1）《模块验收标准清单》中95%以上的验收项通过测试；
   （2）未通过的验收项均为轻微问题（不影响核心业务流程），且双方约定在后续维保期修复；
   （3）甲方在验收期限内未提出任何问题；
   （4）甲方在验收期限内提出的问题经乙方修复后，甲方不再提出新问题。

4. 验收不通过的处理：
   （1）若验收不通过，甲方应在验收期限内书面列出不通过的原因和问题清单；
   （2）乙方收到问题清单后，评估修复工作量并反馈修复计划；
   （3）若问题属于功能性Bug，乙方免费修复；若问题属于需求变更，按变更流程处理；
   （4）修复完成后，重新进入验收流程，验收期限重新计算。

5. 验收争议处理：
   若双方对验收结果存在争议，以《模块验收标准清单》为准：
   - 若系统实现符合清单标准，视为验收通过，甲方不得以其他理由拒绝验收；
   - 若清单标准本身存在歧义，双方协商解决，协商不成的，提交第三方技术专家鉴定（费用双方各半）。
```

## 🕐 时间条款（防拖延扯皮）

### 必须写进合同的条款

#### 1. 项目周期条款

```
第X条 项目周期

1. 总体周期：
   本项目自合同签订并收到首付款之日起，至项目验收通过之日止，总计**23周**（约5.5个月）。

2. 各阶段周期：
   - 需求评审阶段：2周
   - 第一期开发（模块1-8）：8周
   - 第二期开发（模块9-15）：7周
   - 集成测试：2周
   - 部署上线：1周
   - 试运行期：2周
   - 最终验收：1周

3. 周期起算：
   各阶段周期自上一阶段验收通过且对应款项到账后开始计算。

4. 不可抗力：
   因以下原因导致的延期，不计入乙方开发周期：
   （1）甲方未按时支付款项；
   （2）甲方未按时完成验收（超过约定验收期限）；
   （3）甲方提出需求变更；
   （4）甲方未按时提供必要的协助（如测试数据、业务配合等）；
   （5）不可抗力（自然灾害、政府行为、疫情等）。
```

#### 2. 延期责任条款

```
第X条 延期责任

1. 乙方延期责任：
   若因乙方原因导致项目延期，乙方应承担以下责任：
   （1）延期15个工作日以内：向甲方书面说明原因并提供补救措施；
   （2）延期超过15个工作日：每延期1日，向甲方支付合同总价款的千分之一（1‰）作为违约金，
        累计违约金不超过合同总价款的5%；
   （3）延期超过30个工作日：甲方有权单方解除合同，乙方退还已收款项的50%并支付违约金。

2. 甲方延期责任：
   若因甲方原因导致项目延期（如未按时付款、未按时验收、频繁变更需求），
   延期时间不计入乙方开发周期，乙方不承担任何延期责任。

3. 延期的认定：
   （1）以合同约定的各阶段完成时间为准；
   （2）因甲方原因导致的延期，乙方应书面通知甲方并要求甲方确认；
   （3）若甲方在收到通知后3个工作日内未回复，视为认可延期原因。
```

第X条 免费维保期

1. 维保期时长：
   自项目验收通过之日起，乙方提供**12个月**的免费维保服务。

2. 维保服务内容：

## 📌 使用建议

### 与客户谈判时

1. **先报价，后看合同**：
   先让客户接受¥140万的报价，再拿出合同让他看细节。
   不要一开始就展示这么详细的条款，会吓跑客户。

2. **强调"行业标准"**：
   不要说"这是为了防你扯皮"，而要说"这是软件行业的标准合同条款"。

3. **展示专业性**：
   详细的合同条款会让客户觉得你们很专业、很正规，反而增加信任。

4. **底线条款**：
   以下条款是底线，必须写进合同，客户不接受就不签：
   - 分阶段付款（不能全部做完才付款）
   - 逾期付款违约金（否则客户会一直拖）
   - 验收期限（否则客户会无限试运行）
   - 需求变更收费（否则客户会无限改需求）

### 合同签订流程

1. **第一稿**：我方起草合同，包含所有防扯皮条款
2. **第二稿**：客户提出修改意见，双方协商（可在付款比例、验收期限上适当妥协）
3. **第三稿**：双方确认最终版本
4. **签字盖章**：双方法人签字+公司盖章
5. **首付到账**：客户支付首付款后合同生效
6. **项目启动**：收到首付款3日内启动项目
