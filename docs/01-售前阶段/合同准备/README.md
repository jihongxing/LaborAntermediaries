## ⚠️ 常见扯皮场景与应对

### 1️⃣ 验收扯皮（概率最高）

**客户话术**：
- "这个功能跟我想的不一样"
- "这不是我要的，你们做错了"

**应对策略**：
- 📄 **附件一：验收标准清单** - 144项客观标准，功能符合清单即通过
- 📄 **附件二：功能清单确认书** - 需求评审后客户签字，锁定范围
- 📋 **合同条款**：验收以清单为准，不以"满意度"为标准

### 2️⃣ 付款拖延（概率最高）

**客户话术**：
- "等全部做完再一起付"
- "财务流程慢，再等等"

**应对策略**：
- 💰 **分阶段付款**：6个节点分批收款，不是一次性
- ⏰ **付款时限刚性**：每个节点5个工作日内必须付款
- 📋 **合同条款**：逾期付款千分之三/日滞纳金
- 🛑 **付款与交付绑定**：未付款不交付下一阶段

### 3️⃣ 需求变更不付钱（概率高）

**客户话术**：
- "这只是小改动，顺便帮我改了吧"
- "这是原来需求里应该有的"

**应对策略**：
- 📄 **附件四：需求变更管理流程** - 变更必须走流程并付费
- 💵 **变更收费标准**：¥1,500/人天，最低¥5,000
- 📋 **合同条款**：超出《功能清单确认书》的都算变更

### 4️⃣ 无限试运行（概率中）

**客户话术**：
- "再试用一段时间，发现问题再改"
- "等业务量大了再正式验收"

**应对策略**：
- ⏰ **试运行期限明确**：最长2周，到期必须验收
- 📄 **附件五：验收流程** - 明确验收期限和逾期后果
- 📋 **合同条款**：试运行期满7日内未验收，视为验收通过

### 5️⃣ 尾款扣留（概率中）

**客户话术**：
- "留点尾款压着，有问题好找你们"
- "质保金得等一年后再给"

**应对策略**：
- 💰 **质保金比例低**：只保留5%（¥7万），不是传统的10%
- ⏰ **质保期明确**：12个月免费维保期，期满7日内支付尾款
- 📋 **合同条款**：质保期结束后逾期不付，按逾期处理

## 📋 合同签订前检查清单

### 合同条款检查（必须全部写进合同）

#### 付款相关（9项）
- [ ] 付款节点表（6个节点，金额、时限、触发条件）
- [ ] 每个节点的付款时限（5个工作日）
- [ ] 逾期付款违约金（千分之三/日）
- [ ] 逾期超过15日的后果（暂停服务或解除合同）
- [ ] 付款与交付绑定条款（未付款不交付）
- [ ] 首付款未支付的后果（合同自动失效）
- [ ] 发票开具约定（收款后X日内开具）
- [ ] 银行账户信息（指定收款账户）
- [ ] 付款方式（电汇/支票，不接受承兑汇票）

#### 范围锁定相关（7项）
- [ ] 功能范围以《功能清单确认书》为准
- [ ] 需求变更的定义和界定标准
- [ ] 变更申请流程（4步：申请→评估→协商→实施）
- [ ] 变更收费标准（¥1,500/人天，最低¥5,000）
- [ ] 变更费用支付方式（50%预付+50%尾款）
- [ ] Bug与变更的界定标准（清单中有=Bug，无=变更）
- [ ] 累计变更超过20%需签补充协议

#### 验收相关（8项）
- [ ] 分阶段验收机制（5个阶段）
- [ ] 每个阶段的验收期限（5-10个工作日）
- [ ] 逾期未验收的后果（视为验收通过）
- [ ] 验收标准（基于《模块验收标准清单》）
- [ ] 验收通过标准（95%通过或轻微问题）
- [ ] 试运行期时长（2周，不可延长）
- [ ] 试运行期满必须验收（7个工作日内）
- [ ] 验收争议处理（以清单为准）

#### 时间相关（5项）
- [ ] 总体开发周期（23周）
- [ ] 各阶段周期明细
- [ ] 周期起算规则（付款到账后）
- [ ] 不计入周期的情形（客户原因、不可抗力）
- [ ] 延期责任（乙方延期违约金千分之一/日）

#### 其他重要条款（8项）
- [ ] 免费维保期（12个月）
- [ ] 维保服务内容和不包含内容
- [ ] 响应时间承诺（按问题级别）
- [ ] 甲方未付款的违约责任
- [ ] 乙方延期的违约责任
- [ ] 知识产权归属
- [ ] 口头承诺无效条款
- [ ] 争议解决方式（仲裁）

## 🎓 使用指南

### 给商务/销售的建议

1. **先报价，后看合同**：
   - 先让客户接受¥140万的报价
   - 再拿出合同让他看细节
   - 不要一开始就展示这么详细的条款，会吓跑客户

2. **强调"行业标准"**：
   - 不要说"这是为了防你扯皮"
   - 而要说"这是软件行业的标准合同条款"
   - 详细的合同条款会让客户觉得你们很专业

3. **底线条款**（必须写进合同）：
   - 分阶段付款（不能全部做完才付款）
   - 逾期付款违约金（否则客户会一直拖）
   - 验收期限（否则客户会无限试运行）
   - 需求变更收费（否则客户会无限改需求）

### 给项目经理的建议

1. **合同签订前**：
   - 用本目录的文档与客户逐一确认
   - 特别是《验收标准清单》，要让客户看懂
   - 客户有疑问当场解答，不要留到开发时再说

2. **项目执行中**：
   - 严格按照《分阶段交付计划》执行
   - 所有变更必须走《变更管理流程》
   - 每个验收节点按《验收流程》操作

3. **留痕记录**：
   - 所有重要决策发邮件确认
   - 关键节点让客户签字盖章
   - 演示和培训录屏存档

### 给开发团队的建议

1. **开发前**：
   - 仔细阅读《功能清单确认书》
   - 不清楚的地方及时问产品经理
   - 不要自作主张"优化"功能

2. **开发中**：
   - 严格按照《验收标准清单》开发
   - 每个功能点都要能通过验收标准
   - 不要漏掉任何一项验收标准

3. **验收时**：
   - 提前准备好演示数据
   - 按照验收清单逐项演示
   - 客户提出的问题及时记录

## 📞 紧急情况处理

### 客户拒绝签合同怎么办？

**分析原因**：
- 觉得条款太严格？→ 解释这是行业标准，保护双方利益
- 担心没有变更空间？→ 解释有变更流程，合理变更可以做
- 想等做完再签？→ 明确拒绝，不签合同不开工

**底线**：
- 可以在付款比例上妥协（如首付降到25%）
- 可以在验收期限上妥协（如延长2-3天）
- **不能妥协的**：分阶段付款、逾期违约金、验收期限、变更收费

### 客户要求修改附件怎么办？

**可以接受的修改**：
- 删减部分验收标准（不影响核心功能）
- 调整验收期限（延长2-3天）
- 调整付款比例（但总价不变）

**不能接受的修改**：
- 删除逾期付款违约金条款
- 删除验收期限条款（变成无限期）
- 删除需求变更收费条款
- 降低验收通过标准（从95%降到80%以下）
