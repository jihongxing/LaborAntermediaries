\## 一、原始需求提炼



| 原始描述 | 理解 |

|---|---|

| 工作流程标准化 | 核心价值：把靠微信群和 Excel 跑的流程搬到线上 |

| 员工招聘、管理、借支、工资 | 员工从报名到离职的整个周期：报名 → 入职 → 在职 → 借支 → 发薪 → 离职 |

| 财务、驻场、项目经理、招聘专员 | 管理端的 4 类内部角色 |

| 内部人事专员 vs 外部经纪人 | 两类招聘渠道，结算方式不同：内部拿提成，外部拿返费 |

| 发招聘信息让别人报名，显示是谁招来的 | 报名链接带渠道标识，用来确定人头归属和结算返费 |

| 先做一家，再全国推广 | MVP 只服务一家公司，但架构从第一天就按多租户 SaaS 设计 |



\## 二、业务全景



\*\*参与方\*\*：用工企业（工厂/客户）、劳务公司（系统的主要用户）、招聘渠道（内部专员和外部经纪人）、求职者/员工。



\*\*资金流\*\*（三条线）：



```

用工企业 ──(工时×结算单价 / 管理费)──▶ 劳务公司 ──(工时×员工工价 − 借支 − 扣款)──▶ 员工

&#x20;                                         └──(返费 / 提成)──▶ 经纪人 / 招聘专员

```



劳务公司利润 = 企业结算款 − 员工工资 − 渠道返费 − 运营成本（宿舍、车辆、保险等）。系统要能\*\*按项目\*\*把这笔账算清楚。



\*\*主流程\*\*：



```

企业提需求 → 项目经理建项目/岗位 → 发布招聘（生成专属链接/海报）

→ 求职者报名（自动记录渠道）→ 提报名单 → 安排面试（集合/接送）

→ 入职（建档/合同/宿舍）→ 驻场日常管理（考勤/工时）

→ 借支 → 月度工资核算 → 发薪 → 返费结算 → 离职

```



\## 三、角色与权限



| 角色 | 职责 | 使用端 |

|---|---|---|

| 老板/管理员 | 全局配置、看数据、最终审批 | Web 后台 |

| 财务 | 工资核算发放、借支打款、返费结算、企业对账回款 | Web 后台 |

| 项目经理 | 对接企业，管理一个或多个项目：用工需求、工价、招聘进度、利润 | Web + 移动端 |

| 驻场 | 常驻工厂：接人、办入职、录工时、借支初审、办离职、处理员工问题 | 移动端 |

| 内部招聘专员 | 公司员工，发职位、提报名单、跟进面试，按绩效拿提成 | 移动端 |

| 外部经纪人 | 独立中介，用专属链接招人、提报名单，按返费政策结算 | 小程序 |

| 求职者/员工 | 报名、查进度、查工时工资、申请借支 | 小程序 |

| 用工企业（P1） | 确认工时、对账 | Web/小程序 |



\*\*内部专员和外部经纪人的区别\*\*：内部专员能看到全部项目和人才库；外部经纪人只能看到自己招的人和对外开放的岗位。结算上，内部走工资加提成，外部走返费，还要考虑代扣个税或开票。



\## 四、功能模块



\### 1. 基础管理



\- 组织架构、账号、角色权限，按项目隔离数据（比如驻场只能看自己驻的厂）

\- 客户（用工企业）档案：企业信息、联系人、合作合同、结算方式

\- 项目/岗位配置：工种、\*\*员工工价\*\*、\*\*企业结算价\*\*、年龄/性别要求、班次、食宿条件、\*\*返费政策\*\*



\### 2. 招聘管理（MVP 核心）



\- \*\*职位发布\*\*：生成职位页，以及带渠道码的分享链接/海报，方便在微信里转发

\- \*\*在线报名\*\*：姓名、手机、身份证（支持 OCR 识别）；自动记录是哪个渠道来的

\- \*\*提报名单\*\*：手动录入或 Excel 批量导入

\- \*\*归属与撞单规则\*\*（劳务行业最常见的纠纷）：

&#x20; - 以身份证号作为每个人的唯一标识

&#x20; - 先报先得，设保护期（比如 15 天内没面试就释放给别人）

&#x20; - 撞单时自动提示，必要时人工裁定，所有操作留记录

\- \*\*面试安排\*\*：时间、集合点、接送车辆，批量通知

\- \*\*状态流转\*\*：报名 → 已提报 → 待面试 → 通过/未通过 → 已入职/未到岗

\- \*\*招聘看板\*\*：按渠道统计到面率、入职率、留存率



\### 3. 员工管理



\- 档案：身份证、银行卡、紧急联系人、渠道来源、所在项目

\- 入职：合同、体检、工服押金、宿舍分配

\- 在职：调岗、转项目、黑名单

\- \*\*考勤工时\*\*：驻场录入，或导入工厂给的考勤表，并支持差异核对

\- 离职：区分正常离职、自离、辞退；离职时自动触发借支清算和返费达标判定

\- \*\*人才库\*\*：离职员工可以再推荐。这个行业员工回流率很高



\### 4. 借支管理



\- 流程：员工在小程序申请 → 驻场初审 → 项目经理/财务审批 → 打款 → 发工资时自动扣回

\- \*\*额度控制\*\*：可借额度 = 已出勤工时 × 工价 × 比例（比如 50%）− 已借金额

\- 可配置的规则：入职 N 天内不能借、单次和每月上限、借支次数

\- 风险点：借支的主要坏账来自员工借完就走。系统要实时显示每个人的"已借 vs 应发"



\### 5. 工资管理



\- 规则按项目配置：小时工价、加班倍率、夜班补贴、全勤奖、阶梯工价

\- 扣款项：借支、住宿、水电、餐费、工服、体检、保险

\- 核算流程：确认工时 → 自动计算 → 人工调整（留痕）→ 审批 → 锁定

\- \*\*工资条\*\*：员工在小程序查看并确认，减少争议

\- 发放：MVP 先导出银行代发文件，P1 再对接银行或支付渠道的代发接口

\- 小时工支持日结/周结，长期工按月结



\### 6. 渠道结算（返费/提成）



\- 返费政策按岗位配置：

&#x20; - \*\*按人头\*\*：员工在职满 N 天，一次性给 X 元

&#x20; - \*\*按工时\*\*：每工时 X 元，到员工离职或满 N 个月为止

&#x20; - \*\*阶梯\*\*：满 7、30、90 天分段发

\- 系统根据工时和在职天数自动判断是否达标，生成待结算明细

\- \*\*经纪人端能实时看到自己招的人、在职状态和预计返费\*\*。这是留住经纪人的关键

\- 结算审批、打款、代扣个税



\### 7. 财务管理



\- \*\*应收\*\*：按项目生成企业结算单 → 对账 → 开票 → 跟踪回款

\- \*\*应付\*\*：工资、借支、返费、宿舍租金、车辆等

\- \*\*项目利润表\*\*

\- \*\*资金与垫资\*\*：劳务公司通常要先垫钱发工资，企业回款往往滞后，现金流要看得清



\### 8. 驻场管理



\- 驻场和项目绑定，只看本厂员工

\- 日常操作：接人签到、入职登记、录工时、借支初审、离职登记

\- 驻场日报：在职人数、入离职、异常事件

\- 宿舍：房间、床位、入住退住、费用



\### 9. 项目经理工作台



\- 用工需求和实际在职人数对比，看缺口

\- 招聘进度、各渠道表现、项目利润和回款状态



\### 10. 数据看板



\- 老板看：在职人数趋势、各项目利润、应收应付、借支余额

\- 招聘看：渠道转化漏斗、经纪人排行

\- 风险看：未回款、借支坏账、离职率高的项目



\## 五、MVP 范围建议



原则：\*\*先跑通"招人 → 入职 → 工时 → 借支 → 发薪 → 返费"这条主线\*\*，其余能用 Excel 导入导出顶替的先顶替。



| 优先级 | 内容 |

|---|---|

| \*\*P0（MVP）\*\* | 账号权限、客户/项目/岗位、渠道链接报名和归属、提报名单、面试入职状态流转、员工档案、工时导入/录入、借支申请审批扣回、工资核算和工资条、返费自动计算、基础收支台账 |

| \*\*P1\*\* | 企业对账回款、宿舍、电子合同、银行代发对接、可配置的撞单规则、数据看板、驻场日报 |

| \*\*P2（推广阶段）\*\* | 多租户运营后台、企业端工时确认、保险对接、灵活用工/税务合规、跨公司经纪人网络、智能岗位匹配 |



\## 六、为全国推广提前考虑的设计点



\- \*\*多租户\*\*：数据模型从第一天就带租户 ID，MVP 阶段只开一个租户

\- \*\*规则配置化\*\*：工价、扣款、返费、借支额度、审批流都做成配置，不写死在代码里。每家公司、每个工厂的规则都不一样

\- \*\*地区差异\*\*：各地最低工资和社保政策不同

\- \*\*合规\*\*：

&#x20; - 劳务派遣许可证、人力资源服务许可证

&#x20; - 身份证、银行卡这类敏感信息要加密存储，并按《个人信息保护法》做授权和脱敏

&#x20; - 返费的个税处理

&#x20; - 经纪人层级不超过两级，避免被认定为多级分销

\- \*\*经纪人网络\*\*：经纪人通常同时给多家劳务公司供人。推广后，做成平台级经纪人账号（一个账号对接多家公司）会是很强的增长点
