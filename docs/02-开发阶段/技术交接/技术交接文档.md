## 1. 先对齐项目及交接依据

### 1.1 项目是什么

本项目是自主运营的**劳务供应链交易与履约协同平台**，不是向劳务公司出售的一套内部管理 SaaS，也不是仅发布需求、交换联系方式的撮合网站。

完整链路为：

`身份与组织 → 双方主体准入 → 用工方有效需求 → 供应商应标 → 用工方选标/配额 → 双方条件确认 → 供给计划 → 招聘及入职保险核验 → 到岗、排班与打卡 → 差异复核及计量确认 → 分类账单 → 授权付款/线下对公核验与对账 → 监督、申诉、信用及复购`

人事经理贡献和直接跨企业推荐是需要设计合法可执行路径的增长需求；保理融资是未来可选扩展，不能当作当前已批准的交付或收费能力。

### 1.2 七条交接护栏

交接各方先核对[根 README 七条护栏](../../../README.md#后续工作的七条护栏)：

1. 管理功能服务交易和履约，不按单家公司后台模块数量衡量平台完成度。
2. 需求发布之后还须覆盖履约、资金状态及平台监督。
3. 供应商承担约定交付与资金责任，平台界面不能变成平台供人、垫工资或代供应商审批。
4. 线下对公付款也是闭环路径，必须有账期、凭证、核验、核销和对账，不默认所有资金归集平台。
5. 用工方、供应商、经纪人及平台自身均受可核验、可申诉的约束。
6. 合规限制不能替代增长设计；资格、真实服务、直接推荐、合同与合法付款路径必须落实。
7. 规则批准、开发完成、联调验证和真实启用分别记录，不能互相替代。

## 3. 必须保持的技术交接合同

### 3.1 身份、组织及资源授权

- 后端是资源服务器，不是已建成的登录中心。DP-01 确认可信签发方后，才能落实组织上下文与多端认证。
- JWT 核对签名、`iss`、`aud`、`exp`、`jti` 和合法 `sub`；需要组织的请求还须可信 `tenant_id`。客户端声明的组织头、角色或用户 ID 不是身份凭据。
- 租户等于组织，用工方与劳务公司各自隔离，平台运营属于独立平台租户；同一组织不兼具用工方与劳务公司角色。
- 工人、个人经纪人是全局账号，通过成员或专项授权访问本人/授权项目；不是独立租户，也不因此获得组织全量数据。
- 使用 `ExecutionContext.require()`、`requireTenant()`、`checkPermission(...)` 及 `@PreAuthorize`；再核对项目、人员、账单、案件范围及业务状态，不设置通用管理员绕过。
- 撤权、组织停用、资质失效及付款前实时校验必须进入用例。历史申诉授权独立受限，不等于恢复全部新业务权限。
- 个人多公司汇总由客户端按合法成员关系分别请求后合并；不以后台无界跨租户查询便利聚合。

### 3.2 跨组织协作

**只投递，不跨租户查询**。需求归用工方，应标归供应商，双方各自保存获授权快照和项目视图，平台只接收监督所需事实。

目标投递模块仍待建设，交接必须给出：

1. 源数据归属、接收组织资格、字段白名单及版本模式；内部利润、无关工资、证件和其他客户数据不得整包投递。
2. 源事务内的业务事实和发件意图、接收方收件/投影、事件去重键、版本检查及失败重放。
3. 撤回、截止、变更、资格失效和更正传播；界面标明投递中、失败或落后，不能跨租户读源表兜底。
4. 唯一受控投递实现的专用目标写入通道、最小权限、审计和专项隔离测试。
5. 接收成功与业务确认分离；接收方必须用自己的合法身份完成确认。

业务代码不得切换租户上下文，不得用共享表配置、`InterceptorIgnore` 或原生 SQL 实现普通跨组织可见。任何投递例外须专项评审并封装在唯一投递模块，不能给各业务模块暴露任意目标租户写入能力。

文件引用不是下载许可。业务附件关联、跨组织授权和撤回尚需实现，必须逐次校验租户、业务对象和用途。

### 3.3 数据、接口及可靠执行

| 项目 | 强制接入要求 |
| --- | --- |
| 建表与迁移 | 普通业务表包含组织归属和工程必备字段；显式注册租户表/受控共享表，未知表拒绝。新增 Flyway 迁移，不改已应用版本。 |
| 归属字段 | DTO 不接受任意 `tenant_id`；租户表插入由插件注入，更新不改组织，遵守底座实体策略；不使用尚不支持的租户表 upsert。 |
| 命令与状态 | 明确前置状态、操作者、规则版本、预期版本与后置事实；禁止通用 `setStatus` 绕过审批。 |
| 并发 | 乐观锁、必要行锁及数据库业务唯一约束结合，覆盖超配额、重复建项目和资金超分配；前端按钮或 JVM 锁不构成保障。 |
| 编号 | 使用 `SequenceIds.nextId()` / `nextReference(prefix)`，可跳号，不当作严格时间顺序或连续会计凭证；文件使用底座 UUID。 |
| 金额和时间 | `BigDecimal` / `NUMERIC`，不使用浮点；中间精度及舍入按领域规则，不能通用套用两位小数。绝对时间、业务日期和项目时区分开，映射和往返按现行规范评审。 |
| 响应与精度 | `/api`、`Result<T>`、真实 HTTP 状态；下载/Actuator/OpenAPI 遵守原生合同。`Long/long` 序列化字符串；分页 `PageQuery` 单页最多 200。 |
| 幂等 | `IdempotentExecutor` 重放前重新授权，操作名/版本及 DTO 稳定；请求冲突拒绝，不能用新键绕开未知支付。记录保留策略另行设计。 |
| 任务 | `TaskQueue` 同事务入队、负载最多 64 KiB；至少一次、无租约续期/强制中断保证，处理器须超时、幂等及重新授权，恢复权限集合为空。 |
| 审计与证据 | 不记录完整敏感 DTO；同事务审计随回滚消失，不当作独立安全账本。事实、快照、回执和修正链不可无痕覆盖或删除。 |

### 3.4 五条资金关系与不可替代的确认

分别交接用工方→供应商项目款、供应商→工人工资、供应商→经纪人/合作公司应付、供应商→平台费用，以及未来独立的机构融资关系。不得合成一个可编辑“项目余额”。

- 平台核验不等于用工方采购决定、双方合同确认、工时确认、供应商资金审批或机构实际执行。
- 用工方未回款不自动推迟已形成的工资义务；供应商发了工资不等于买方项目款已到账。
- 出账、开票、审批、发起指令、机构处理中、实际收付和对账分别记录。
- 线下凭证先待核验，核对账户、币种、金额和流水后分配账单；覆盖重复凭证、部分收款、未分配款、争议和逾期。
- 线上指令固化责任主体授权与稳定业务号；本地事务记录意图/任务，机构调用在事务外执行；底座幂等不使银行副作用原子化。
- 超时或失联标记未知结果，按原指令查询/对账，不换新单号盲重付；验签、防重放、去重、乱序和金额核对均需验证。
- 机构回调不是用户同意或审批；保证金、分账、退款及保理各有独立规则、账户与启用条件。

资金业务依据[资金流程](../产品设计/03-账单与资金/资金账户与支付指令流程-v0.1.md)和[账期模型分析](../产品设计/03-账单与资金/资金流转闭环与账期模型分析-v0.1.md)细化；不在交接文档复制费率或承诺机构到账时效。

## 5. 环境接收与安全验证

### 5.1 接收代码和依赖

1. 记录仓库、分支、提交号及未提交修改，标明交付内容；不要通过重置工作区“清理”他人变更。
2. 准备 Java 17、Maven 和 PostgreSQL 16；检查现有 `backend/pom.xml`、Compose 与配置，不将版本表当成依赖升级指令。
3. 建立独立开发与测试数据库；机构、身份、公钥/私钥、加密密钥和文件目录按环境隔离。
4. 真实密钥、密码、令牌、人员资料及生产凭证不进仓库或交接附件；通过获授权渠道传递配置位置与权限。
5. 接收方核对权限、网络、迁移、任务开关和存储，不因能启动进程就签收业务可用。

### 5.2 本地启动

以下命令在 `backend/` 目录执行；配置细节以[后端 README](../../../backend/README.md)为准：

```powershell
$env:DB_PASSWORD = '自行生成的本地数据库密码'
docker compose up -d
mvn spring-boot:run '-Dspring-boot.run.profiles=local'
```

不使用 Compose 时通过 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 指向独立本地 PostgreSQL。启动迁移只创建已有底座表，不会自动生成目标业务闭环。

- 匿名健康检查为 `GET /api/actuator/health`；就绪检查可用 `/api/actuator/health/readiness`。
- 本地 `/api/swagger-ui/index.html` 和 `/api/v3/api-docs` 仍需认证；除健康检查外默认不匿名开放，Actuator 还需 `foundation:observe`。
- 认证验证须配置可信 `JWT_PUBLIC_KEY`、`JWT_ISSUER`、`JWT_AUDIENCE` 并取得合法令牌；未配置公钥时全部拒绝，不添加本地免认证开关。
- 文件根目录由 `STORAGE_ROOT` 配置为私有位置；`CRYPTO_ACTIVE_KEY` 及对应 AES 密钥通过受保护外部配置注入，不能复制示例密钥。
- `TASKS_ENABLED` 默认关闭；启用前确认所需处理器、实时授权、超时和重试策略。
- JSON 上限 1 MiB，单文件 10 MiB，multipart 总请求 11 MiB；扩大限制和开放 CORS 来源须评审。

### 5.3 单元测试及完整后端验证

```powershell
mvn test
$env:TEST_DATABASE_URL = 'jdbc:postgresql://localhost:5432/labor_foundation_test'
$env:TEST_DATABASE_USERNAME = '你的独立测试数据库账号'
$env:TEST_DATABASE_PASSWORD = '你的测试数据库密码'
mvn -B -ntp -Pintegration clean verify
```

**集成测试会清空技术测试表和隔离测试表，只能指向库名以 `_test` 结尾的独立 PostgreSQL 数据库，禁止生产或共享开发库。**

- `mvn test` 只覆盖单元测试；没有数据库时可运行，但不能声称完整验证通过。
- 完整验证执行 Checkstyle、单元测试、打包、Failsafe 集成测试和 JaCoCo，全后端 LINE ≥80%；禁止跳过、降低门槛或排除低覆盖类掩盖失败。
- 保存 `target/surefire-reports`、`target/failsafe-reports`、`target/site/jacoco/index.html` 对应报告及环境记录；`target/` 是构建产物，不存唯一交接资料。
- 前端目前不能声称已有构建命令和测试结果；初始化时为各端确定并记录可重复的安装、构建、静态检查、任务测试及发布方式。

### 6.2 必须验收的异常

- 身份/权限：非成员、已撤权、伪造组织、跨项目/跨人员/附件越权，平台不代交易方确认。
- 协作：投递目标越权、白名单泄露、事件重复/乱序/丢失、撤回和重放，接收成功不算对方同意。
- 交易/履约：并发超配额、确认版本冲突、项目重复生成、同人多源、未批协作、报名不算到岗。
- 计量/权益：跨日班、漏卡补正、外部记录冲突、争议量隔离、未付借支不扣回、旧政策锁定和锁账调整。
- 资金：未授权或账户不符、余额不足、未知先查、重复/乱序回调、凭证重复、部分付款、并发超分配和对账不平。
- 治理/增长：投诉未定不判失信、原经办不能自复核、平台自身投诉、未授权导出、利益冲突、推荐重复、退款及未批准奖励付款被阻断。
- 运行：任务超时与租约失效后重复执行、服务重启恢复、DB/文件恢复、模拟环境不能误开真实资金。

用例须说明可观察断言及来源；Mock 成功不能替代真实数据库隔离/事务测试，模拟机构成功不能替代真实机构验签、授权、查询与对账。
