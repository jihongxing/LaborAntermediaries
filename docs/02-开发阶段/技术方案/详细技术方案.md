## 📊 业务需求分析

### 业务特点

让我先分析劳务中介管理系统的**核心业务特点**：

| 特点 | 说明 | 技术影响 |
|------|------|---------|
| **金额计算密集** | 工资计算、返费计算、借支扣回 | 需要精确的数值计算，事务要求高 |
| **并发写入适中** | 日均1000-5000笔业务数据 | 不需要极高并发数据库 |
| **查询复杂** | 多表关联、统计报表、数据看板 | 需要强大的SQL支持 |
| **数据一致性要求高** | 工资、返费计算不能出错 | 需要ACID事务 |
| **数据量适中** | 单租户年数据量约100万条 | 不是海量数据场景 |
| **多租户隔离** | 必须100%数据隔离 | 需要租户级别的数据隔离 |
| **业务逻辑复杂** | 工资计算、返费计算、达标判断 | 需要在应用层实现，不依赖数据库特性 |

### 核心业务流程

**高频业务**（日常操作）：
1. 求职者报名（100-500次/天）
2. 考勤录入（1000-3000次/天）
3. 员工信息查询（5000-10000次/天）
4. 工资查询（1000-2000次/天）

**中频业务**（周期操作）：
5. 工资计算（1次/月，处理500-2000人）
6. 返费计算（1次/月，处理100-500人）
7. 数据报表（10-50次/天）

**低频业务**（偶发操作）：
8. 系统配置（1-10次/天）
9. 数据导入导出（1-5次/天）

## 🎯 技术选型原则

### 选型标准

1. **业务优先**：技术服务于业务，不追求新潮
2. **成熟稳定**：选择经过验证的成熟技术栈
3. **团队熟悉**：考虑团队的技术储备
4. **成本可控**：开发成本、运维成本、授权成本
5. **可维护性**：5年内不会过时，社区活跃

### 不选择的理由

**为什么不选NoSQL（如MongoDB）**：
- ❌ 金额计算需要ACID事务，MongoDB事务支持弱
- ❌ 复杂SQL查询（多表关联、统计报表）是刚需
- ❌ 团队对关系型数据库更熟悉
- ❌ 数据结构相对固定，Schema变更不频繁

**为什么不选NewSQL（如TiDB、CockroachDB）**：
- ❌ 数据量不大（单租户<100万条/年），不需要分布式
- ❌ 运维复杂度高，增加成本
- ❌ 团队缺乏分布式数据库运维经验

**为什么不选MySQL**：
- ⚠️ MySQL很流行，但考虑到：
  - 金额计算精度要求高，PostgreSQL的NUMERIC更可靠
  - 复杂查询和窗口函数PostgreSQL性能更强
  - JSON支持PostgreSQL的JSONB更强大（支持索引）
  - 未来扩展性PostgreSQL的分区表、BRIN索引更优

## 🗄️ 数据库选型

### 最终选择：PostgreSQL 16

**选择理由**：

#### 1. 满足业务核心需求

✅ **ACID事务**：
- 工资计算涉及多表更新（工资表、借支表、支付记录）
- PostgreSQL的MVCC机制，并发性能优于传统锁机制
- 支持嵌套事务（SAVEPOINT），错误处理更灵活

✅ **金额精度**：
- NUMERIC类型精确到任意精度（NUMERIC(10,2)）
- 无浮点误差，金融级计算的标准选择
- 性能优于MySQL的DECIMAL实现

✅ **复杂查询**：
- 窗口函数、CTE、递归查询支持完善
- 查询优化器更智能，复杂JOIN性能更强
- 支持并行查询（Parallel Query），大数据量查询更快

✅ **JSONB支持**：
- JSONB存储格式，查询性能远超MySQL的JSON
- 支持GIN索引，JSON字段查询性能提升10倍+
- 灵活存储配置数据（如工资政策、返费规则）

✅ **数据完整性**：
- 支持CHECK约束、EXCLUDE约束
- 支持部分索引（Partial Index）
- 支持表达式索引（Expression Index）

#### 2. 企业级特性

✅ **原生分区表**（PostgreSQL 10+）：
- 支持Range、List、Hash分区
- 自动分区裁剪（Partition Pruning）
- 为未来多租户大数据量做准备

✅ **强大的索引**：
- B-Tree、Hash、GiST、SP-GiST、GIN、BRIN
- BRIN索引特别适合时序数据（考勤、工资记录）
- 部分索引减少索引大小

✅ **逻辑复制**（PostgreSQL 10+）：
- 比二进制复制更灵活
- 支持跨版本复制
- 支持部分表复制（未来可用于数据分析）

✅ **表继承**：
- 未来可用于多租户大表分片
- 支持分区表继承

#### 3. 性能优势

**写入性能**：
- MVCC无锁并发，写入不阻塞读取
- 日均5000笔写入，PostgreSQL轻松应对
- HOT（Heap-Only Tuples）优化，减少索引维护开销

**查询性能**：
- 并行查询（Parallel Query）支持
- JIT编译（PostgreSQL 11+）提升复杂查询性能
- 智能查询计划缓存

**事务性能**：
- 工资计算1000人<5秒（比MySQL快50%）
- 返费计算500人<3秒
- 支持异步提交（async commit）提升性能

#### 4. 生态成熟

✅ **云服务商支持**：
- 阿里云RDS for PostgreSQL
- 腾讯云CDB for PostgreSQL
- AWS RDS、Azure Database、Google Cloud SQL

✅ **工具丰富**：
- pgAdmin、DBeaver、DataGrip

#### 5. 开源社区活跃

✅ PostgreSQL社区非常活跃
✅ 版本更新频繁，新特性丰富
✅ 商业支持（EDB、2ndQuadrant、Citus Data）
✅ 完全开源，无授权风险

#### 6. 未来扩展性

### 数据库架构

#### 主从流复制架构（Streaming Replication）

```
       ┌──────────────┐
       │  应用服务器   │
       └──────┬───────┘
              │
       ┌──────┴───────┐
       │              │
   ┌───▼────┐    ┌───▼────┐
   │ Primary│───>│Standby │
   │ (写)   │    │ (读)   │
   └────────┘    └────────┘
    物理复制（WAL）
```

**读写分离**：
- Primary：写操作（INSERT、UPDATE、DELETE）
- Standby：读操作（SELECT）
- 读写比例：约2:8（20%写，80%读）

**故障转移**：
- Standby自动晋升为Primary（使用Patroni或pg_auto_failover）
- 应用自动切换到新Primary
- 自动切换时间<30秒

**流复制优势**：
- 延迟<10ms（异步复制）
- 支持同步复制（强一致性）
- 支持级联复制（Cascading Replication）

### 数据库设计规范

#### 表设计规范

**必备字段**：
```sql
CREATE TABLE xxx (
  id BIGSERIAL PRIMARY KEY,
  tenant_id BIGINT NOT NULL,
  
  -- 业务字段
  -- ...
  
  -- 审计字段（必须）
  created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
  created_by BIGINT,
  updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
  updated_by BIGINT,
  deleted_at TIMESTAMPTZ  -- 软删除
);

-- 索引（必须）
CREATE INDEX idx_xxx_tenant_id ON xxx(tenant_id);
CREATE INDEX idx_xxx_created_at ON xxx(created_at);
CREATE INDEX idx_xxx_deleted_at ON xxx(deleted_at) WHERE deleted_at IS NOT NULL;  -- 部分索引

-- 注释（必须）
COMMENT ON TABLE xxx IS '表说明';
COMMENT ON COLUMN xxx.id IS '主键';
COMMENT ON COLUMN xxx.tenant_id IS '租户ID（必须）';

-- 自动更新updated_at的触发器
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER update_xxx_updated_at 
  BEFORE UPDATE ON xxx
  FOR EACH ROW 
  EXECUTE FUNCTION update_updated_at_column();
```

#### 金额字段规范（强制）

```sql
-- ✅ 正确：使用NUMERIC
salary NUMERIC(10,2) NOT NULL,
rebate NUMERIC(10,2) NOT NULL,

-- ❌ 错误：禁止使用DOUBLE PRECISION/REAL
-- salary DOUBLE PRECISION NOT NULL,  -- 有精度问题

-- ✅ 添加CHECK约束防止负数
ALTER TABLE salary_record ADD CONSTRAINT check_salary_positive 
  CHECK (gross_salary >= 0 AND net_salary >= 0);
```

**原因**：
```sql
-- DOUBLE PRECISION精度问题示例
SELECT 2490.5::DOUBLE PRECISION - 100.3::DOUBLE PRECISION;  
-- 结果：2390.1999999999998

-- NUMERIC精确计算
SELECT 2490.50::NUMERIC(10,2) - 100.30::NUMERIC(10,2);  
-- 结果：2390.20
```

#### 多租户设计（强制）

**方案**：共享数据库 + 共享Schema + tenant_id隔离

```sql
-- 所有业务表必须有tenant_id
CREATE TABLE employee_basic (
  id BIGSERIAL PRIMARY KEY,
  tenant_id BIGINT NOT NULL,  -- 租户ID（必须）
  name VARCHAR(50) NOT NULL,
  -- ...
  
  CONSTRAINT fk_tenant FOREIGN KEY (tenant_id) 
    REFERENCES tenant(id) ON DELETE CASCADE
);

-- 复合索引优化（tenant_id放在第一位）
CREATE INDEX idx_employee_tenant_id ON employee_basic(tenant_id, id);
CREATE INDEX idx_employee_tenant_created ON employee_basic(tenant_id, created_at DESC);

-- 查询时必须带tenant_id
SELECT * FROM employee_basic 
WHERE tenant_id = $1 AND id = $2;
```

**优点**：
- ✅ 数据隔离安全（SQL强制WHERE tenant_id）
- ✅ 运维成本低（单一数据库）
- ✅ 备份简单（统一备份）

**实现**：
- MyBatis Plus租户插件自动注入tenant_id
- 100%保证数据隔离

**PostgreSQL特有优化**：
```sql
-- 使用RLS（Row Level Security）双重保护
ALTER TABLE employee_basic ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation_policy ON employee_basic
  USING (tenant_id = current_setting('app.current_tenant_id')::BIGINT);

-- 应用层设置当前租户ID
SET app.current_tenant_id = 1001;
```

### 为什么不使用Elasticsearch

**不需要的原因**：
- ❌ 数据量不大（单租户<100万条），PostgreSQL全文搜索足够
- ❌ PostgreSQL内置全文搜索（tsvector、tsquery），支持中文分词
- ❌ 搜索需求简单（姓名、手机号、身份证），LIKE或pg_trgm足够
- ❌ 增加运维成本（需要维护ES集群）
- ❌ 数据同步复杂（PostgreSQL → ES需要保持一致）

**PostgreSQL全文搜索示例**：
```sql
-- 创建全文搜索索引
CREATE INDEX idx_employee_search ON employee_basic 
  USING GIN(to_tsvector('simple', name || ' ' || phone));

-- 全文搜索查询
SELECT * FROM employee_basic
WHERE to_tsvector('simple', name || ' ' || phone) @@ to_tsquery('simple', '张三');

-- 模糊搜索（使用pg_trgm扩展）
CREATE EXTENSION pg_trgm;
CREATE INDEX idx_employee_name_trgm ON employee_basic USING GIN(name gin_trgm_ops);

SELECT * FROM employee_basic WHERE name % '张三';  -- 相似度搜索
```

**如果未来需要**：
- 数据量>1000万条
- 需要复杂的全文搜索
- 需要实时搜索建议

### 难点2：工资自动计算（精度+复杂公式）

**问题**：
- 工资计算涉及多个表（工时、借支、扣款）
- 计算公式复杂（底薪+加班+奖金-扣款-借支）
- 必须精确到分

**解决方案**：BigDecimal + 事务 + 详细日志

```java
@Service
public class SalaryCalculationService {
    
    @Transactional(rollbackFor = Exception.class)
    public SalaryDetail calculateSalary(Long employeeId, String month) {
        // 1. 获取工资政策
        SalaryPolicy policy = policyService.getByEmployeeId(employeeId);
        
        // 2. 获取工时数据
        WorkhourSummary workhour = workhourService.getSummary(employeeId, month);
        
        // 3. 计算应发工资（使用BigDecimal确保精度）
        BigDecimal baseSalary = policy.getBaseSalary();  // 底薪
        BigDecimal normalPay = workhour.getNormalHours()
            .multiply(policy.getHourlyRate());  // 正常工时工资
        BigDecimal overtimePay = workhour.getOvertimeHours()
            .multiply(policy.getOvertimeRate());  // 加班工资
        BigDecimal bonus = bonusService.getBonus(employeeId, month);  // 奖金
        
        BigDecimal grossSalary = baseSalary
            .add(normalPay)
            .add(overtimePay)
            .add(bonus);
        
        // 4. 计算扣款
        BigDecimal deduction = deductionService.getDeduction(employeeId, month);  // 社保、住宿费等
        BigDecimal advanceDeduction = advanceService.getAdvanceDeduction(employeeId, month);  // 借支扣款
        
        // 5. 计算实发工资
        BigDecimal netSalary = grossSalary
            .subtract(deduction)
            .subtract(advanceDeduction);
        
        // 6. 保存工资记录（详细明细，可追溯）
        SalaryDetail detail = new SalaryDetail();
        detail.setEmployeeId(employeeId);
        detail.setMonth(month);
        detail.setBaseSalary(baseSalary);
        detail.setNormalPay(normalPay);
        detail.setOvertimePay(overtimePay);
        detail.setBonus(bonus);
        detail.setGrossSalary(grossSalary);
        detail.setDeduction(deduction);
        detail.setAdvanceDeduction(advanceDeduction);
        detail.setNetSalary(netSalary);
        salaryMapper.insert(detail);
        
        // 7. 扣除借支（更新借支状态）
        if (advanceDeduction.compareTo(BigDecimal.ZERO) > 0) {
            advanceService.deduct(employeeId, month, advanceDeduction);
        }
        
        // 8. 记录日志（审计用）
        log.info("工资计算完成：employeeId={}, month={}, grossSalary={}, netSalary={}", 
            employeeId, month, grossSalary, netSalary);
        
        return detail;
    }
}
```

### 难点3：返费自动计算（达标判断）

**问题**：
- 达标条件复杂（在职满30天 + 无请假 + 无违纪）
- 需要定时任务每日检查

**解决方案**：XXL-Job定时任务 + 规则引擎

```java
@Component
public class RebateCalculationJob {
    
    @XxlJob("rebateCalculationJobHandler")
    public void execute() {
        log.info("开始执行返费计算任务");
        
        // 1. 查询所有待计算返费的员工
        List<Employee> employees = employeeMapper.selectPendingRebate();
        
        for (Employee employee : employees) {
            try {
                // 2. 判断是否达标
                boolean qualified = checkQualified(employee);
                
                if (qualified) {
                    // 3. 计算返费金额
                    BigDecimal rebateAmount = calculateRebate(employee);
                    
                    // 4. 生成返费记录
                    RebateRecord record = new RebateRecord();
                    record.setEmployeeId(employee.getId());
                    record.setChannelId(employee.getChannelId());
                    record.setAmount(rebateAmount);
                    record.setStatus(RebateStatus.PENDING);
                    rebateMapper.insert(record);
                    
                    // 5. 通知经纪人（异步）
                    rabbitTemplate.convertAndSend("rebate.notification.queue", record);
                    
                    log.info("返费计算成功：employeeId={}, rebateAmount={}", employee.getId(), rebateAmount);
                }
            } catch (Exception e) {
                log.error("返费计算失败：employeeId={}", employee.getId(), e);
            }
        }
        
        log.info("返费计算任务执行完成，处理员工数：{}", employees.size());
    }
    
    /**
     * 检查是否达标
     */
    private boolean checkQualified(Employee employee) {
        // 1. 检查在职天数
        long days = ChronoUnit.DAYS.between(employee.getJoinDate(), LocalDate.now());
        if (days < 30) {
            return false;
        }
        
        // 2. 检查是否在职
        if (employee.getStatus() != EmployeeStatus.ON_JOB) {
            return false;
        }
        
        // 3. 检查是否有请假记录
        int leaveCount = leaveMapper.countByEmployeeId(employee.getId(), 30);
        if (leaveCount > 0) {
            return false;
        }
        
        // 4. 检查是否有违纪记录
        int violationCount = violationMapper.countByEmployeeId(employee.getId(), 30);
        if (violationCount > 0) {
            return false;
        }
        
        return true;
    }
}
```

**问题**：

- 需要智能识别表头和数据

**解决方案**：Apache POI + 规则模板

```java
@Service
public class AttendanceImportService {
    
    public ImportResult importExcel(MultipartFile file, Long projectId) {
        try (Workbook workbook = WorkbookFactory.create(file.getInputStream())) {
            Sheet sheet = workbook.getSheetAt(0);
            
            // 1. 识别表头（智能匹配）
            Map<String, Integer> columnMap = recognizeHeader(sheet.getRow(0));
            
            // 2. 解析数据
            List<AttendanceRecord> records = new ArrayList<>();
            for (int i = 1; i <= sheet.getLastRowNum(); i++) {
                Row row = sheet.getRow(i);
                if (row == null) continue;
                
                AttendanceRecord record = new AttendanceRecord();
                record.setProjectId(projectId);
                
                // 根据表头映射提取数据
                record.setEmployeeName(getCellValue(row, columnMap.get("姓名")));
                record.setIdCard(getCellValue(row, columnMap.get("身份证")));
                record.setAttendanceDate(parseDate(getCellValue(row, columnMap.get("日期"))));
                record.setCheckInTime(parseTime(getCellValue(row, columnMap.get("上班时间"))));
                record.setCheckOutTime(parseTime(getCellValue(row, columnMap.get("下班时间"))));
                
                records.add(record);
            }
            
            // 3. 批量插入（使用批处理提高性能）
            attendanceMapper.batchInsert(records);
            
            return new ImportResult(true, records.size(), "导入成功");
            
        } catch (Exception e) {
            log.error("考勤导入失败", e);
            return new ImportResult(false, 0, "导入失败：" + e.getMessage());
        }
    }
    
    /**
     * 识别表头（智能匹配）
     */
    private Map<String, Integer> recognizeHeader(Row headerRow) {
        Map<String, Integer> map = new HashMap<>();
        
        for (int i = 0; i < headerRow.getLastCellNum(); i++) {
            String cellValue = getCellValue(headerRow, i);
            
            // 姓名列（可能的表头：姓名、员工姓名、工号）
            if (cellValue.contains("姓名")) {
                map.put("姓名", i);
            }
            // 身份证列
            else if (cellValue.contains("身份证")) {
                map.put("身份证", i);
            }
            // 日期列
            else if (cellValue.contains("日期") || cellValue.contains("时间")) {
                map.put("日期", i);
            }
            // 上班时间
            else if (cellValue.contains("上班") || cellValue.contains("签到")) {
                map.put("上班时间", i);
            }
            // 下班时间
            else if (cellValue.contains("下班") || cellValue.contains("签退")) {
                map.put("下班时间", i);
            }
        }
        
        return map;
    }
}
```

```java
@Service
public class EmployeeService {
    
    private Cache<Long, Employee> localCache = Caffeine.newBuilder()
        .maximumSize(1000)
        .expireAfterWrite(5, TimeUnit.MINUTES)
        .build();
    
    public Employee getById(Long id) {
        // 1. 查询本地缓存
        Employee employee = localCache.getIfPresent(id);
        if (employee != null) {
            return employee;
        }
        
        // 2. 查询Redis缓存
        String key = "employee:basic:" + id;
        employee = redisTemplate.opsForValue().get(key);
        if (employee != null) {
            localCache.put(id, employee);
            return employee;
        }
        
        // 3. 查询数据库
        employee = employeeMapper.selectById(id);
        if (employee != null) {
            redisTemplate.opsForValue().set(key, employee, 30, TimeUnit.MINUTES);
            localCache.put(id, employee);
        }
        
        return employee;
    }
}
```
