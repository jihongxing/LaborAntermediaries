## 1. 问题与平台定位

现有 PRD 故事 43～55 已覆盖审核、风险、对账等概括目标，但“谁能审核、谁来复核、双方如何举证、结论如何执行、平台自己有利益冲突怎么办”尚不完整。只有一个管理员后台，不能证明平台具备中立监督能力。

建议将平台定义为**交易规则的执行与程序监督方、交易事实的核验协作方、争议处理的组织方**。中立不是不处理问题，而是对用工方、供应商、经纪人及平台自身使用可解释、一致、可复核的程序。

平台不因用工方是获客重点而偏袒其投诉，也不因供应商支付平台费而倾斜审核；经纪人和工人有与本人业务相关的直接申诉入口，不以被投诉公司的同意为前提。平台内部复核不是当然独立的第三方裁决；平台处理结论不冒充司法、行政、仲裁或融资机构结论。本稿仅作产品设计，不作法律权限与责任结论。

### 1.1 监督什么，不替代什么

| 环节 | 平台应审核/监督 | 不得替代 |
|---|---|---|
| 入驻与授权 | 材料、来源、主体/经办授权、适用能力、补正及复审 | 不凭营业执照替人接管组织；不保证未来一定履约 |
| 需求发布 | 真实性核验、关键字段、业务范围、版本和补正依据 | 不伪造需求，不替买方决定采购价格与服务目标 |
| 应标选标 | 合格可见、规则披露、版本变更、配额和授权过程异常 | 不替用工方评标、指定中标，不查看或转发无关供应商私密报价 |
| 履约确认 | 承诺与实际差异、确认超时、异常和证据缺口 | 不替驻场证明未见事实，不修改原始打卡或代双方确认无争议量 |
| 对账收付 | 到期依据、凭证核验、未知结果、部分支付和争议隔离 | 不替劳务公司资金审批，不伪造到账，不从应收推定应付可延期 |
| 纠纷与信用 | 双方举证、处理理由、申诉复核、纠错传播及整改 | 不把投诉即违约、不回应即承认；不自动扣钱、认定债权或判失信 |
| 平台自身 | 收费争议、人员违规、利益冲突、数据滥用及处理质量 | 不由被投诉员工或服务费收取人员单独终审，不付费加速/买结论 |

## 2. 平台岗位、分工与权力约束

岗位是权限与职责集合，不要求每个岗位独立招聘；小团队可以兼任普通工作，但不得让同一人完成受限制案件的初审与独立复核，不能因人手不足静默放宽约束。

| 岗位 | 工作目标与可见范围 | 可做 | 不可做 |
|---|---|---|---|
| 审核运营/分派负责人 | 看审核/案件队列、风险级别和处理容量 | 分类、认领、分派、转交及升级；记录理由 | 无任务授权查看全部原始证据；以销售价值覆盖优先级 |
| 主体/资质审核员 | 当前申请及获授权核验材料 | 核验、补正、提出通过/不通过意见 | 越权开通能力、接管组织、删除审核依据 |
| 需求审核员 | 当前需求、授权及关联材料 | 核验需求、检查版本及提出重审 | 代改需求商业条件、替买方选标 |
| 履约监督员 | 授权项目的投递摘要及异常线索 | 要求说明、催办、建立案件和跟踪整改 | 直接改工时、合同、已锁账单或支付结果 |
| 投诉受理/协调员 | 本人承办案件的必要信息 | 核实诉求、收集双方材料、组织调解 | 对自己经办或有利益关系的事项独立复核 |
| 事实核验/独立复核员 | 授权案件和必要证据 | 分事实意见、复核处理理由、退回补证 | 把调解提案当双方已达成协议；冒充外部裁决 |
| 风险处置审批员 | 受控措施的证据、范围和影响 | 审批临时措施、复查、到期解除及恢复 | 默认冻结资金、阻断本人查账/申诉或无限期延长 |
| 业务执行协同员 | 已通过复核的具体执行任务 | 发送业务修正请求、查回执、跟踪更正传播 | 绕过原业务授权、直接改库/点击“已付” |
| 规则维护/发布岗位 | 规则差异、适用范围及批准记录 | 草拟、复核、定时发布/回滚 | 作者独自批准发布；用新规则静默重判历史 |
| 平台财务/支付运营 | 授权账单、机构回执及对账异常 | 出具计费依据、提供核验结果、跟进回执 | 独立终审对本平台收费的投诉；代劳务公司支出审批 |
| 安全审计/质量监督 | 分级授权的审计事件与抽样材料 | 访问复核、质检、人员违规调查和纠错跟踪 | 授权自己处理自己；为降低投诉量删记录 |
| 销售/客户成功 | 联系依据、采用障碍及授权跟进状态 | 协助准备资料、向客户解释流程 | 修改审核结果、影响独立复核、因付费改变排队或结论 |

受限行为至少包括：原处理人自审其申诉、被投诉人接触保护证据、利益相关人独立终审、规则作者自批发布、处置提议人自批重大限制。职责可兼任与受限行为的定义须在 D-17 定稿；约束由服务端执行，不只写进员工手册。

## 3. 能力分解与 PRD 映射

| 工作包 | 平台交付结果 | 主 FR | 与既有能力的边界 |

| 准入/需求复审 | 补正、来源核验、变更重审、能力恢复可追踪 | FR-16 | 不另造材料矩阵或付费审核 |
| 交易监督台 | 关键节点、差异、超时、证据缺口与双方待办 | FR-17 | 只读授权摘要和产生监督任务，不另造业务账本 |

| 投诉与举证中心 | 受理、分类、双方答复、证据清单及分项意见 | FR-18 | 复用工时/返费等领域申诉，关联而非重复计案 |

## 4. 审核任务闭环（FR-16）

### 4.1 任务与核验

每项任务至少关联：任务编号、业务对象及版本、申请/触发方、平台岗位、分派历史、规则版本、材料清单、来源核验结果、结论理由、补正内容、通知及复核入口。可从组织申请、资质变化、需求提交/关键变更或定期检查触发；复审周期不是本稿已确认参数。

任务接入 → 分类/检查授权 → 分派或认领 → 来源核验 → 补正/待外部核验 → 提出结论 → 按规则独立复核 → 通知 → 业务门禁执行回执。通过、补正、不通过、待核验、已被新版本替代等须可区分，超时不能自动通过。

- 材料、字段预检与真实性核验分开显示；上传齐全不等于真实性通过。
- 核验渠道故障进入待核验；保存尝试及失败原因，不能写“申请人造假”。
- 补正逐项说明缺什么、为何需要、如何修正；引用未变材料，不强迫重复上传。
- 业务对象关键版本改变时重新验证审核资格；旧任务不能通过迟到结果解锁新版本。
- 认领、转派与最终提交需防并发冲突；重复回调/点击不能产生多次开通、矛盾结论或重复限制。
- 通过时说明获批主体、角色和能力，平台审核记录不显示成政府或融资机构背书。

### 4.2 服务时钟

受理、处理、补正、外部核验、复核和通知分别记录开始/结束；等待可标记原因、下一动作、责任人和复查时点。仅按批准规则暂停计时，保留总历时、有效处理时长和暂停时长。队列积压自动升级，不因转派重置总等待。

本版不指定审核天数、地区或外部渠道；可配置不等于已对外承诺。缺少配置时显示待配置并进入人工分派，不自行采用历史天数，更不能无限隐藏积压。

## 5. 交易全程监督与异常分流（FR-17）

### 5.1 监督看板

以需求—应标—中标快照—供给计划—到岗/确认—账单—到期收付为时间轴，展示来源版本、责任主体、应办事项、约定期限、最新回执及已存在的案件。默认聚合/脱敏；展开原始材料须有任务和字段级权限。

| 线索 | 初始动作 | 不允许的推断 |
|---|---|---|
| 关键需求变更、供应商未获通知 | 查版本与送达、补投递、提示交易方重确认 | 自动替供应商接受新价格 |
| 应标/选标过程异常或配额冲突 | 检查已披露规则、权限、时间和日志，要求说明 | 平台自行选中另一家供应商 |
| 计划供给与实际到岗/有效履约明显偏离 | 核实单位、时间、变更及双方说明，催办补救 | 计划未兑现即直接判欺诈 |
| 工时/账单长期未确认 | 核实约定期限和证据，催办、升级或建案 | 超时默认同意、直接改变结算量 |
| 账款到期、部分支付、回执结果未知 | 核实到期依据、争议部分和通道状态，分科目跟进 | 未知即失败、线下自报即到账、项目未回款即可拖欠工资 |
| 多次投诉、疑似重复凭证/互刷、数据越权 | 归并关联、保全必要证据、人工核验及安全升级 | 投诉数量等于失信、同证据重复计为多次违约 |

### 5.2 临时措施与整改

受控措施记录对象、证据、规则依据、影响能力、审批人、起止/复查时点、告知方式和申诉入口。可建议暂停新需求/新应标、限制争议字段继续传播等；具体可用措施需 D-18 评审，不默认启用。

采取措施前说明必要性和范围。涉及紧急安全风险时，只有在专门批准的应急规则下才能先做范围最小的临时防护，并及时人工复查与告知；不能借“应急”绕过审计或取得资金权限。申诉不自动取消必要安全措施，措施也不等于失信结论。

整改必须写明责任主体、内容、证据、约定/批准期限和复核人。到期未完成转人工复查，不自动永久封禁；完成后重新核验恢复条件，恢复不抹除历史。措施到期按批准策略解除或进入复查，不能静默无限续期。存量打卡、查薪、对账、申诉、补发等必要能力按既有规则保留。

## 6. 投诉、调解与独立复核（FR-18）

### 6.1 受理与分类

用工方 Web、劳务公司 Web、驻场/项目经理 App、工人/经纪人小程序提供与本人或授权业务关联的投诉入口，平台 Web 办案。未通过入驻、权限受限或合作已结束的主体仍可经身份和历史关系核验访问相关案件；不因此重新开通业务能力。平台违规/越权等举报可由安全受控入口先受理为线索，不要求先证明交易违约。

案件至少包含：申请人及代表授权、被涉及主体、对象/版本、诉求和分项金额/数量、争议与无争议部分、证据清单/来源、受理范围、双方联系人与可见字段、承办/复核人、时钟、状态、处理版本和执行任务。

先确认属于资料审核、交易流程、履约/工时、归属/返费、付款/平台费、信用更正、平台人员/数据问题中的哪类。领域申诉保留原编号和业务权责；平台案件关联协调，不复制一套工时或返费结果。重复投诉关联主案，新增证据/不同诉求不能仅因重复而丢弃，也不得重复计数处罚。

超出平台处理范围时给出原因、已有材料和可用后续渠道说明；外部申请或处理结果由当事人补充并标明来源/核验状态，不声称平台已有自动移送或执行能力。

### 6.2 双方举证与保护

核实主体与关系 → 指定无冲突承办人 → 通知相关方 → 分别举证/答复 → 列明已确认/争议/证据不足事项 → 调解建议或规则处理意见 → 独立复核 → 通知 → 申诉/执行。

- 对各方提供与具体争点相关的答复机会、要求和处理进度；未回应只记录送达/未回应状态，不自动承认指控。
- 交换可核验的脱敏摘要和必要反证，不把证人/举报人身份、工资、联系方式或无关报价全量共享。确需限制披露时记录理由、范围及可替代答复材料。
- 举报人保护由有权人员限定身份可见范围，不对绝对匿名或绝不推断身份作保证；被投诉人不得因原岗位权力查询保护材料、删除投诉或报复性关停申诉。
- 每份证据保存提交人、来源、时间、关联业务版本、访问和更正轨迹；平台原始事件、单方陈述、双方确认、外部回执分列。缺少证据不能靠高收费客户的口头确认补齐。
- 证据不足可以补证、维持未确认或以证据不足说明结束本轮核验；均不得在信用档案展示为违约成立。

### 6.3 处理与申诉

处理意见区分四类：**事实核验意见、调解提案、平台规则内处置决定、已核验外部处理结果**。调解提案须由相关方明确同意且有权确认，未经接受不能写成已达成协议；平台规则处置不能超出已批准范围。

决定保存争点、事实、依据/规则版本、采信与不采信理由、适用范围、处理/复核人、通知结果、申诉入口与期限配置。原处理人、利益相关人不能独立复核；无可用无冲突人员时升级或待复核，不自动生效高影响处置。一般事项是否需双人复核由规则定义，但不得免除申诉复核的回避。

新证据、程序瑕疵、执行未达标可发起申诉/重开并关联原案。不得由原处理人独自驳回对自己的申诉。未明确终结条件、重开规则及专业要求前不定义“平台终局裁决”。

## 7. 决定、执行与信用联动（FR-18/19）

处理意见、规则决定、业务调整、实际收付和案件结束分别保存状态，不能一个“已处理”全部代替。

| 执行类型 | 谁实际执行 | 完成依据 |
|---|---|---|
| 申请资料或需求更正 | 有权申请人/发布人，必要时重审 | 新版本、审核及通知回执 |
| 工时、归属、账单差异修正 | 既有领域授权人员与原业务服务 | 更正/补差事件及必要双方确认，原始事件不覆盖 |
| 付款核验或补付 | 义务方资金审批人及获授权执行机构 | 授权和真实机构回执/经核实凭证；平台决定不等于扣款授权 |
| 信用事实更正 | 获授权信用核验岗位及 FR-15 投递链 | 原事实关联、新版本、接收方/摘要/缓存同步结果 |
| 限制或恢复新增能力 | 按规则审批的处置岗位及门禁服务 | 措施版本、生效/解除回执及通知 |

执行任务记录对象、动作、前置条件、授权、唯一业务键、责任人、期限/复查时点、结果及失败恢复；重复执行不重复调整账务或支付。执行中权限/版本变化须重新检查，不以旧决定绕过现行授权。执行失败或未知保持在途、告警和人工接管，不能结案冒充完成。

争议部分单列，无争议部分按合同与既有权限流程继续，不因立案一刀切冻结整个项目。平台对自己服务费的争议同样拆分，不通过限制申诉、工资或返费办理催缴。

结案应区分：协议已达成但待执行、决定已通知但待执行、执行完成可结案、撤回/不受理/证据不足说明结束。完成型结案必须有对应执行证据及通知；程序性结束注明仍未解决的诉求、权利与后续入口，不能计为履约修复或“争议已解决”。

## 8. 规则治理、利益冲突与平台自我监督（FR-19）

- **规则公开与版本：**公开适用对象、材料要求、处理/申诉流程及影响范围；适用规则保存版本、生效时间和通知，内部反滥用阈值按必要性控制披露。
- **制定和发布分离：**草案、影响分析、业务/安全等必要评审、批准、发布及回滚均留痕；收费规则仍以[商业模式与收费标准](../03-账单与资金/商业模式与收费标准-v0.1.md)为唯一来源。
- **历史案件：**引用当时有效规则和交易快照；新规则不自动追溯重判或改历史费用。确需重开须说明范围、依据、通知及审批。
- **利益冲突与回避：**记录与当事方的销售、收费、经办、亲属/其他利益关系申报；分派和复核校验已知关系，相关方可申请回避。信息不完整时允许补充申报，不宣称算法能识别全部冲突。
- **平台被投诉：**走独立工单与无利益冲突复核路径，原被投诉人/其收费经办人不能单独终审；涉及整个平台利益时展示内部复核局限并保留外部渠道，不假称已交“独立第三方”。
- **内部数据访问：**以案件/任务、角色、字段、用途、时限共同授权；平台租户不是全库通行证。紧急读取也须预设范围、限时和事后复查，不能赋予业务审批或资金权。
- **质量抽检：**按批准的风险/随机策略抽样，查看证据完整度、理由质量、回避、通知、执行及改判。发现错审重开纠正，不静默删历史结论。
- **不做绩效诱导：**不以驳回多、处罚多、关单快或投诉少作为唯一好绩效，不把客户付费额、中标金额当审核通过依据。审计利益冲突和越权，不只审计供应商。

## 9. 平台工作台与参与方入口

平台 Web 建议按任务而非按数据库表组织：

| 区域 | 必需内容 |
|---|---|
| 我的工作台/分派台 | 待认领、临期/超时、待外部核验、需回避、待复核、待执行；负责人及下一动作 |
| 审核中心 | 对象/版本对比、材料清单、来源核验、补正、理由、历史结果及门禁执行状态 |
| 交易监督台 | 授权时间轴、异常摘要、双方待办、关联案件、约定期限及关键回执 |
| 案件中心 | 争点、双方说明、证据分层、可见性、调解/规则意见、复核、通知及重开 |
| 处置执行台 | 整改、临时措施、恢复、业务更正回执、失败重试及跨组织同步 |
| 规则与质量中心 | 规则版本/发布、权限与回避、平台自身投诉、抽检、审计和质量指标 |

参与方原有各端增加审核结果/补正、本人案件列表、分项诉求、证据提交、答复、结果依据、执行进度和申诉入口；不要求用户进入平台内部后台。平台工作人员移动审批是否需要新增端能力另行评审，不据此删去已确认的独立 App。

## 10. 系统设计要求与不变量

建议区分任务、案件、争点、证据引用、核验意见、规则决定、复核、执行任务、限制措施、规则版本及审计事件。案件/决定为事实与程序记录，不是可直接覆盖交易账务的“超级单据”。具体表、接口和存储由技术设计决定。

- 核验状态、决定状态、申诉状态和执行状态独立；已复核不等于已执行，已通知不等于对方接受。
- 一个申请版本不能有并行冲突的有效审核结论；版本、锁定及幂等在服务端校验。
- 平台仅使用授权投递数据和案件必要材料；跨租户证据投递白名单、来源、撤权/更正同步沿用 FR-14。
- 涉及信用结论仅向 FR-15 提交有来源、有核验和争议状态的事件；立案、告警、未答复不直接生成负面信用。
- 决定更正保留前后版本，派生摘要及后续导出同步更新；已下载材料不能承诺自动收回，按授权和接收方流程通知更正。
- 证据访问、下载、通知、派单、回避、复核、执行、重试和规则发布可审计；敏感内容不直接写入普通通知与日志。
- 保存期限、删除与必要留痕按 D-12/16/19 决策，不以监督为由永久保存所有原始个人信息。

## 11. 验收场景

沿用 PRD 第 13 节的跨端、跨组织业务场景，验证外部可观察结果，不以后台“有按钮”或流程图存在验收。新增平台工作流串联同一业务对象及其原有领域接口，不新建可绕过权限的通用执行通道。

| 场景 | 预期结果 | FR |
|---|---|---|
| 外部核验失败/材料齐全但未核实 | 留待核验和原因，不自动通过、不标申请造假 | FR-16 |
| 补正后提交新版本，旧结论晚到 | 旧结论不能解锁新版本，记录替代关系与新任务 | FR-16 |
| 两人同时认领/重复点击通过 | 不产生冲突有效结论或重复开通，冲突可见 | FR-16 |
| 销售要求加速付费客户的审核 | 无修改通过/复核权限，不产生付费优先或付费补审 | FR-16/19 |
| 配额异常、需求变更后供应商未确认 | 平台催办/核验，不代替选标和接受条件 | FR-17 |
| 支付未知或应收尚未到期 | 不认定付款失败/逾期，不自动限制或生成负面信用 | FR-17 |
| 工人被停用、经纪人合作已终止 | 可验证本人身份与历史业务后查看/申诉，不恢复无关业务权限 | FR-18 |
| 被投诉方拒绝答复/原管理员试图删投诉 | 记录送达与未答复，不默认成立；无删除/终审权限 | FR-18/19 |
| 暴露举报人身份或跨租户下载证据 | 拒绝越权、记录审计，提供必要脱敏答复材料 | FR-18/19 |
| 原处理人复核其申诉/无可用回避人员 | 服务端拒绝自审并升级，保持待复核，不自动高影响生效 | FR-18/19 |
| 调解只有一方同意 | 保持提案/未达成，不能记协议成立或触发付款 | FR-18 |
| 有结论但没有业务/机构执行回执 | 仍待执行/未知，不记完成型结案，不伪造到账 | FR-18 |
| 争议工时更正重复投递、执行权限已撤销 | 防重不重复补差；权限失效进入待授权/升级，不绕过资金审批 | FR-18 |
| 临时限制到期、整改完成或提出申诉 | 按审批范围复查/解除并留回执；申诉等必要能力持续可用 | FR-17/19 |
| 平台服务费或工作人员被投诉 | 原收费/被投诉经办不能独自终审，保留未解决事项和后续入口 | FR-19 |
| 信用事实改判但接收方同步失败 | 新事实与在途任务可见，告警/重试，不宣称更正全部完成 | FR-15/18 |
| 新规则发布/回滚 | 有独立批准和生效版本，不自动改历史快照与费用 | FR-19 |

## 12. 指标、验证与待评审决策

### 12.1 质量优先于关单数量

| 指标 | 观察口径 |
|---|---|
| 审核积压与处理历时 | 按对象/风险/状态观察任务数、总历时、有效处理时长及等待原因；转派不清零 |
| 理由和证据完整度 | 抽检任务中具备规则、材料来源、理由、通知与必要复核的比例；未核验事实不冒充完整 |
| 改判与重开 | 按原因展示复核改判、执行失败、补证重开；不把正当改判本身当坏绩效 |
| 完成型结案执行率 | 已有真实执行证据的应执行任务数/期间应执行任务数；另列未知、失败及程序性结束 |
| 纠错传播及时性 | 按接收方统计更正应同步/已同步、延迟和失败，不只看源系统改成功 |
| 中立与访问控制 | 应回避/已回避、试图自审、越权读取/导出、平台自身投诉处理；关键越权为验收失败项 |
| 服务与公平性 | 各类主体的等待、补正、申诉可达性和投诉反馈；按样本/案件类型解释差异，不预设一方更可信 |

不在本稿指定百分比 KPI 或固定响应小时数；先形成真实样本和运营能力基线，再评审内部目标与对外时效。

### 12.2 首轮情境验证

1. 让用工方、供应商、经纪人分别带一个真实审核/争议案例，核对证据来源、谁有权确认、谁能更正，以及希望看到的处理依据。
2. 邀请人事经理、财务、驻场和工人复盘一次工时/账单差异，验证平台介入是否减少扯皮，还是制造重复确认；不以平台介入替代原确认责任。
3. 以“付费供应商投诉用工方”“用工方投诉重要供应商”“投诉平台收费/员工”三个对称场景检验中立流程。
4. 让平台工作人员演练补正、旧版本回调、利益回避、未回应、证据不足、执行失败和改判，记录人力、权限缺口及可承诺时效。
5. 让弱权限、受限账户和离场人员测试本人申诉及证据访问，确认不必依赖被投诉方代办。

验证产物为脱敏案例、权限矩阵、争点/证据模板、处置执行清单、运营容量与未决规则；不以访谈认同等同平台已具备公正处理能力。

### 12.3 待评审决策

| 编号 | 必须明确的内容 | 未决边界 |
|---|---|---|
| D-17 | 岗位授权、案件分派、利益冲突/回避、独立复核人员与无人可复核时升级 | 不允许自审申诉或以超级管理员绕过职责分离 |
| D-18 | 可受理事项、证据门槛、双方答复/申诉和时钟、临时措施、执行授权、结案/重开及外部渠道 | 不承诺固定期限/终局裁决；不默认同意、不自动扣款或永久封禁 |
| D-19 | 规则批准发布、平台自身投诉、抽检、证据分级访问/保护、保存与更正传播 | 不默认全库可见、不让被投诉人终审，不将新增规则直接追溯历史 |

D-17～19 与既有 D-01～16 一并评审。具体地区、审核渠道、复审周期和人员编制可继续验证，本稿不把确定这些参数当作继续设计的前提。
