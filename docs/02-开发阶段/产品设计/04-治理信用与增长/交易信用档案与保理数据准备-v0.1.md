| 非目标 | 建立未解释的综合信用分、对外提供征信报告、承诺授信/保理/融资、以平台记录替代机构尽调 |

## 1. 产品定义

本设计所称“平台信用”，第一阶段定义为**交易信用档案**：围绕真实需求、应标承诺、履约、确认、结算、付款/回款、争议与整改形成的有来源、有时间、有责任主体、可查看和可纠错的事实记录。参与者可查看与自己交易相关的对方档案摘要；主体可查看自身完整档案并发起纠错或申诉。

“维护好自己的羽翼”落到产品上，是持续积累可验证的履约证据和及时处理异常，而不是购买信用、刷分或由平台单方面贴标签。信用档案以**事实事件 + 口径 + 来源 + 状态**为基础；是否提供汇总指标、排序或等级，须另行验证可解释性、公平性和使用目的，不作为本版默认功能。

平台信用档案不是法定征信结论、信用报告或融资评级。未来可在主体授权、交易方知情、用途限定、数据字段最小化及接收机构评审后，为银行或持牌保理机构提供交易资料包；机构独立进行准入、授信、定价和风险决策。资料完整不等于信用良好，更不等于必然获批融资。

## 2. 主体模型与角色边界

| 主体 | 档案归属 | 主要可见内容 | 不应混淆 |
|---|---|---|---|
| 用工方 | 经审核的组织主体；成员操作留个人审计 | 需求真实性与变更、采购/选标流程记录、合同约定下的结算确认、应付款及已核实回款表现、争议与整改 | 不以需求撤回、正当争议、不可抗力或未到期款项直接推定违约；经办人行为不自动成为个人信用记录 |
| 劳务供应商 | 经审核的供应商组织主体；项目/成员操作可追溯 | 资质状态、应标承诺、供给计划与实际到岗、履约完成、工时/账单确认、合同约定付款及义务状态、投诉争议及整改 | 计划人数、单次缺勤、争议中的金额或未经核实的投诉不能直接认定失信；组织档案不自动转为法定代表人或员工个人信用 |
| 独立劳务经纪人 | 经验证的个人账号及其受授权劳务公司合作关系分别记录 | 授权关系有效期、推荐来源与回执、重复提报裁定、候选人授权状态、有效推荐结果、返费规则/应付/实付状态及争议 | 经纪人个人记录与其合作劳务公司信用分开；不展示被推荐人的工资或其他经纪人的资料；不把雇主/供应商违约归责给经纪人 |

平台内部另保留主体认证、审计、投诉与处置记录。平台运营人员不得以未经核实的内部标签对外形成“黑名单”或公开失信结论。

## 3. 信用维度与事实口径

### 3.1 用工方组织档案

- **需求履真与稳定性：**需求审核和补正状态、发布后关键条件变更、暂停/撤回及原因；区分正常业务调整与无合理说明的反复变更。
- **采购与合同协作：**授权是否完整、选标记录是否按已披露规则完成、合同/中标快照确认状态。
- **履约确认协作：**是否在约定或配置时限内处理排班、工时、验收和账单；记录响应耗时和待处理状态，不把平台建议时限当成合同义务。
- **结算与回款：**合同到期应付、已核实实付、部分付款、短款、逾期天数、争议金额和争议结果；按合同主体、账单科目和到期日计算。
- **争议与整改：**投诉、异议、核实结论、责任认定、整改动作及完成情况。

### 3.2 劳务供应商组织档案

- **组织与资质：**审核状态、适用资质及有效期、补正/核验状态；清楚标明“平台审核记录”而非政府背书。
- **应标可靠性：**提交、修订、撤回和中标确认的时间及版本；履约承诺与实际供给差异。未中标或未应标不作为负面信用。
- **供给与履约：**计划/确认能力/候选/到岗/在岗/有效履约量逐阶段记录，注明统计分母、项目条件和数据来源。
- **出勤、工时与服务质量：**经确认的工时差异、补员响应、到岗和留存等指标；争议数据、外部来源与平台第一方数据分列。
- **结算与付款：**合同约定的到期义务、经核实付款或支付回执、逾期、部分支付、争议和补正；不把资金不足推断成恶意。
- **投诉、争议与整改：**仅展示核实状态、结论和申诉结果；未核实投诉不可作为已成立事实。

### 3.3 独立劳务经纪人档案

- **身份及合作授权：**身份核验状态、授权劳务公司、授权范围、有效期及解除时间。
- **推荐记录质量：**候选人授权/告知状态、推荐提交回执、资料完整性、重复提报及裁定结果。
- **有效推荐履行：**经确认的报名、到面、入职或约定有效节点；注明定义、统计期间和来源，不用单纯转化率掩盖岗位条件差异。
- **返费透明度：**适用政策快照、达标状态、应付金额、实付凭证和争议状态；明确付款责任主体，不暗示平台担保。
- **纠错与合规处置：**虚假承诺、未经授权提交、资料错误等事件需有证据、核实、告知、异议和处理结论。

## 4. 展示方式与访问控制

采用三层展示，默认最小披露：

1. **交易对手摘要：**仅向满足资格和授权条件的应标/邀约参与方、授权合作方或存量交易对手展示与合作相关的主体级摘要、统计期间、样本量、口径、数据更新时间、未决争议说明和来源类别。不要求先成交再了解对方，但不建设公开可检索的个人信用榜。
2. **主体自有档案：**主体可查看自身明细、原始来源引用、计算口径、查看记录、纠错入口及历史版本；经纪人只能看本人及授权合作范围内记录。
3. **融资数据资料包：**仅在主体针对特定接收方、特定目的明确授权后生成；字段、期间、接收方、下载/访问和有效期均有审计。平台不因参与交易而默认向资金方共享。

授权撤销后阻止新的在线访问与导出；已经下载到接收方的资料不能宣称技术上自动收回，应记录接收方通知、后续更正、停止使用/删除处理及反馈。授权人不能代替其他主体授权其无权提供的材料；机构接入、合同及资料接收条件未评审前，仅预留证据模型和虚构样例，不启用真实机构导出。

不得跨主体展示个人身份证件、联系方式、工资明细、银行账号、候选人名单、商业秘密、其他供应商报价或非必要原始凭证。对外摘要优先使用聚合数据和脱敏凭证引用；任何个人层级记录均须有明确目的、访问权限和必要授权。

### 4.1 谁看谁，以及为了什么

| 查看方 | 对方档案 | 建议可见内容与门槛 |
|---|---|---|
| 用工方老板/人事经理 | 参与其应标、邀约或项目的供应商 | 主体核验、承诺兑现、有效履约、对账协作和已核实整改的摘要；不展示其他客户合同明细及利润 |
| 合格应标/受邀或已合作供应商 | 对应用工方 | 需求变更、确认协作、到期付款核验摘要；组织授权、需求资格和展示授权须通过校验 |
| 供应商 | 与其建立授权合作的经纪人 | 合作授权、资料授权完整性、有效推荐及已核实归属裁定摘要；不展示其他合作公司的候选名单/佣金 |
| 经纪人 | 与其建立授权合作的供应商 | 返费政策兑现、确认及时性、到期返费核验和争议整改摘要；不能借此直接对接用工方 |
| 各主体本人/组织授权成员 | 自身档案 | 按成员职责查看明细、依据、待办、访问记录及申诉；组织员工并非天然拥有完整档案权限 |
| 平台运营/复核人员 | 待核验/申诉相关主体 | 按工单职责查看必要证据，复核和敏感访问留痕；禁止随意搜索或修改主体事实 |

具体摘要字段和小样本脱敏门槛由 D-16 评审；即使是交易摘要，也不能通过金额、时间或少量样本反推出其他交易方和个人。

### 4.2 信用维护的正向反馈

- 自有档案首页展示经核实的完成记录、数据完整度及“待确认/待补证/待整改”任务，提供明确责任人、依据及处理入口。
- 持续履约、按约确认、按期付款和完成整改均能形成可查记录；新主体显示“平台记录不足”，不能默认比老主体差。
- 处理完成形成新的事实与更正版本；不能付费删负面、买分、用缴纳平台费换取信用提升，或以拖欠平台费为由篡改已核实履约事实。
- 信用记录供合作判断参考；是否影响邀约、评审或合作条件须由独立规则评审，不能把本稿当作自动惩罚或承诺交易机会的依据。

## 5. 状态、纠错与争议治理

平台侧受理、双方举证、利益回避、独立复核、业务执行及平台自身投诉，统一衔接[平台方审核与中立监督需求](./平台方审核与中立监督需求-v0.1.md)的 FR-18/19；本稿仍维护信用事实和展示口径。案件结论与事实更正执行分离，立案/未回应不直接成为负面信用，更正须追踪到接收方同步结果。

每条信用事件至少保存：主体与组织关系、事件类型、关联项目/合同/账单、发生与入库时间、责任方、规则版本、数据来源及来源质量、证据引用、金额/数量与单位、核验状态、争议状态、可见级别、计算口径版本、纠错/申诉轨迹和保留期限。

系统设计应沿用 FR-14 的租户边界：信用档案通过授权的事实投递与字段白名单形成摘要，不能以“统一档案”为由跨租户直接读取合同、人员或付款明细。源业务事件须有唯一标识并防重，撤回、更正、授权变更同步摘要及缓存；任一汇总可追溯到其来源和规则版本。驻场/项目经理依现有授权提供证据，不因提交证据获得修改信用结论的权限。

来源至少区分平台原始事件、双方确认、单方提交和外部机构回执；自动采集不等于自动核实，银行回执也需核对主体、金额与关联账单。脱离真实交易的自评、互刷、拆单或重复凭证不能增加已核实记录；异常进入人工复核，平台不能让被投诉方单方面关闭对自己的申诉。

核验状态、争议状态与展示状态分别管理：核验为`已采集 → 待核验 → 已核实/证据不足`；争议为`无争议 → 异议受理 → 复核中 → 维持/更正/撤销`；展示为`仅主体可见/授权摘要可见/暂停传播/不再用于摘要`。已核实记录也可再申诉，不能因单一线性状态掩盖这一点。更正产生新版本并关联原事件；留存、到期删除及必要审计保留另按 D-12/D-16 评审，不等于永久保存原始个人资料。

- 未到期义务不显示逾期；结果未知、接口超时、凭证待核验不显示为已付款或违约。
- 有争议记录须显著标记，默认不计入负向汇总；申诉期间限制传播，除处理该交易所必需外不向新的交易对手展示。
- 主体可查看记录依据、提交补充证据并申诉；应记录受理、处理人、理由、时限配置和结果。重大不利展示前须完成人工复核与告知。
- 统计指标需显示期间、分母、样本量和排除规则；样本不足时显示“数据不足”，不生成排名或负面标签。
- 任何限制交易、拒绝合作或融资资格的决定，不得仅由平台信用指标自动触发；决策规则、人工复核及申诉渠道需单独评审。

## 6. 面向未来保理的数据准备

平台当下建设目标是让交易证据可核验、可归属、可追溯、可授权导出，而非先做融资评分。优先沉淀需求版本、应标及中标快照、合同关系、履约确认、账单、付款/回款凭证、争议和更正链条。

对未来融资资料包，至少应能证明：

- 交易各方主体与授权关系，以及合同、需求、中标、履约、账单之间的关联；
- 应收/应付的合同依据、形成条件、金额计算、确认人、账期、到期日和变更历史；
- 已收/已付、部分收付、未结、争议、退款/冲正及机构或银行凭证的来源；
- 数据由谁提交、谁确认、何时更改、是否存在争议，以及导出时适用的口径版本；
- 特定主体对特定接收方和用途的授权记录。

不得默认开放自动债权转让、融资申请、资金归集、平台放款或信用评分服务。未来保理机构自行核验债权真实性、转让条件、重复融资风险、交易对手资信和法律文件；平台档案只是经授权的业务证据来源之一。

## 7. 关键验收场景

| 场景 | 预期结果 |
|---|---|
| 用工方有一笔未到期账单 | 不显示逾期，不降低逾期类指标 |
| 回款凭证已提交但未核实 | 显示待核验，不计为实收或违约 |
| 供应商履约量存在争议 | 双方看到各自可见的争议状态；未决量不进入负向汇总 |
| 经纪人推荐发生重复归属争议 | 仅相关授权方可见，裁定完成前不将其计为违规 |
| 组织管理员查看经纪人个人档案 | 默认拒绝；仅允许其查看合作授权和相关交易所需数据 |
| 参与方要求查看档案依据 | 返回可解释的事件、来源类别、时间范围、样本量和纠错入口 |
| 主体授权向保理机构导出 | 只导出授权字段/期间/接收方范围，并记录授权、访问、下载及撤销状态 |
| 未授权资金方尝试获取资料包 | 拒绝访问并留下审计记录 |
| 小样本或数据来源不完整 | 显示数据不足/来源有限，不产生排名、信用标签或融资结论 |

## 8. 待评审决策

- 各类事件的核验责任人、数据来源等级、统计期间、样本阈值和指标公式。
- 交易对手摘要的具体字段、可见条件、异议期间和个人信息影响评估。
- 逾期、履约偏差、取消与整改事件的合同依据和可展示口径。
- 档案数据保存期限、删除/更正例外、跨组织导出和主体授权撤销处理。
- 是否以及何时引入外部征信、银行或保理机构；接入模式、合同、收费及责任边界。
- 是否需要汇总等级或评分。若评审考虑评分，须先完成数据充分性、公平性、可解释性、偏差测试、申诉机制和适用专业审查；当前版本不定义分值、权重或自动决策。

## 9. 指标口径建议与首轮验证

以下均为待评审示例，不直接配置生产阈值：

| 口径 | 定义建议 | 防止误读 |
|---|---|---|
| 约定时限内确认率 | 期间内按约定截止前完成确认的事项数 / 期间内截止且具备确认条件的事项数 | 用合同/已确认流程时限，排除未决争议并披露数量，不用平台建议时限判违约 |
| 到期付款表现 | 按合同账单分别展示到期无争议应付金额、核实按期实付、部分付款、逾期未结及逾期天数 | 争议金额单列；未到期不算逾期；经纪人应收返费不归责为经纪人付款违约 |
| 承诺兑现 | 同项目/节点/单位展示最终有效承诺、经确认实际量及差异原因 | 需求变更同步版本，不混用计划人数、到岗人数、有效人天；不跨不同合同条件粗排 |
| 事实来源可追溯覆盖率 | 具备有效主体、关联交易、来源及证据引用的事件数 / 统计期事件总数 | 单方自报不能算已核实；同时披露核验状态占比 |
| 更正同步与申诉处理 | 到期应同步接收方的成功数/总数；申诉受理至处理的时长及未结数量 | 更正需同步摘要、缓存及后续导出；不能靠拒收申诉优化指标 |

访谈应要求近期真实案例与可脱敏材料，而非仅询问“是否需要信用分”：

1. **用工方老板：**最近一次选供应商如何核实能力？哪些履约证据会改变选标？是否愿意在明确范围内展示自己的确认和付款记录？
2. **人事经理：**哪些确认与异常由其推动、财务或老板负责？愿意为补证投入多少工作？如何防止将组织拖款归责给经办人？
3. **供应商：**最近一次被拖欠/需求变更的证据是什么？是否愿意展示自己的履约和返费付款记录，以换取对等的信息透明？
4. **独立经纪人：**最近一次撞单、政策变更或返费争议如何解决？最需要看合作供应商的哪些记录？哪些个人数据不愿跨公司分享？
5. **平台审核：**谁能核实线下付款和履约、核验成本多少？双方说法冲突时由谁复核、如何处理利益冲突、如何告知并执行更正？
6. **未来机构访谈（非接入承诺）：**机构需要哪些合同、确权、履约和回款证据？平台现有凭证哪些不足？哪些资料必须由交易方或银行独立提供？由机构反馈反推资料包，而非自行定义融资可用性。

验证产物为脱敏案例、字段/证据缺口、可见性接受范围、核验成本及需调整的规则；未完成前不把信用档案对获客、降低坏账或融资定价的帮助表述为已证实效果。
