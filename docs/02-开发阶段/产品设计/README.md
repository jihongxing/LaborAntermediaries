## 二、业务域地图

### 角色视角补充入口

员工推荐已正式纳入 PRD FR-24～25，详细规则见[员工推荐与按工时持续奖励需求](04-治理信用与增长/员工推荐与按工时持续奖励需求-v0.1.md)，员工操作见下方角色稿；需求追踪 G-10、业务包 BP-07～12 相关切片同步承接。该专项覆盖一次性、持续工时与混合奖励，不替代经纪返费、人事经理企业引荐、客户收费或已批准组织分账规则。

[角色与流程](06-角色与流程/README.md)按统一六项模板梳理角色边界、业务目标、功能清单、主流程与异常流程、协作关系、状态与凭证。首份为[员工端角色功能与全流程](06-角色与流程/员工端角色功能与全流程-v0.1.md)，后续角色使用[通用模板](06-角色与流程/角色流程通用模板-v0.1.md)扩展。角色文档是跨业务域视图，不代替下方专项规则，也不表示功能已开发或规则已批准。

[劳务供应商角色功能与全流程](06-角色与流程/劳务供应商角色功能与全流程-v0.1.md)按现有文档整理组织侧完整旅程，覆盖准入、应标、供给、现场履约、分类应收应付、对账与争议；主供应商和协同方分开描述，实际权限落到组织内授权岗位，不新增 PRD 规则。

[用工方角色功能与全流程](06-角色与流程/用工方角色功能与全流程-v0.1.md)按相同六项模板整理准入、有效需求、评审选标、双方成交、现场协作、业务量确认、对账付款与争议；组织分享和个人贡献／引荐分开，排班权限及付款审批等来源待决事项保留，不新增 PRD 规则。

[平台方角色功能与全流程](06-角色与流程/平台方角色功能与全流程-v0.1.md)按相同六项模板整理分岗授权、主体与需求审核、交易监督、投诉举证与独立复核、授权执行和纠错、收费支付协同及平台自身监督；不将平台方视为全能管理员，保留 D-17～19 和各专项启用门禁，不新增 PRD 规则。

## 四、文档职责与冲突处理

文档“主要业务域”只是导航标签；以下职责决定内容如何使用：

| 文档职责 | 典型文件 | 解释 |
| --- | --- | --- |
| 产品总纲 | PRD | 描述平台范围、全局用户与功能需求；具体收费等专项仍由相应唯一维护入口维护。 |
| 背景与需求推导 | 需求梳理、战略与履约流程补充 | 解释为什么需要某项能力、源材料如何进入需求；历史推导稿不自动覆盖 PRD 或批准规则。 |
| 业务规则/专项方案 | 各域专项文档 | 提供该主题的流程、角色、数据和异常细化；须遵守文档自身的草案、建议、待决状态。 |
| 跨域流程/视图 | 泳道图、排班至资金审批流程 | 说明域间交接或参与方视角；不取代每个业务域中的规则主来源。 |
| 商业规则维护入口 | 商业模式与收费标准、独立经营制度 | 具体费率、收款对象或奖励资格只能按指定来源及已批准状态使用，不从其他示例推导。 |
| 推进与验收控制 | 业务包清单、需求追踪与交接门禁 | 把范围、待决事项和验收证据连接起来；做任务拆分不是业务规则批准。 |
| 未来战略资源 | 战略路线、未来支付与保理、相关数据准备 | 用于未来方案研究；不代表当前范围、产品资格、接口已接通或真实启用。 |

若文档之间表述冲突，先记录**冲突术语/规则、双方来源、影响业务域、决策责任人和阻断范围**；不得默默选择较新文件、示例值或代码现状作为批准规则。规则批准、开发完成、联调验证和真实启用是四个独立状态。
