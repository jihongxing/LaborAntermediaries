# 人事经理收益与跨企业推荐增长需求 v0.1

- 日期：2026-10-23
- 状态：需求范围已由用户明确提出；本文为需求提炼与产品评审稿，不代表支付安排、合同、参数或真实上线已获批准。
- 制度依据：[人事经理贡献奖励与跨企业渠道推荐奖励管理制度 V1.0](../../00-项目管理/经营制度/人事经理贡献奖励与跨企业渠道推荐奖励管理制度-v1.0.md)；本稿不修改制度，也不独立作出法律结论。
- 追踪：主 [PRD](PRD-v0.1.md) FR-20～FR-23、故事 161～180；[交接门禁](需求追踪与交接门禁-v0.1.md) G-09。

## 1. 问题与目标

已合作的人事经理既是客户组织内的平台运营参与者，也可能实际引荐其他企业。平台需要明确回答三个产品问题：

1. **怎么获得收入**：区分贡献记录、雇主自行发放的内部奖励、独立服务收入与推荐收入，明确谁有资格、谁付款、需要什么证据、何时才形成可结算金额。
2. **怎么帮助平台推广**：允许已合作的人事经理在身份和联系授权边界内登记跨企业推荐，留下实际引荐证据，由平台接续商务跟进，不靠私下口头承诺分配归属。
3. **推广如何再产生收入**：推荐企业产生真实履约和合格服务收入实收后，在已批准的主体、合同、期限和费率范围内核算、审核、支付及处理冲回。

这是明确的业务需求，不应只作为制度附件或风控禁令存放。与此同时，“要支持获得收入”不能推导为“所有在职人事经理都能收平台佣金”。产品应能展示不具备资格、需补材料、被拒绝及仅可记录贡献的真实结果，不保证每个参与者都有平台付款路径。

## 2. 范围与收益路径

### 2.1 对象、付款方与产品结果

| 场景 | 制度中的候选路径 | 产品必须支持的结果 | 不能推导的结论 |
| --- | --- | --- | --- |
| 用工企业在职人事经理协助本企业上线、运营 | 平台记录贡献；雇主可依自身制度独立决定内部奖励 | 客户授权、贡献证据、运营报告；有权人员按范围查看或导出供雇主参考 | 贡献分不是个人现金余额；平台不指定奖励员工、不代发、不保证雇主奖励 |
| 劳务供应商在职员工协同履约和数据质量 | 平台记录贡献；供应商自行决定内部激励 | 与用工方员工同样执行身份、利益冲突、证据及直接付款阻断 | 不能因影响报价、中标或结算向其个人付款 |
| 真正独立的外部运营服务提供者交付服务 | 经核实不存在受限关系后，评估独立合同、成果验收及服务费结算 | 服务范围、合理计价、成果与验收、主体及税务资料审核 | 登记为“顾问”或开票不自动证明独立、合法或适格 |
| 已合作的人事经理引荐另一家企业 | 先登记真实引荐；审查雇佣/代理关系、目标企业职权、必要授权及专项法律意见 | 可登记线索；个人佣金资格单独审核；未完成审核不得承诺现金或进入支付 | 推荐外部企业、雇主同意或跨企业关系均不自动消除受限身份 |
| 独立自然人或独立企业推荐新企业 | 经准入、合同、真实引荐及实收收入审核后，按批准规则核算 | 推荐关系、归属、服务收入映射、奖励账单及本人/企业账户付款记录 | 推荐名单、注册、签约或未实收交易额不是可支付收益 |
| 平台员工 | 另行适用内部绩效制度 | 识别身份并导向内部制度 | 不混入两类外部激励预算 |

不得通过切换账号、挂靠企业、亲属账户或更换合同名称把受限人员变成独立服务商。独立服务与推荐是不同服务成果；确有不同服务时分别核验合同、成果、计价并防止重复计奖。

### 2.2 产品范围与排除项

- 范围：身份和资格、贡献及服务成果、推荐登记与归属、商务转化状态、实收收入关联、奖励核算、审批、结算记录、异常、查询与审计。
- 不在本稿内新增：客户收费项目、线索解锁联系人奖励、工人就业推荐返费、平台员工绩效、保理收益、客户资金托管或平台钱包。
- “再产生收入”指推荐客户后续真实业务在合同奖励期内产生的合格收入；**本稿不设计多级分销、发展推荐人奖励或下级团队流水抽成**。被推荐企业的联系人以后推荐新企业时，必须作为新的直接推荐人独立准入、登记和签约；原推荐人不自动分享该次推荐收益。
- 本次只提炼需求和验收，不实施业务代码，不替代后续法律、财税、客户合规与产品评审。

## 3. 角色、权限与多端入口

| 角色 | 可操作事项 | 权限边界 |
| --- | --- | --- |
| 贡献人/推荐人 | 本人身份申报、贡献提交、推荐登记、补证、查看本人资格/归属/核算/结算状态及提出异议 | 不能自行审批资格或金额，不能查询目标企业报价、工人工资、其他推荐人或全部平台收入 |
| 客户/供应商有权人员 | 确认本组织授权与成果、查看必要贡献报告、提供适用政策 | 不能代替平台法务批准个人付款；内部员工奖金由其自行决定 |
| 销售/客户成功 | 邀请参与、协助提交、接续商务跟进、核验引荐事实 | 不能承诺佣金、擅改归属或批准本人经办款项 |
| 法务/合规 | 审查身份、利益冲突、许可和例外，记录意见及适用范围 | 资格通过不是金额批准，必要法律意见缺失不得绕过 |
| 财务/税务 | 确认收入及退款、预算、票据税务、账户、结算与回执 | 不能以实收证明替代收款资格，也不能挪用客户资金 |
| 管理层授权人 | 批准规则版本、试点范围、预算及重大例外 | 不得覆盖法务/财务硬性阻断 |

推荐人可以与组织成员使用同一实名账号，但“组织操作权限”与“个人推荐资格”分别授予、撤销和审计；不因能推荐而取得目标企业组织后台权限。平台 Web 提供审核、CRM 跟进与结算管理；已合作人事经理所在企业 Web 及独立 App 按角色提供本人入口。小程序分享/登记作为候选触达入口，具体端分工待评审，不预设必须新增独立 App。共享资格和归属结果，任一端均不得绕过服务端限制。

## 4. 核心流程

### 4.1 贡献与独立服务

客户授权采用平台 → 登记贡献人及雇佣/代理关系 → 提交上线、培训、数据质量或运营改善证据 → 核验成果、去重及确认 → 形成贡献报告。

贡献报告可供客户自行评价；**流程在此不自动进入个人付款**。如属于真正独立的运营服务，必须另经资格、合同、定价与验收审核，且付款前重新核验受限身份、预算、税务和账户。贡献评分权重、核算方式及例外条件未批准前，不以积分兑换或“预计到账”变相承诺现金。

### 4.2 利用已有合作关系开展推荐

1. 客户成功向已合作人事经理解释参与资格、无现金保证和信息使用范围；禁止以决定本企业采购作为奖励条件。
2. 推荐人申报本人、雇主/代理关系、目标企业关联及可能的采购/评审影响力。受限人员未完成审查时只能登记线索。
3. 在获得目标客户联系许可的必要范围内，登记企业、实际引荐方式、时间及证据。可评审使用邀请链接/二维码辅助登记，但链接点击或邀请码不等于有效推荐证据。
4. 平台检查已有客户、已有实质商务接洽、重复主体和集团关联；归属由首个有效登记且有实际引荐证据确定，不简单按点击时间占坑。
5. 多人共同贡献的分配在合同签署前书面批准；归属争议冻结争议部分，不静默覆盖原记录，也不冻结无关正常业务。
6. 销售接续联系、签约和履约跟进；推荐人仅查看经授权的摘要和本人奖励相关进度，不因此获得客户内部资料。

### 4.3 从推广转化到可结算收入

| 推荐里程碑 | 产品可显示状态 | 资金含义 |
| --- | --- | --- |
| R0 登记 | 已提交/待核验 | 无应付奖励 |
| R1 有效引荐 | 引荐事实及归属已核验；收款资格另列 | 无应付奖励，不能以归属通过替代资格通过 |
| R2 企业签约 | 合同已关联 | 不因签约自动产生可支付金额 |
| R3 有效履约 | 可核验订单、人天与确认记录已关联 | 可进入候选核算；服务费未实收时不得付款 |
| R4 合格收入实收 | 财务确认收入来源、金额、税费及排除项 | 全部资格、合同、规则和审批满足时形成可结算奖励 |
| R5 持续合作 | 奖励期内后续合格实收继续核算 | 受期限及预算限制，到期不自动续期 |

资格状态、推荐里程碑、核算状态及付款结果是四条独立维度。退款或争议不删除里程碑历史，也不能将历史已付款直接改成未付款。

## 5. 功能需求与验收

| 编号 | 需求及制度来源 | 最低可观察验收 |
| --- | --- | --- |
| FR-20 收益身份与资格 | 制度第 2、3、7、11、15 节；分别管理雇佣/代理、目标企业职权、资格结论、适用服务/客户/期限、证据与复核 | 在职客户人事经理即使雇主已书面同意，缺少具体法律审查和批准仍不能个人付款；资格变化付款前重新审查，保留原结论 |
| FR-21 贡献与独立服务成果 | 制度第 5～9 节；贡献事件、授权、证据、核验、重复检查及报告；独立服务另关联合同、成果和验收 | 同一贡献重复提交不重复记分；贡献通过不生成现金债权；独立服务缺合同/验收或存在受限身份时不能结算 |
| FR-22 跨企业推荐与转化 | 制度第 10～13 节；邀请、联系许可、真实引荐、客户查重、归属/共同贡献、CRM 跟进、R0～R5及异议 | 已合作人事经理可提交合规范围内的推荐，但不会自动取得佣金资格；已有客户、公开名单或无授权联系不能成为合格推荐；并发有效登记不得形成冲突归属 |
| FR-23 外部奖励核算与结算 | 制度第 4、14～19 节；合格实收收入、版本化费率和期限、去重、合计预算、合同财税、审批、本人账户及结果核对 | 未实收不付款；两类激励并发核算不突破批准预算；退款按合同冲回、重复回执不重复支付；支付未知保持待核对，不显示已到账 |

### 5.1 金额与预算口径

- 计算依据为合格平台服务收入，需关联客户、订单/有效人天、财务实收及归属期间；剔除税额（如适用）、退款、代收代付、工资、劳务结算款、保证金、融资款及其他非平台收入。
- 现行收费存在用工方分账时，先由财务确认平台实际收入与企业分账/第三方应付款，不以收到银行流水总额直接计算激励；原[收费及分账规则](商业模式与收费标准-v0.1.md)不变。
- 推荐奖励候选公式为“奖励期内合格服务收入 × 已批准奖励率”；独立运营服务按实际批准合同计价。费率、固定单价、封顶、分配比例、舍入及税前税后口径均需批准并可追溯。
- 同一成果/引荐/人天不得由两预算池重复计奖；不同服务必须有独立义务和成果。去重及预算校验覆盖待付已占用额度与已付金额，驳回、撤销、冲回的释放有记录，不能并发透支。
- 规则需记录版本、适用对象、有效时间和审批；历史核算引用原版本，调整生成有依据的新记录，不覆盖历史。
- 49% 是两类外部激励合计预算上限情景，1 元是收入示例，180 天和 12 个月是候选期限；未批准参数不得自动启用。

### 5.2 结算与异常

建议区分“候选核算、待补证、待审批、可结算、冻结/驳回、付款处理中、结果未知、已付、冲回/追索”等状态，最终状态迁移待评审。推荐人看到的待核算、税前应付、扣缴税额、实付及冲回应分别标示，不展示为可自由提现的钱包余额。

付款前同时核验：成果/引荐、身份和利益冲突、实收、合同与验收、规则和预算、税务凭证、合同主体与收款账户、审批。付款只能从平台合法自有可用资金支付；通过有权银行/支付通道执行或记录经核验的线下付款，不另建客户资金池。失败可按规则重试，未知先查询核对，同一义务不得重复支付。

退款、无效履约、推荐造假或资格不符时，暂停/调整相关部分，已付款追回或后续抵扣须有合同和适用法律依据及审批。申诉沿用平台投诉与独立复核能力，相关经办人不得独立终审；推荐归属及奖励异议不自动限制工人工资或客户正常履约。

## 6. 数据与信息边界

在制度附件 A 的最小字段上形成以下业务对象，不预设表结构和接口：

- 参与主体与资格档案：实名主体、组织/雇佣/代理关系、目标企业职权、必要授权、利益冲突、法律意见引用、适用范围与复核记录。
- 贡献/服务成果：类型、客户、项目或运营事项、发生时间、指标证据、核验、合同及验收、规则版本。
- 推荐关系：推荐人与目标企业、许可和引荐证据、登记时间、已有 CRM 检查、共同贡献、归属及争议、转化事件。
- 核算与结算：实收收入来源、有效量、排除项、规则快照、预算占用、税费、审批、付款主体、账户一致性、回执及调整。

采用最小必要授权；对外只展示本人相关且经批准的收入核算摘要，不暴露企业完整流水、平台利润、工资或他人联系方式。证件、账户和法律意见分权访问；保存期限、撤回授权后的处理及法定义务留存待法务确认，不能承诺一键删除全部历史审计。

## 7. 用户故事索引与验证方式

主 PRD 故事 161～165 对应 FR-20，166～170 对应 FR-21，171～175 对应 FR-22，176～180 对应 FR-23。角色包括已合作的人事经理、目标企业联系人、独立服务商、渠道方、客户成功、法务、财务及授权审批人。

优先以“参与人提交 → 平台核验 → 财务核算 → 审批与结果查询”的业务边界验证，不依赖具体数据库表或内部方法。研发拆解时复用组织授权、证据附件、规则版本、审计、CRM、收入对账与支付结果能力；是否已有可用实现须另行代码核查，本稿不宣称已实现。

至少覆盖：受限身份拒付、雇主授权不足、身份变更复审、贡献无现金权利、已有客户与无授权推荐、并发归属、共同贡献分配、签约无实收、部分回款/退款、同一收入重复事件、合计预算并发、参数未批、付款未知及重复回执、越权导出、利益相关人回避、到期不续期和无上级抽成。

## 8. 待决策与上线门禁

| 决策项 | 责任方 | 未决时阻断 |
| --- | --- | --- |
| 不同雇佣/代理/目标企业职权下的收款资格、必要授权与具体法律意见；何时复审 | 法务/合规、客户有权人员 | 相应个人奖励承诺、应付确认及付款 |
| 独立服务与推荐的合同、真实成果、许可边界及验收 | 法务、业务 | 对应有偿服务启用 |
| 合格收入与用工方分账、费率/封顶/期限/留存、去重范围、舍入及预算 | 财务、业务、管理层授权人 | 正式核算；只可使用明确标为无支付效力的虚构样例 |
| CRM 实质接洽、回溯、集团关系、共同贡献、归属争议程序 | 销售、产品、合规 | 自动确认推荐归属与对应奖励 |
