## 一、执行摘要

**研究判断：应围绕“真实需求如何转化为可履约、可对账、可复购的交易”验证机会，而不是延续“多少家中介公司愿意购买管理软件”的测算。**

1. **供给主体广泛，但不能直接等于目标市场。** 人社部门披露，截至 2025 年底全国共有各类人力资源服务机构 8.1 万家；这一总量包含不同业务类型，不代表 8.1 万家均符合本项目的供应商准入、区域和交付要求。[S1]
2. **竞争不只来自软件。** 官方产品资料显示，上海外服提供派遣、招聘及灵活用工、业务外包等服务；Workday VNDLY 则提供外部用工的需求、供应商协同、工时及账单等管理能力。[S3–S4] 据此判断，平台既面对已有服务关系，也面对企业内部流程和成熟管理工具，不能以“没有完全同名产品”推断没有竞争。
3. **市场空间应按交易和履约测量。** 当前内部商业模式包含履约管理费与线索解锁费，但实际收费启用、合同和结算仍有门禁；不能把需求人数、工资流水、供应商收入或管理费总额直接当成平台收入。[I2]
4. **切入建议是区域密度，不是全国注册量。** 先围绕真实用工方、具体岗位与可核验供应商建立完整链路，再验证响应质量、履约、对账、复购和单位经济性。此为研究建议，不另行批准区域、预算或试点。
5. **金融不是当前市场规模的补数。** 交易—数据—金融是既有获批方向，但未来支付与保理仍须专项评审；不能用融资规模或金融机构数量弥补尚未验证的交易价值。[I3]

## 二、研究对象与统计口径

### 2.1 不是哪几类市场

| 容易混淆的市场 | 与本项目的关系 |
|---|---|
| 劳务公司内部管理 SaaS | 可提供组织内部工具，但本项目核心是跨组织交易与履约协作，不以软件席位或年费客户数作为唯一市场单位 |
| 面向个人的招聘信息平台 | 可覆盖触达和报名，本项目还须处理组织准入、应标选标、供给、履约确认及对账 |
| 劳务承接与外包交付 | 供应商承担相应交付责任；平台不因协同记录而默认成为外包承接方或工资债务人 |
| 灵活用工结算或资金产品 | 不能仅因具有结算界面就视为业务可比；须核对合同主体、劳动关系、支付及风险承担 |
| 金融或保理平台 | 属于未来可选合作方向，不作为当前已获准经营、已形成收入的市场 |

以上定位以当前 PRD、收费与战略材料为内部依据，不是对任何具体企业法律性质的认定。[I1–I3]

### 2.2 市场中的关键角色

- **需求方与选择方**：具有真实需求和组织授权的用工方；需区分组织决策人、采购、人事经办与履约确认人员。
- **交易和交付方**：符合当前准入要求的劳务公司；注册、意愿、应标、承诺和实际交付是不同状态。
- **平台费用承担方**：按当前商业模式分别识别履约管理费与线索解锁费付款方，不将用工方收益、组织采购和个人激励混为一谈。[I2]
- **资源与履约参与者**：经纪人、招聘渠道、员工及驻场人员；他们影响交易结果，但不因此都成为独立平台付费客户。
- **监督与执行方**：平台运营和审核人员，以及未来专项获准接入的支付或金融机构；各自职责须通过权限与合同明确。

**研究判断：真正需要验证的是“需求方愿不愿改变协作方式、供应商愿不愿带着真实履约和付费承诺参与”，而非只有账号注册意愿。**

## 三、行业背景：可核实的规模与不能外推的结论

| 已核实事实 | 统计时点及来源 | 可以说明 | 不能推出 |
|---|---|---|---|
| 全国各类人力资源服务机构 8.1 万家，从业人员 111.5 万人 | 截至 2025 年底；2026-08-14 人社部门公开材料 [S1] | 行业主体及专业服务供给的宏观背景 | 本项目合格供应商数、有效合作数、可交付人数 |
| 各类机构建立 6 万多个招聘场所、2 万多个网上服务平台；年均服务 3 亿多人次劳动者 | 同一公开材料 [S1] | 已有大量就业对接渠道 | 独立平台公司数、去重工人数、平台可获取用户或年度可收费人天 |
| 福田区截至 2025-12-31 有依法审批劳务派遣机构 330 家、备案分支机构 52 家 | 2026-08-06 地方公示正文 [S2] | 主体与分支应区分，地方公示可作为名单核验起点 | 全国总量、全部外包供应商总量，或本项目已连接 382 家独立合格供应商 |

**本轮限制**：未取得足以统一口径的全国“符合本项目准入、愿意合作且具备指定区域交付能力”的供应商数量，也未取得可直接折算本项目收入的全国有效履约人天。国家统计局站内农民工报告检索未获得可用结果正文，因此不填入未经核验的全国劳动者数量。

现有[全国劳务供应商市场估算与用工方价值论证](全国劳务供应商市场估算与用工方价值论证-v0.1.md)中的内部数量情景仍是待验证假设，不因本报告新增而变成官方统计。本报告不重新给出一个看似精确、但无法复核的全国市场金额。

**2026-10-24 SAM 专项补充**：上述专项文档第 3.4–3.6 节新增全国供应侧条件情景、年度人天与金额模型、区域去重及证据补齐路径。其数量结果来自人为筛选参数，不能与本节官方行业总量等同；全国有效派遣许可的独立主体总数及本平台实际可服务供应商总数仍未核实。

## 四、需求侧：用工方为什么可能采用，也为什么可能拒绝

以下均为**待访谈验证的假设**，不是已完成客户调研的发现：

| 场景与角色 | 价值假设 | 必须追问的反证 |
|---|---|---|
| 需求集中、到岗时间明确的项目负责人 | 通过可比较响应增加合适的供给备选，减少反复询问进度 | 现有供应商是否已足够；新增供应商是否真正减少缺口 |
| 采购或经营负责人 | 能比较合作条件、交付事实与综合成本 | 平台费是否经供应商报价转嫁；采用后的总成本是否反而上升 |
| 人事与驻场经办 | 减少重复登记、催确认、补表与账单解释 | 是否只是多维护一个系统；与现有流程如何衔接 |
| 财务与结算人员 | 工时确认、账单差异、付款与回款证据关联 | 谁确认原始数据；争议未解决时如何处理；凭证是否能支持内部审计 |
| 已有稳定合作网络的用工方 | 通过备用供给、跨项目协作或对账降低风险 | 是否根本不愿公开需求或改变供应商关系 |

### 需求访谈不能只问“愿不愿意用”

应围绕最近一笔真实业务询问并取得必要授权的证据：

1. 谁提出需求、批准供应商、确认工时及处理账款？各自能否授权系统参与？
2. 最近一次未按期供给、补缺、对账差异是什么？实际耗费多少人工、时间和费用？
3. 从发布需求到确认合作有哪些不可省略的采购或合规环节？
4. 若不使用平台，现有方案是什么、费用是多少、为什么仍然可接受？
5. 是否愿意提供一笔真实需求贯通应标、履约和结算？哪些环节明确拒绝在线处理？

不能以人事经理个人对奖励的兴趣替代组织采购意愿，也不能把演示满意度视为真实采用或持续复购。

## 五、供给侧：供应商为什么可能参与

**待验证假设**：供应商愿意参与的前提，是获得适配、真实、有授权的需求，并且预期交易价值能覆盖报价、招聘、履约、平台服务及资金占用等成本，而不仅是“多一个曝光渠道”。

| 需要核实 | 具体问题 |
|---|---|
| 准入与适用业务 | 主体、业务范围、所需许可或备案与实际项目是否匹配；不能用一种资格覆盖所有业务 |
| 真实可供给 | 在什么区域、岗位、时间和条件下能新增供给；历史最大人数不等于当前可供给 |
| 经济性 | 项目业务报价、平台费用、招聘与协同成本、回款周期是否可承受 |
| 信息与信任 | 联系人是否授权、需求是否仍有效、重复或无效线索如何处理 |
| 采用阻力 | 是否担心客户或渠道流失、敏感信息暴露、重复录入以及平台偏袒需求方 |
| 交付证据 | 是否愿意按约定记录承诺、到岗、工时和差异；拒绝提交的真实原因是什么 |

多家供应商可能共享渠道或人员，不能将其自报人数直接相加。协同供给须保留主责、合同与必要批准，不因为市场调研提出协作机会就默认开放转包。

## 六、竞争与替代方案

### 6.1 按客户任务比较，而不是只按产品名称比较

| 类别 | 核实或分析依据 | 本项目需要验证的差异 | 不能作出的结论 |
|---|---|---|---|
| 现有供应商关系、微信群与表格 | 作为访谈待核实的替代方案，不宣称其全国普及率 | 是否确实减少找供应商、协调、核验和对账成本 | “所有企业都落后”“上线自然有客户” |
| 国内综合人力资源服务商 | 上海外服官网列示人事管理、人才派遣、招聘及灵活用工和业务外包 [S3] | 本项目是否能让用工方比较和协同多个合格供给方，同时不承接交付 | 上海外服一定与本项目同模式、不能合作或服务价格更高 |
| 外部用工与供应商管理系统 | Workday VNDLY 官网列示审批流程、供应商门户、工时、账单与全生命周期能力 [S4] | 除了管理工具，本项目能否带来真实适配供给和交易密度 | 企业管理系统等同开放交易市场，或其海外能力已适配中国劳务业务 |
| 招聘与信息触达平台 | 本轮未完成具体国内产品的完整一手核验 | 从触达到实际履约、结算的增量价值是什么 | 没有核验就断言对方不做履约、不合规或市场空白 |
| 支付、提前付款与保理协作产品 | 参见既有欧美对标研究；本轮 C2FO 页面访问受限 [I5] | 未来是否能提供合法授权的可信业务证据 | 直接复制融资模式、沿用旧研究数字或认定当前有金融收入 |

以上是竞争结构分析，不是完整竞品排名。本轮没有充分资料判断国内交易平台的份额、费率、获客成本、盈利或客户满意度，不给“本项目领先”评分。

### 6.2 潜在差异化不是功能清单

**研究判断**：可能形成差异的是同一区域和业务场景中的有效网络密度，以及需求—应标—履约—结算证据的连续性。它需要同时证明：

- 用工方能获得真实可比较的适配响应，而不是更多无效联系。
- 供应商愿意重复参与，并在计入平台成本后仍能获得可持续回报。
- 各方愿意把履约确认和账款差异留在平台内处理，而不只在线交换联系方式。
- 平台保持中立、处理成本可控，且不依赖承担未定价的供给或资金风险维持体验。

## 七、市场空间与收入：从年费客户数改为交易漏斗

### 7.1 三层口径

| 层次 | 本项目的合理定义 | 当前状态 |
|---|---|---|
| 总体机会（TAM） | 与目标业务相关、潜在适用交易及履约协作的需求和履约规模 | 缺乏可核实的全国同口径人天及渗透数据，不给金额结论 |
| 可服务市场（SAM） | 指定区域、行业、岗位、准入与合作条件下可合法服务的真实需求 | 需区域名单与用工方访谈去重，尚未量化 |
| 可获取市场（SOM） | 在给定周期、团队、预算与供给约束下能真实完成并形成合法收费的规模 | 需试点响应、交付、收费及成本证据，不能先填市场份额 |

机构数量可用于获取名单线索，但不能用“8.1 万家 × 软件年费”计算本平台市场；劳动者人数和“服务人次”也不能直接乘人天费率。

### 7.2 建议建立的交易漏斗

```text
区域内可核实的目标组织
    → 有授权并愿意进入流程的用工方
    → 通过门禁的真实有效需求
    → 收到适配且可比较的有效应标
    → 明确合作与供给承诺
    → 核验实际到岗和有效履约
    → 确认账单并完成相应对账
    → 满足启用条件的收费、实收及复购
```

每层同时记录数量、流失原因、耗时和运营成本。报价人数、中标配额、实际到岗人数和有效履约人天不可互相替代。

### 7.3 不复制费率的测算模板

```text
项目履约管理费总额 = Σ（按适用合同确认的有效履约人天 × 适用费率）
线索费计费总额 = Σ（满足授权、有效性与启用条件的实际解锁事件 × 适用价格）
```

适用费率、组织分配、线索解锁价格、退款及真实收费门禁，均从[商业模式与收费标准](../03-账单与资金/商业模式与收费标准-v0.1.md)读取；本报告不另立价格或改变暂缓状态。[I2]

**研究判断：至少分开建立以下账本口径，不能用一条“流水”代表全部结果：**

- 业务合作规模、工资或劳务结算金额；
- 平台相关计费总额、待收、实收、退款及各类应付；
- 平台现金留存与会计收入；
- 真实采购、税费、获客、运营、核验、争议和技术成本；
- 单需求、单项目、单有效履约人天的贡献及回款周期。

可在每个单位下计算“按统一财务口径归属的平台收益减去相应可归属成本”的管理贡献指标，但它不是未经财务确认即可对外宣称的会计利润。没有真实采用、实收和成本样本前，不提供精确收入预测或估值。

## 八、区域冷启动与网络效应验证

以下是**经营验证建议**，不是固定实施范围或预算批准，也不删减 PRD 中的独立 App、履约或资金能力：

1. **选择可验证场景**：根据真实需求密度、供应商覆盖、确认权限和回款透明度选择区域与岗位，不先以全国覆盖为目标。
2. **由有效需求牵引供给**：拿到组织授权的真实需求，再寻找符合条件且明确愿意响应的供应商；不先以购买大量联系人建库替代需求。
3. **人工协同可以验证，但不能伪装产品完成**：记录每次人工审核、催办、纠错和对账耗时，识别哪些能力可标准化、哪些成本会随交易线性增长。
4. **完整记录失败**：无响应、弃标、到岗不足、工时争议、未回款和退出都进入样本，不只展示成功案例。
5. **用复购与密度决定扩展**：下一笔需求是否再次使用、同场景可比较响应是否增加、单位运营成本是否改善，再决定区域复制。

建议的运营证据表：

| 观察方向 | 建议记录 | 失败信号 |
|---|---|---|
| 需求真实性 | 授权、核验日期、需求条件版本、撤销原因 | 联系人无权确认或需求早已失效 |
| 有效响应 | 首个合格响应耗时、合格响应数、拒绝原因 | 注册多但无适配供给，或依赖同一渠道重复报价 |
| 履约质量 | 承诺与到岗差异、确认工时、补缺和争议 | 交易在中标后离开平台，证据持续缺失 |
| 流程价值 | 经办工时、重复录入、对账耗时及可比基线 | 客户只是多填一套表，人工协同成本持续上升 |
| 经济性 | 实收、退款、回款、采购与可归属成本 | 只能依靠补贴或平台隐性兜底维持交易 |
| 复购与中立性 | 同场景再次使用、退出原因、申诉复核 | 双方普遍绕行或对公平处理缺乏信任 |

阈值、观察周期、访谈和试点预算须在实际计划中确认；本报告不任意将样本数或转化率写成已批准 KPI。

## 九、合规与责任：必须核实，不能靠定位自我豁免

《人力资源服务机构管理规定》公开正文第五条区分职业中介及网络招聘有关许可要求，第九条规定相应人力资源服务业务的备案；地方公示也明确区分机构许可与分支备案。[S2、S5]

据此提出以下**待专业审阅事项**，不构成法律意见或对本平台已具备资质的认定：

- 按实际业务行为核对平台及供应商需要的许可、备案和电信等要求，不能仅声明“信息撮合”就认为没有监管义务。
- 区分外包、派遣、职业中介等活动及各方合同和用工责任，不用一种主体证明或产品名称替代判断。
- 联系人线索、员工资料、考勤与信用信息需要对应授权、必要范围、访问控制、留存和纠错机制。
- 组织采购、组织分享、个人贡献和推荐奖励分别审查资格、合同、真实服务、财税及付款责任，不能以营销需要替代审批。
- 平台不得因收取费用偏袒付费方；信用与禁入需要证据、复核和申诉，不将投诉自动转成惩戒结论。
- 支付归集、融资、担保及资金托管等后续能力须另审，本报告不授予启用许可。

本轮核验的是政府页面公开正文，未完成全部法律法规、地方政策及现行适用关系的穷尽检索；具体上线前应结合业务所在地和实际行为再次审阅。

## 十、结论与下一步

**可支持的结论**：项目应以交易与履约网络为研究对象，已有行业主体和成熟企业产品说明相关服务与流程确实存在，但不足以证明本平台已获得需求、市场份额、收费能力或竞争优势。[S1、S3–S4]

**下一步最有价值的补证**：

1. 用工方真实业务访谈：同时覆盖决策、经办、履约确认和财务，纳入拒绝采用样本。
2. 区域供应商核验：去重主体与分支，核对业务资格、岗位区域能力、参与意愿和实际交付证据。
3. 国内同类平台一手比较：补充正式产品说明、服务协议、费用与责任条款，不以搜索摘要或销售口号定性。
4. 完整交易样本：从有效需求到履约、对账与回款记录事实，单列人工介入和失败成本。
5. 经济与责任审阅：在既有收费规则下验证真实收益和成本，并完成合同、财税与启用门禁。

若无法获得授权需求、可核验履约或可持续经济性，应调整场景、流程或商业假设，而不是通过扩大全国人口数字论证项目必然成功。
