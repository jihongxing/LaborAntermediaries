## 1. 需求到验收的追踪矩阵

下表中的“交接前确认”是**需要明确的规则或前置条件**，不是把整项功能从已确认的产品范围移出。每项由产品经理提供业务判定，项目经理跟踪评审与依赖，技术负责人确认接口/数据方案，测试负责人确认可观察的结果。

## 2. 优先决策清单与阻断范围

| 决策包 | 应作的产品/项目决策 | 未决时可做 / 不可做 |
| --- | --- | --- |
| G-01 组织与需求准入 | 谁审核、所需材料、角色授权、需求可见性、补正与版本再审。 | 可梳理状态和权限原型；**不可**将建议字段门槛写死并让未审需求进入真实应标。 |
| G-02 应标与中标 | 配额/承诺确认、工价、时限、异常回退及中标快照。 | 可设计版本与测试样例；**不可**以历史默认规则锁定合同或自动建项目。 |
| G-03 履约与有效计量 | 供给关系、现场/用工方复核权限、工时差异、有效人天及返费口径。 | 可保留数据来源并编写异常用例；**不可**用单一打卡或未确认人天自动产生无争议账单。 |
| G-04 收费与合同 | 与[收费唯一文档](../03-账单与资金/商业模式与收费标准-v0.1.md)逐项核对收费对象、计费量、合同、收取时点和结算方式。 | 可实现已批准规则的配置与演算；**不可**因费率获批就开启实收或收取未来保理规划费。 |
| G-05 资金和对外联调 | 机构能力、责任主体、账户/资金权属、授权、回执与异常恢复。 | 可隔离环境设计适配器与模拟场景；**不可**在缺乏机构/合同/合规结论时启用真实资金通道。 |
| G-06 多端与上线 | 端间交接、关键权限、真实场景验收、严重风险修复和运维责任。 | 可依业务依赖并行设计各端；**不可**因某端页面未完成而单方面删去独立 App 或完整履约/资金范围。 |
| G-07 三方交易信用与授权 | D-16 的主体归属、证据来源、展示矩阵、申诉纠错、样本口径、留存及未来资料包授权。 | 可用虚构案例设计事实与纠错链；**不可**把单方投诉/争议/未到期/未知结果判为已证实失信，不可未授权向机构共享，不可将档案当作保理已上线。 |
| G-08 平台审核与中立监督 | D-17～19 的岗位/回避、举证复核、措施、执行授权、时钟、结案/重开、规则与平台自身投诉。 | 可按专项和虚构案例设计任务/案件与跨端入口；**不可**让原处理人自审申诉、以未回应默认同意、代确认/代资金审批、无回执结案或让相关经办终审自身投诉。 |
| G-09 外部贡献与推荐收益路径 | [收益与推荐专项](../04-治理信用与增长/人事经理收益与跨企业推荐增长需求-v0.1.md)、[奖励制度 V1.0](../../../00-项目管理/经营制度/人事经理贡献奖励与跨企业渠道推荐奖励管理制度-v1.0.md)；须确定“人事经理以何种身份、为谁、提供何种服务、由谁付款”的合法路径，及引荐资格、证据/归属、实收口径、去重、费率/期限、预算、合同、财税和试点审批。 | 可设计资格拒绝/补正、贡献记录、推荐转化漏斗及虚构核算样例；**不可**把所有在职人事经理视为可收个人佣金，不能只凭雇主同意付款，不可自动计提/付款、承诺个人提成，把49%写成个人费率或将1元、180天、12个月示例设为现行参数。 |

以上是**评审/上线门禁，不是把产品拆成缩减交付版本的里程碑**。项目经理记录负责人、预期决策日期与依赖；当规则变化时先更新唯一来源和 PRD，再同步本矩阵、原型、技术设计与测试用例。

## 3. 交接签收清单

- 产品：逐条确认当前范围、角色、主/异常流程、来源与规则状态；未决项有记录和决策人。
- 技术：指出实体/版本、跨组织投递、权限和外部集成的技术依赖；不能用技术实现倒推业务授权或收费许可。
- 测试：每个 FR 至少关联正向、拒绝或异常的可观察断言；关键资金/权限/跨组织场景须覆盖 PRD 第 13 节。
- 项目：保留评审纪要与变更记录；把“产品规则通过评审”“开发完成”“联调验证”“允许真实上线”四个状态分别记录。
