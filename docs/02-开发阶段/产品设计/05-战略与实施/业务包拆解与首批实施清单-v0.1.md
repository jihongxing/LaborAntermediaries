## 1. 使用规则与当前状态

BP 为研发业务包编号，DP 为本文件的待决策项，AC 为拟定验收场景，均不是新业务规则或已创建的远程 Issue。FR、G 编号沿用 PRD 与门禁文档。

首批 BP-01～BP-04 拆到任务和验收场景；后续 BP-05～BP-15 先定义范围、依赖、门禁和验收目标，进入开发前按首批粒度补齐，不宣称所有包已具备直接编码条件。复杂包应继续按有独立结果的角色任务拆小，不以整个大包作为单一开发任务。

编制时所有业务包的开发状态为“未开始”、联调状态为“未验证”、真实启用为“未申请”；业务方向与具体规则审批状态须分别核对原文，不统一标成“未批准”或“已批准”。后端底座作为已有依赖，不计作任何业务包完成。

每个进入开发的子任务须具备：

| 必填项 | 要求 |
| --- | --- |
| 来源与价值 | FR、专项章节、用户角色、解决的问题；说明如何服务交易、履约或增长。 |
| 规则与决策 | 规则版本、审批范围、DP/G 编号、决策人与证据；无证据填待确认。 |
| 业务合同 | 输入、前置条件、主/异常流程、输出、状态和可修改时点；明确创建、读取、确认和执行主体。 |
| 研发合同 | 领域对象与不变量、接口/事件、各端任务、组织/项目/本人权限、迁移和外部依赖。 |
| 验收与发布 | 正反向用例、重复/并发/故障场景、环境、证据及回退方式；四类状态分别维护。 |
| 责任与估算 | 产品、研发、测试和决策责任人；未指派填待指定，未估算不填固定日期。 |

### 准入放行结论

- **放行实现：** BP-01～BP-03 的服务端纵向切片，顺序为“受信身份 → 组织创建/加入 → 组织审核 → 需求补正/审核 → 需求发布”。
- **必须保持阻断：** 未通过组织审核不能发布需求；未通过需求审核不能开放应标；平台审核员不能代替组织成员发布需求；未经批准不能收费、代收保证金或产生个人奖励。
- **验证证据：** SQL 迁移、服务端接口、状态转移、审计记录、组织隔离、越权/重复/并发测试和 `backend/` 下的 Maven 验证。真实身份、资质渠道和真实业务启用仍单独记录为未验证或待审批。

- 已完成：首批后端业务 API、V3～V7 迁移、BP-04 应标/选标/确认/快照 API、BP-03 暂停/关闭/改版门禁、平台监督回避切片和 Web 管理端工作台。

## 7. 本轮 BP-04：应标、选标、配额与确认交接

### 7.1 实现合同与状态
