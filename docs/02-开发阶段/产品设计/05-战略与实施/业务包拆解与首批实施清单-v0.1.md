## 1. 使用规则与当前状态

BP 为研发业务包编号，DP 为本文件的待决策项，AC 为拟定验收场景，均不是新业务规则或已创建的远程 Issue。FR、G 编号沿用 PRD 与门禁文档。

首批 BP-01～BP-03 拆到任务和验收场景；后续 BP-04～BP-15 先定义范围、依赖、门禁和验收目标，进入开发前按首批粒度补齐，不宣称所有包已具备直接编码条件。复杂包应继续按有独立结果的角色任务拆小，不以整个大包作为单一开发任务。

编制时所有业务包的开发状态为“未开始”、联调状态为“未验证”、真实启用为“未申请”；业务方向与具体规则审批状态须分别核对原文，不统一标成“未批准”或“已批准”。后端底座作为已有依赖，不计作任何业务包完成。

每个进入开发的子任务须具备：

| 必填项 | 要求 |
| --- | --- |
| 来源与价值 | FR、专项章节、用户角色、解决的问题；说明如何服务交易、履约或增长。 |
| 规则与决策 | 规则版本、审批范围、DP/G 编号、决策人与证据；无证据填待确认。 |
| 业务合同 | 输入、前置条件、主/异常流程、输出、状态和可修改时点；明确创建、读取、确认和执行主体。 |
| 研发合同 | 领域对象与不变量、接口/事件、各端任务、组织/项目/本人权限、迁移和外部依赖。 |
| 验收与发布 | 正反向用例、重复/并发/故障场景、环境、证据及回退方式；四类状态分别维护。 |
| 责任与估算 | 产品、研发、测试和决策责任人；未指派填待指定，未估算不填固定日期。 |

## 4. 首批 BP-01：身份、组织成员与权限

### 4.1 范围与业务合同

- 角色：平台注册用户、组织申请人/管理员/成员、平台审核及复核岗位；具体权限按 DP-02/03 评审。
- 前置：现有底座及独立开发/测试环境可用；身份签发与接入方案须经 DP-01 确认。
- 输入：可信身份、成员授权或组织控制权材料、目标组织及操作；禁止直接信任客户端声明的组织身份和权限。
- 主流程：可信注册/登录 → 申请建立或加入组织 → 核验组织控制权/成员授权 → 服务端生成有效组织上下文 → 按角色进入业务；首次入驻与业务资格由 BP-02 决定。
- 输出：可追溯的账号/组织/成员关系、有效授权及审计事件；成功登录不代表组织审核通过。
- 异常：身份无效/被撤销、成员授权不存在、重复申请、跨组织切换越权、组织停用、成员撤权及历史申诉访问。
- 不变量：同一组织不兼具用工方与劳务公司角色；平台权限不自动成为交易方权限；历史申诉授权不能恢复新业务权限。

## 5. 首批 BP-02：组织入驻与资质审核

### 5.1 范围与业务合同
