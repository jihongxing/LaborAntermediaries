# 多端功能清单与职责边界 v0.1

> **文档状态：草案，待评审**
>
> 本文档用于独立维护平台 Web、独立 App、微信小程序的角色职责、功能范围、权限边界和端间交接关系。本文档尚未最终定稿，不替代产品需求文档（PRD）中的产品范围和业务规则。

## 1. 文档定位

### 1.1 适用范围

本文档适用于产品、业务、交互、研发、测试和交付人员，用于：

- 明确不同端分别服务的角色和工作场景；
- 划分各端承担的功能、数据操作和审批职责；
- 识别端间交接关系，避免同一业务责任在多个端重复或互相覆盖；
- 作为原型、详细设计、接口设计和测试用例的端侧依据。

### 1.2 与 PRD 的关系

- PRD 定义产品定位、业务范围、核心业务规则和验收要求；
- 本文档定义端侧职责、功能清单、权限边界和端间协作方式；
- 原型和详细设计负责页面交互、端间跳转、适配方式及具体组件设计；
- 若详细设计与本文档冲突，应先评审并更新本文档，不应通过页面实现自行改变端侧职责；
- 本文档的“草案”内容不能直接视为已确认的交付承诺。

## 2. 三端总体原则

1. Web、独立 App 和微信小程序共享同一套服务端业务规则、人员/项目/排班/工时记录、权限和审计记录。
2. 端的区别是角色和工作场景的适配，不得各自形成互相覆盖的业务账本。
3. Web 面向组织管理、复杂配置、批量处理和财务工作台。
4. 独立 App 面向项目经理、驻场及授权现场人员的现场履约任务和异常处理。
5. 微信小程序面向工人个人自助和经纪人供给协作。
6. 身份证、银行卡等敏感信息不得出现在公开分享内容中；页面可复用不代表接口权限可以放宽。

## 3. 多端功能与职责清单

| 端 | 核心角色 | 必需页面/能力 | 明确边界 |
|---|---|---|---|
| 平台 Web | 平台审核、运营、风控、财务 | 组织/资质审核、需求审核、风险与申诉、交易/投递异常、平台服务费、机构回执与账务对账、审计与运营配置 | 不替交易方确认现场事实；不审批或执行劳务公司工资、社保、保险等支出，不因此承担合同/付款责任 |
| 用工方 Web | 用工方管理员、业务、财务 | 入驻与成员授权、需求创建/审核状态、应标比较、选标配额、中标结果、项目排班协同、工时差异与结算确认、业务对账及回款状态 | 不修改劳务公司原始打卡；确认权按项目授权和合同规则配置 |
| 劳务公司 Web | 管理员、招聘、项目、财务/资金审批人 | 组织权限、需求与应标、履约方案/供给计划、岗位、招聘归属、人员档案、排班编制、考勤批量核对、异常队列、工时复核、工资/返费、供应商业务对账、平台服务费、资金准备状态及最终资金审批 | 仅经授权的劳务公司资金审批角色可最终批准相应支出/支付指令；不将计划或外部考勤覆盖为平台原始事件；不能越权修改已锁定快照 |
| 独立 App | 项目经理、驻场、授权现场人员 | 现场待办、人员/班次查看、到岗与缺勤登记、打卡事件查询、漏卡核验与补正流转、工时差异跟进、入离职/保险核验、现场协同 | 面向现场履约而非组织复杂配置/财务批处理；补录必须与工人打卡区分并留痕 |
| 微信小程序（工人） | 工人 | 本人岗位/履约关系与班次、上班/下班打卡、本人打卡事件和工时、补正/异议申请、工资条及借支自助 | 仅本人操作和查看；不代替组织排班、审核和最终对账确认 |
| 微信小程序（经纪人） | 经授权的个人经纪人 | 授权岗位、分享/提报、归属结果、推荐进度、返费明细与状态 | 只访问本人合作范围；不参与应标、工人打卡或考勤确认 |

## 4. 端间交接规则

| 业务环节 | 发起/主责端 | 协作端 | 交接结果 |
|---|---|---|---|
| 组织、资质和需求审核 | 平台 Web / 用工方 Web | 平台 Web | 审核状态、补正记录和发布结果可追溯 |
| 应标、选标和配额确认 | 用工方 Web / 劳务公司 Web | 平台 Web | 应标版本、中标结果和项目快照 |
| 排班编制与发布 | 劳务公司 Web | 独立 App、工人小程序 | 工人只能看到本人有效班次；现场人员据此执行核验 |
| 上下班打卡 | 工人小程序 | 服务端、独立 App、劳务公司 Web | 形成不可覆盖的原始打卡事件 |
| 漏卡、异常与补正 | 工人小程序 / 独立 App | 劳务公司 Web、用工方 Web | 申请、核验、审批和执行结果形成审计链 |
| 工时核对与结算确认 | 劳务公司 Web | 独立 App、用工方 Web | 形成确认快照，供工资、供应商结算和平台计费分别引用 |
| 工资、借支和返费 | 劳务公司 Web | 工人小程序、经纪人小程序、独立 App | 个人查询、申请和现场初审与后台核算、审批分离 |
| 资金审批与支付回执 | 劳务公司 Web | 平台 Web、支付机构适配层 | 审批状态、支付指令、机构回执和对账差异可追踪 |

## 5. 权限与数据边界

- 工人只能提交和查看本人相关的班次、打卡、工时、补正、工资和借支信息。
- 经纪人只能访问本人授权合作范围内的岗位、提报、归属和返费信息。
- 项目经理、驻场和现场人员只能在被授权的组织、项目、工厂或人员范围内操作。
- 平台 Web 的审核、风控、运营和对账权限不等于交易方的业务确认或资金审批权限。
- 原始打卡事件只追加、不覆盖；现场补录、外部考勤和人工修正必须保留独立来源和审计关系。
- 已锁定的确认快照不得被普通业务操作直接修改；发生纠错时通过补差、调整或冲正形成新记录。
- 页面复用、端内跳转或接口聚合不得绕过组织、项目、岗位和本人数据权限。

## 6. 暂不在本文档固化的内容

以下内容由原型、详细设计、接口设计或专项规则文档继续明确：

- 页面级交互、信息架构、组件和视觉规范；
- 端间跳转、消息通知和异常恢复的具体交互；
- 具体组织岗位与授权角色的逐项映射；
- App 与小程序的操作系统、微信版本和设备适配要求；
- 端侧接口路径、字段命名、缓存策略和离线策略；
- 保险、电子签、宿舍车辆、外部市场同步等扩展能力的最终范围。

## 7. 待确认事项

1. 各组织类型下管理员、业务、项目、财务和资金审批人的具体授权矩阵。
2. 用工方对排班协同、工时差异和结算确认的实际参与范围。
3. 现场补正、异常证据和用工方确认之间的超时、驳回及升级规则。
4. 工人和经纪人可见的工资、返费、工价及进度信息的最终字段范围。
5. 端间通知、待办聚合、消息送达和失败重试规则。
