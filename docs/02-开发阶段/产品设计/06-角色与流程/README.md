# 角色与流程

- **用途**：从单个角色的完整业务旅程出发，梳理功能、流程、交接和完成依据，避免仅按菜单罗列功能。
- **文档状态**：产品设计与评审材料；不代表相关功能已经开发、规则已批准或真实启用。
- **维护原则**：角色文档是跨业务域视图，不另行维护收费、考勤、资金审批等专项规则；冲突按[产品设计文档地图](../README.md#四文档职责与冲突处理)处理。

## 统一模板

所有角色均按以下六项组织，使用[角色流程通用模板](角色流程通用模板-v0.1.md)新增文档：

1. **角色边界**：代表谁，负责什么，不能做什么。
2. **业务目标**：这个角色最终要完成什么。
3. **功能清单**：可以查看、提交、确认、审批哪些事项。
4. **主流程与异常流程**：正常怎么走，失败怎么处理。
5. **协作关系**：提交给谁，谁处理，结果返回给谁。
6. **状态与凭证**：产生什么记录，何时完成，凭什么认定完成。

角色、组织身份和操作权限必须分开：同一个人可以承担多个角色，但不因岗位名称自动取得审批或资金权限。状态应按业务对象分别定义，不用一个“员工状态”代替报名、入职、派驻、考勤、工资与付款状态。

劳务供应商与用工方文档用于理解各自整家组织如何完成交易与履约，组织内的查看、办理、确认和审批仍按岗位授权拆开，不将整家组织视作一个操作角色；组织分享与成员个人收益资格也分别处理。

平台方文档用于理解运营与治理组织如何协作，不设可跨租户任意查看、代选标、代业务确认或直接扣款的全能管理员；审核、复核、处置、执行、财务和审计按岗位与回避要求分开，平台自身投诉也纳入处理。
