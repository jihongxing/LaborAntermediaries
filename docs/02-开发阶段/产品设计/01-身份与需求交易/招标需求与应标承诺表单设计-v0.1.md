# 招标需求与应标承诺表单设计 v0.1

- 日期：2026-10-20
- 状态：产品设计稿；DP-09/G-02 应标、选标和快照交接规则已于 2026-10-25 确认。其他指标、字段门槛和示例值仍按本文标记待评审，不视为默认业务配置。
- 依据：[平台 PRD](../00-产品全景/PRD-v0.1.md)、[入驻专项](./入驻与资质审核需求细化-v0.1.md)、历史 v0.3 的轻量竞标、多家配额及中标条件快照。
- 已确认边界：平台信息撮合；组织角色互斥；用工方覆盖依法设立主体；劳务公司直接承接仅限合规外包；不展开盈利策略，不缩减后续履约和资金能力。
- “招标”在本文指平台业务中的发需求、应标和选标流程，不声明替代任何适用的法定采购或招投标程序。

## 1. 问题与方案

仅有“岗位、人数、单价、账期”的需求，不能充分说明劳务公司要交付什么、如何比较方案、分配配额后承诺如何变化、未达标如何认定、最后按什么付款。

建议围绕一份结构化条件清单建立四个相互关联的视图：

| 视图 | 谁负责 | 核心内容 |
|---|---|---|
| 招标需求 | 用工方 | 项目与岗位事实、目标、不可偏离条件、商务与验收规则 |
| 应标方案 | 劳务公司 | 逐项响应、量化承诺、报价、资源安排、偏离说明 |
| 中标确认单 | 用工方选标，劳务公司确认 | 实际分配的标项、配额、最终条件及双方接受的承诺 |
| 履约与结算依据 | 履约双方按授权记录、确认 | 实际量、证据、指标结果、应付金额及争议 |

关键原则：招标目标、应标承诺、中标接受值、履约实际值分别保存；不能用一份可反复编辑的表单覆盖全过程。

## 2. 什么是可供应标的有效需求

建议同时满足以下要求才可发布：

1. 发单组织审核有效，经办人有发布权限，实际用工及签约主体清楚。
2. 明确外包服务范围、交付对象、现场协作与责任分工，不只写“缺人”或仅选择外包标签。
3. 至少有一个结构化标项，包含工作地点、服务期间、岗位或服务单元、数量目标和交付节点。
4. 所有用于筛选或决定中标的指标，具有定义、单位、阈值、方向、验收证据及判定时间。
5. 所有影响金额或到期日的条件，具有可执行的数量口径、价格单位、公式、起算事件及付款安排。
6. 硬条件与允许偏离的条件分开；选标方式、可拆分规则和配额规则在应标前可见。
7. 不存在硬性节点、总量、分配下限、价格或日期的内部冲突；当前应标截止早于最早必需服务节点。
8. 完成平台需求审核，待核验事项不冒充审核通过。

不以“可能招得到人”作为发布保证；有效需求是信息可理解、方案可比较、承诺可确认、结果可验收，而不是平台担保成交。

### 2.1 首版发布校验摘要

| 信息组 | 首版必填或条件必填内容 |
|---|---|
| 主体 | 已认证用工方、实际服务接受方、签约及付款主体、必要授权关系 |
| 服务 | 合规外包服务范围、工作地点、服务期、双方职责与联系人 |
| 标项岗位 | 工作内容、数量及单位、现场时段、岗位条件 |
| 目标 | 至少一个数量或交付节点，并说明是硬门槛、评标目标还是信息参考 |
| 应标 | 截止时间、报价规则、多家授予/拆分规则、选标方法 |
| 结算 | 计量定义、结算周期、账期起算事件及日历口径、争议确认流程 |
| 保证金 | 是否启用、保证金类型、金额/计算方式、缴纳主体、收款账户主体、缴纳时点、有效期、退还/扣划条件及争议处理；账户经授权核验 |
| 用工安排 | 实际劳动关系及工资/保险责任；未定工价须标明未定事项及定案责任，不能伪装成已确定岗位条件 |

目标值不是应标承诺；未被选作应标响应、验收、价格计算或合同条件的指标，应明确标记为参考信息。

## 3. 表单结构：八个分步区块

字段标记：必填为建议发布门槛；条件必填在启用相关规则时必须完整；选填不影响基础发布。

### A. 发单组织与项目背景

| 字段 | 填写方式 | 要求 |
|---|---|---|
| 需求名称 | 如“某园区包装服务项目” | 必填 |
| 发单主体、主体类型、认证状态 | 从当前组织带入 | 必填，不允许随意修改冒用 |
| 签约主体、实际服务接受主体、付款主体 | 默认同一主体，不同则展开填写关系及授权 | 必填；不默认允许任意第三方代发、代付 |
| 行业、业务简介 | 分类加简述 | 行业必填，简介选填 |
| 实际服务地点 | 地址、场地或车间说明 | 必填；多个地点拆明细 |
| 项目背景与服务目的 | 简述旺季、产线、交付对象等 | 必填 |
| 服务范围及边界 | 做什么、不做什么、双方责任 | 必填 |
| 项目联系人 | 姓名、岗位、联系方式 | 必填；联系方式按授权展示，不公开给个人经纪人 |
| 需求发布经办人 | 关联组织成员、岗位/职责、可联系时段及联系授权 | 必填；经办权限与选标/采购审批权限分开校验 |
| 选标/采购决策角色 | 组织内角色或审批流程说明，可关联一名或多名授权成员 | 条件必填；用于权限与流程配置，不要求公开个人信息或向个人支付利益 |

平台从认证资料带入发单主体、类型及认证状态。用工方填写本次履约相关的企业/场地介绍，如所属行业、场地规模区间、服务对象、生产或运营周期、现场协作方式；与需求无关的宣传资料选填。自填规模、业绩或付款能力不得显示为平台背书。

分别明确实际服务接受方、签约方及付款方；不一致时说明关系与授权。阐明外包服务范围、交付内容、双方责任，不能只写“派人”或“补人”。公司资料与本次项目信息在发布时生成版本快照，后续公司简介更新不改变历史条件。

### B. 岗位与现场劳务信息

每个标项至少关联一条岗位或服务单元明细；不同地点、工种、计价或验收口径应分行，不能用一个平均价掩盖差异。

| 字段 | 要求 | 对应应标内容 |
|---|---|---|
| 岗位或服务单元名称、工作内容、交付物 | 必填 | 接受或在允许范围说明偏离 |
| 地点、服务开始结束时间、服务时段和班次 | 必填 | 可服务时间、现场安排 |
| 数量及单位 | 必填；区分需求人数、同时在岗人数、人天、人时、件数等 | 承接规模及对应单位 |
| 技能、岗位相关证书、培训及上岗条件 | 有要求时必填，否则明确无额外要求 | 满足情况、证明及培训方案 |
| 工作环境、风险说明、防护和安全培训分工 | 必填 | 落实方案与责任响应 |
| 人员劳动关系安排、劳动合同签署方、工资发放责任方 | 必填，按实际安排说明 | 对应方案及责任确认，不得与实际安排矛盾 |
| 工资组成、计价单位、发薪周期、发薪日期规则 | 由劳务公司承担或组织时条件必填 | 逐项承诺，关联岗位展示及后续工资政策 |
| 保险或其他保障、承担方、保障期间 | 按岗位及适用要求填写 | 必要保障未确认前不得开放相关岗位 |
| 食宿、通勤、餐饮、设备与工装 | 逐项填写谁提供、谁付费或不涉及 | 响应及承担费用 |
| 管理边界 | 谁负责人员组织、排班、现场协调、工作指令及成果验收 | 人员组织与现场管理方案 |
| 工作量预测 | 选填；注明测算假设，不等于保量 | 运力或人员测算假设 |

岗位内容应真实且与服务有关，不提供无约束的歧视性筛选模板。年龄、性别、户籍等不得默认为筛选项，需符合适用规则且与岗位相关。不因选择“人时”自动认定业务性质；仍结合实际安排审核合规外包属性。

### C. 目标与承诺指标清单

不要求用工方自行发明公式。提供预定义指标模板，选择启用后填写阈值及少量参数；自由文字补充不得直接驱动自动结算。

每个指标统一包含：

| 属性 | 含义 |
|---|---|
| 指标编号、适用标项 | 后续应标、选标、履约和结算引用同一编号 |
| 指标名称、定义、单位、优劣方向 | 如“节点合格到岗人数”，单位人，越高越优 |
| 条件类型 | 硬门槛 / 可偏离目标 / 信息说明 |
| 目标值及硬限制 | 目标与最低值、最高值分开；允许只设置适用的一侧 |
| 观测窗口、分子分母、去重与舍入 | 对比例、累计量尤其重要 |
| 证据与确认责任 | 原始记录来源、谁提交、谁确认、争议处理入口 |
| 应标响应方式 | 固定接受 / 填承诺值 / 选择方案；不适用需明确原因 |
| 用途 | 准入、评标、履约验收、结算；一项可有多个用途但各自明确 |
| 未达标后果 | 补足、整改、候补、争议或已约定的金额调整；不能默认扣款 |

建议指标库：

| 指标 | 可配置的目标 | 必须明确的口径 |
|---|---|---|
| 节点合格到岗人数 | 各节点至少多少人 | 通过必要资格、培训并完成约定到岗事件；累计首次到岗和时点实际在岗分开 |
| 同时在岗人数 | 各阶段最低人数 | 某时点或某班次实际人数；不等于历史累计到岗 |
| 有效服务量 | 周期内人时、人天或成果数量 | 已确认有效量；培训、休息、缺勤、加班如何计量 |
| 岗位匹配或验收合格率 | 不低于某比例 | 受验对象、检验方法、去重、窗口及零分母处理 |
| 留任率 | 某批次到岗满若干天后达到比例 | 原始批次为分母，仅纳入已满观察期的人；替补不冒充原批次留任 |
| 缺岗补足时限 | 确认缺口后若干小时或天 | 缺口如何确认、何时起算、补足如何验收、例外归责 |
| 驻场服务配置 | 人员数量、覆盖时段、响应时限 | 哪些是最低配置、哪些是方案比较，不泛用人员数量判优 |
| 服务成果或质量 | 合格交付量、返工率等 | 仅在工作对象和成果确实可度量时启用，不给纯人员服务虚构产量承诺 |

留任率等绩效指标与基础服务量分开：不达留任目标，不自动抹除已发生的有效服务量，更不自动生成对工人的工资扣项。

### D. 报价与结算条件

| 字段 | 要求与表达方式 |
|---|---|
| 报价模式 | 固定价格接受、限价内报价、开放报价三选一；目标价与硬限价分开 |
| 计价项目 | 标项、单位、基础单价、适用期间；有分时段或阶梯价格时展开规则 |
| 价格包含范围 | 人工、管理、食宿、交通、设备、保险等逐项明确包含、不包含或不涉及 |
| 平台管理费/服务费 | 用工方按[《商业模式与收费标准》](../03-账单与资金/商业模式与收费标准-v0.1.md)选择并在需求中披露固定档位；供应商应标前确认知悉并纳入项目经济账；与供应商业务报价、工人工资分开展示 |
| 税费与发票 | 含税或不含税、适用税费口径及发票要求；不同口径不可混排价格排名 |
| 计量与验收 | 数量来源、有效量定义、双方确认及争议流程 |
| 结算周期 | 自然月、约定期间或节点；非“计量单位” |
| 账期 | 起算事件加天数、自然日或工作日；不是只填“月结60天” |
| 工资支付与资金安排 | 实际工资付款主体、合同约定的责任主体、发薪周期、用工方结算账期起算事件及约定 | 条件必填；分别记录，不因代发或账期推定责任转移或平台垫资 |
| 付款安排 | 预付款、阶段款、尾款等启用时填比例或金额、触发事件及冲抵方式 |
| 费用调整 | 额外服务、加班或临时变更何时可计费、谁批准、如何计价 |
| 金额上下限 | 区分预算估算、最高采购额、保底量或最低付款承诺；后两者必须显式约定 |
| 未达标金额处理 | 默认不自动扣减；启用时须明确触发、归责、公式、基数、上限及争议确认 |

### D.1 应标保证金与收款账户

当用工方要求供应商缴纳应标保证金或履约保证金时，需求发布表单新增独立区块并在应标前展示。字段至少包括：

| 字段 | 要求与表达方式 |
|---|---|
| 保证金类型 | 区分应标保证金与履约保证金；说明缴纳是提交应标的前置条件，还是中标后的履约条件 |
| 保证金金额 | 固定金额或计算公式、币种、适用标项及多家中标时的分配/重复缴纳规则 |
| 缴纳主体与期限 | 明确由哪一应标组织缴纳、收款截止时点和适用时区；不得默认由经纪人个人代缴 |
| 收款账户 | 收款户名、开户机构、账号/支付标识、账户主体与发单/签约主体关系、账户核验状态；账户变更需重新核验、版本留痕并通知已应标方 |
| 退还与扣划 | 退还触发事件和期限、可扣划/没收的客观条件、计算方式、证据、通知、异议及争议处理；不得使用无边界的“违约可扣”表述 |
| 凭证与状态 | 分别记录待缴、待核验、已缴、部分缴纳、已退、争议等状态；上传凭证不等于确认到账 |

保证金金额、责任、账户及处置规则须由交易双方在合同或经确认的交易文件中约定。平台默认仅保存信息和核验状态，不代收代管、不承诺账户安全或履约结果；若后续采用平台或第三方托管/支付，须另行完成合同、机构能力与合规审查。保证金不得与工资、供应商结算款或平台服务费混账。

基础计算：

`标项基础应付 = Σ（经确认且未重复结算的有效量 × 对应生效单价）`

`本期应付 = 基础应付 + 已确认增项 − 已确认减项 + 历史补差`

实际已收、剩余应收及付款到期日分别记录；预付款冲抵不能重复计入收入。预算、承诺人数或预计工时都不直接替代确认量。

应标报价规则需选择以下一种：

- **指定单价接受**：用工方给出单价，劳务公司接受或不应标，不提交替代价。
- **最高限价内报价**：用工方填写最高可接受单价，劳务公司报出不超过限价的价格。
- **开放报价**：劳务公司自行报价；用工方预算仅作参考，不能误标为硬限价。

预算、目标价与最高限价是不同字段，不能共用含糊的“期望单价”。

用工方结算价不等于工人工价。劳务公司可在受限区域提交其对工人的承诺工价、单位和发薪安排，沿用现有可见性边界，不向用工方暴露其工资与利润明细。未明确为资格或评分项前，该字段不自动参与中标排名；其必填性沿用 D-15 待定，不因本表新增而默认拍板。

### E. 应标资格与交付方案

- 资格要求：平台认证及当前外包准入为基础，附加要求必须与项目有关，不让用工方勾选资质绕过平台准入。
- 承接范围：选择可承接标项、人数或服务量、首批日期、各节点承诺。
- 履约方案：资源组织、岗位适配、培训、现场管理、补足和应急方案。
- 经验证的案例、证明材料按需提供；历史能力与本项目未来承诺分开展示。
- 平台不根据企业自行填报的“资源池人数”就认定其交付能力已经核实。

### F. 应标与选标规则

- 应标截止、预计选标时间、计划服务开始时间；截止由服务端时间判断。中标确认期限须在需求中显式配置，未配置不得发布，不默认24小时。
- 是否允许部分承接、是否允许多家中标、标项最小及最大授予量、剩余量能否另行补充。
- 每个硬门槛用于资格或响应校验，违反时不得简单通过提高总分抵消。
- 建议默认“通过硬条件后人工综合比较”，不默认最低价中标，也不自动把最高分变成中标。
- 如启用评分，事先定义权重、计分公式、上下限、缺失项、并列处理及评分人权限；权重合计100%，无规则的文字不得自动打分。
- 偏离矩阵并排显示用工方期望、硬限制、应标承诺及差值。用工方可接受允许偏离的方案，但不能选标时私自降低已公布硬条件。
- 硬条件需改变时发布新版本并重新履行审核、通知及响应程序，不静默让某家例外。
- 中标前劳务公司只看自己的方案；沿用历史中标信息公开方向，但数量浮动项目区分预计金额、固定承诺额与实际结算额，不把预计金额称为实际成交款。
- 保证金适用与否、缴纳阶段和核验结果须对所有应标方按同一需求版本一致披露；不得选标后临时增加保证金或改变收款账户/扣划规则。
- 选标/采购权限独立于需求编辑和发布权限；平台只监督规则和程序，不替用工方选标、确认或接受条件。
- 暂停需求冻结修改/重提、选标和双方确认，但允许供应商撤回已有应标；撤回/关闭需求不得继续选标或建立快照，已有应标保留撤回关闭记录。已产生的 BP-05 快照不因需求撤回而删除。
- 每家供应商只能查看自己的应标；用工方查看本需求收到的应标；平台按任务权限查看必要摘要和审计证据，不查看无关供应商的私密报价、利润或承诺工价。

### G. 双方责任与异常处理

- 劳务公司负责事项与用工方配合事项分别列出，如资料、场地、设备、培训条件、验收安排。
- 用工方推迟开工、缩量、停工、拒绝已满足条件的交付，与劳务公司未完成承诺分别处理；责任不能全部默认归劳务公司。
- 缺口、质量不合格或不可抗力的通知、证据、整改和争议路径。
- 有整改义务不等于自动罚款；业务合同中的金额责任也不能直接变为工人工资扣项。
- 现场负责人、验收人及结算确认人按组织成员授权配置，不通过公开附件暴露个人敏感信息。

### H. 附件与发布预览

- 服务说明、现场图片、工作规范、协议草案等；敏感资料按授权展示。
- 结构化字段驱动校验和计算，附件不得悄悄覆盖；发现冲突必须统一或明确为待确认，不带冲突发布。
- 预览展示“公司与岗位介绍、交付目标、硬条件、允许偏离项、报价口径、选标方式、责任与验收”。
- 发布前汇总错误与缺项，草稿可保存，错误只定位到相关字段，不要求全部重填。

## 4. 应标方案与招标字段如何对应

劳务公司不再另写一份无法比较的自由文本，而是在同一结构上响应：

| 招标输入 | 劳务公司填写 | 中标后记录 |
|---|---|---|
| 标项、总量和是否允许拆分 | 承接标项、最大承接量、最小接受量 | 实际授予量 |
| 节点目标 | 本公司节点数量、日期、是否按配额比例调整 | 最终节点承诺 |
| 合格率、留任率、补足时限 | 对应承诺值及方案 | 最终指标定义与接受值 |
| 目标价、硬限价及包含范围 | 同口径报价、税费、费用承担 | 生效价格及范围 |
| 期望账期、付款安排 | 接受或在允许范围提出替代值 | 双方确认的起算及付款条件 |
| 硬条件 | 明确接受并提供必要材料 | 不可绕过的约束 |
| 允许偏离项 | 承诺值、偏离原因及影响 | 明确接受的偏离 |
| 现场与应急要求 | 实施方案、负责人和资源安排 | 合同承诺及履约任务 |

不适用、未填写和承诺为零是不同状态；硬条件不允许以“不适用”绕过。每次修改或撤回重提都追加不可变应标版本；截止后不得新增、修改或撤回应标。已发布需求的关键条件变更必须生成新需求版本并重新审核，供应商须基于新版本重新响应。

## 5. 多家中标：必须解决配额与承诺联动

一份总需求的目标不能原样复制给每个中标方。

1. 用工方总目标保存于需求；劳务公司填写自己的承接方案及容量上下限。
2. 用工方有权人员截止后按标项选标，分配授予量不得超过公司已承诺容量或需求剩余量；招募替补所需累计人数不与同时在岗配额混算。
3. 每个节点明确属于固定数量、按授予量比例计算或需要重新确认；比例人数的取整及余数分配必须在需求中显式配置，否则不得发布或选标。
4. 授予量变化可能影响单价、驻场配置和节点承诺。只有事先声明的适用区间或公式可直接计算，不能默认所有字段等比例缩放。
5. 每家公司分别确认完整最终方案；确认一家后即可为该供应商幂等交接一份 BP-05 快照，不必等待其他中标方确认。拒绝或超时释放该配额并允许按授权重新选标；不允许用工方单方面改承诺。
6. 最终快照包含需求版本、应标版本、标项、授予量、节点、指标定义、价格、账期、验收、责任和已接受偏离。
7. 后续增量、补选、替换中标方保留原授予记录并重新确认；不得直接编辑旧配额使历史履约失去依据。

## 6. 端到端填写示例

以下均为虚构示例值，不是推荐工价、法定标准或已批准政策。

用工方发布包装服务标项：2026-11-01至2026-11-30，最终同时在岗目标100人；11月1日首批50人、11月5日达到100人，允许多家中标。最低单家授予20人。采用经确认有效人时计价，无最低工时保证。

| 项目 | 用工方要求 | 公司A应标 | 公司B应标 |
|---|---|---|---|
| 可承接人数 | 总需求100人、可拆分 | 最多60人、最少40人 | 最多60人、最少20人 |
| 首批节点 | 授予量的50%，需确认取整 | 30人/承接60人方案 | 30人/承接60人方案 |
| 最终节点 | 11月5日达到授予量 | 接受 | 接受 |
| 缺口补足 | 硬上限48小时 | 承诺24小时 | 承诺48小时 |
| 结算价 | 目标26元/有效人时，硬限价27元 | 25.5元，同口径 | 26元，同口径 |
| 账期 | 目标为月结算单确认后30自然日，允许偏离 | 45自然日 | 30自然日 |
| 工时保量 | 无 | 接受 | 接受 |

若授予A公司60人、B公司40人，则首批分别为30人、20人。只有B公司事先接受节点随授予量同比例调整且价格适用于40人的情况，才能据此生成待确认方案；否则须由B公司重新确认完整最终条件。

本例未设置价格评分权重，用工方看到A报价较低但账期偏离、B价格较高但账期更匹配，不生成虚构“最优公司”。未达硬条件的方案不能通过综合比较补救。

A最终快照为60人、对应节点、24小时补足、25.5元/有效人时、结算单确认后45自然日付款等完整条件。

若某结算期A的有效确认服务量为10,000人时，无增减及补差，则基础应付255,000元，而不是按60人或预算直接计算。数量存在争议时，已确认部分与争议部分分开；补足指标未达标但未约定金额规则时，只记录履约异常，不自动扣款。

“结算单确认后45日”只明确了账期，仍需同时约定结算提交、确认及争议处理流程；不设置无限期拖延的隐含入口，也不默认超时自动确认。企业付款条件不自动改变工人既定发薪日期。

## 7. 用户故事与验收

1. 作为用工方，我能从认证资料带入主体信息，并明确实际服务、签约与付款关系。
2. 作为用工方，我能按地点、岗位和计价口径拆分标项，而不是把多个不同项目混为一个价格。
3. 作为用工方，我能选择标准指标模板，区分硬限制、目标和信息项。
4. 作为劳务公司，我能逐项提交承诺，知道哪些允许偏离及哪些影响金额。
5. 作为评标人，我能在相同单位、税费和服务范围下比较方案，而不是只比较一个数字。
6. 作为选标人，我能分配多家配额，并发现容量、节点、价格区间冲突。
7. 作为中标公司，我能在确认前看到完整最终条件，拒绝未接受的单方变更。
8. 作为履约人员，我能按快照提交实际记录和证据，区分累计到岗、在岗及计费量。
9. 作为结算人员，我能追溯金额公式和确认数量，不把招标目标直接当结算数量。
10. 作为工人，我的工资不会因企业间某项指标未达标被系统自动扣减。
11. 作为平台审核员，我能识别缺失口径、附件冲突及超出当前准入范围的需求。
12. 作为审计人员，我能还原发布、应标、授予、中标确认及后续调整版本。

建议按“发布—应标—选标确认—履约结算”业务接口边界验证外部行为，不依赖页面内部组件：

- 硬限价27元的方案报28元，不能被当作允许偏离的目标价处理。
- 有比例指标但缺少分母、观察期或零分母规则，不能发布为可自动判定指标。
- 公司承诺最多60人，授予61人被拒绝；不允许部分承接时不能拆授。
- 总量100人分给60和40人后，系统不再接受无增量依据的新授予。
- 结算单位人天、报价单位人时且无明确定义时，不自动换算。
- 已确认10,000人时计入一次结算后，重复导入不再次计费；后续调整有来源。
- 留任目标未达但没有金额处理条款时，不生成罚款或工资扣项。
- 未满留任观察期的人不误计为流失，替补不能填入原批次分子。
- 附件写30日、结构化账期写45日时，必须消除冲突才发布。
- 更改已发布硬条件触发新版本及重新响应规则，原应标不静默沿用。
- 经纪人不能获取未授权的用工方联系方式、公司报价、应标或中标权限。

仓库目前没有这些业务模块的测试实现，本轮仅定义未来验收边界，不新增测试框架或声称功能已实现。

## 8. 当前建议与待评审项

- 建议主结构采用八个分步区块，共享指标字典及招标、应标、中标三层数值。
- 建议默认人工综合选标，自动评分为显式配置，不默认最低价中标。
- 建议先以节点到岗、同时在岗、补足时限及可明确计量的服务量作为基础指标；留任、质量和成果指标按适用场景启用。
- 指标是否必填、默认启用项、岗位层级与标项层级的页面组合及金额责任条款仍需负责人评审；自动评分不是默认，只有在需求中显式配置完整规则后才可启用。
- 本轮不设具体价格、比例、责任金额和固定确认时长；应标确认时限由需求显式配置，未配置不得发布。比例配额的取整和余数必须显式配置，示例不写入默认值。
- 首版优先确保少量必填字段使需求可比较、承诺可验收、金额可结算；工资、保障、返费和绩效规则按实际场景条件展开。
- 不新增远程 Issue，不改变商业模式，不把本次表单设计扩展成完整法定招投标系统。
- 用工方联系人（如人事经理）与选标/采购决策人可为不同角色，应分开记录授权和流程；不得将联系人个人信息用于未经授权的销售，也不得默认向客户员工个人支付佣金或决策分成。
- 保证金、工资支付/账期和平台服务费分别记录、分别约定；任何个人奖励、资金托管或平台代收安排均须另行评审，不作为本表单默认交易条件。
