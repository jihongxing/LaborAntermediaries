# 需求追踪与交接门禁 v0.1

- 整理日期：2026-10-23
- 状态：产品/项目经理工作底稿；映射已记录的需求，不等于通过评审或新增开发承诺。
- 用途：把 [PRD v0.1](PRD-v0.1.md) 的功能编号、专项依据、验收证据和待决事项交给研发与测试。详细业务规则始终以来源文件为准，本文不另设收费、期限、金额或技术实现。

## 1. 需求到验收的追踪矩阵

下表中的“交接前确认”是**需要明确的规则或前置条件**，不是把整项功能从已确认的产品范围移出。每项由产品经理提供业务判定，项目经理跟踪评审与依赖，技术负责人确认接口/数据方案，测试负责人确认可观察的结果。

| PRD 编号与业务结果 | 细化依据 | 最小可观察验收证据 | 交接前确认 / 不能擅自默认 |
| --- | --- | --- | --- |
| FR-01 账号、组织、成员与数据权限 | [PRD](PRD-v0.1.md)、[多端职责](多端功能清单与职责边界-v0.1.md) | 无成员关系、跨租户/跨项目、导出与附件越权均被拒绝。 | 组织岗位与端内权限矩阵需评审。 |
| FR-02 双角色组织准入及资质审核 | [入驻专项](入驻与资质审核需求细化-v0.1.md)、[用工方标准](用工方入驻与有效需求标准-v0.1.md) | 审核状态、补正记录留痕；未通过主体不能开展受限业务，存量权限按规则处理。 | 材料矩阵、资质核验、暂停及恢复门槛待评审。 |
| FR-03 有效需求、审核与发布 | [用工方标准](用工方入驻与有效需求标准-v0.1.md)、[表单设计](招标需求与应标承诺表单设计-v0.1.md) | 组织与需求分别过审，关键条件缺失/冲突不能开放应标；版本变更可追溯。 | 核验深度、字段门槛、关键变更与重审条件待评审。 |
| FR-04 应标、多家中标与配额 | [表单设计](招标需求与应标承诺表单设计-v0.1.md) | 配额不超需求/承诺量；供应商确认最终条件；落标方私密信息不泄露。 | 承诺工价是否必填、中标确认时限和异常释放规则待确认。 |
| FR-05 中标条件与项目快照 | [PRD](PRD-v0.1.md)、[战略与履约补充](战略与履约流程补充需求整合-v0.1.md) | 重复中标事件只建一个项目；旧合同和政策快照不被新政策覆盖。 | 更正与跨组织确认权限需产品/技术联合评审。 |
| FR-05A 履约方案与供给计划 | [战略与履约补充](战略与履约流程补充需求整合-v0.1.md)、[协同供给产品流程与规则建议](劳务公司协同供给产品流程与规则建议-v0.1.md) | 计划、候选、到岗、有效履约分别记录；缺口可创建受控协同请求；多源同人不重复计数。 | 首期触达范围、协同响应字段、用工方批准条件、人员/合同责任和结算边界待负责人确认。 |
| FR-06 岗位、渠道、报名与撞单 | [PRD](PRD-v0.1.md)、[战略与履约补充](战略与履约流程补充需求整合-v0.1.md) | 重复投递可识别；报名/推荐归属可追溯；权限范围外无法查看个人数据。 | 跨来源重复人员认定、保护期及授权范围待确认。 |
| FR-07 招聘、入职、保险核验与离职 | [PRD](PRD-v0.1.md) | 入离职与保险状态关联项目/人员，变更留下证据和操作记录。 | 适用用工关系下保险、签约及责任主体需专项确认。 |
| FR-08 排班、打卡、差异与确认 | [排班工时流程](排班-打卡-考勤核对-资金审批流程-v0.1.md)、[考勤协作草案](合作用工方考勤系统产品与集成设计-v0.1.md) | 原始打卡/外部记录并存；漏卡可补正，争议量不作为无争议结算量。 | 异常处理时限、计算口径及合作系统接口方案待评审。 |
| FR-09 工资、工资条与借支 | [PRD](PRD-v0.1.md)、[排班工时流程](排班-打卡-考勤核对-资金审批流程-v0.1.md) | 未实际支付的借支不扣回；不足时不产生负实发；工人只见本人数据。 | 责任主体、工资/借支限额及审批规则需确认。 |
| FR-10 返费政策与权益 | [PRD](PRD-v0.1.md) | 已锁定权益不被新政策覆盖；经纪人看不到工资或供应商结算价。 | 日结天数口径、起算/上限、税费与收款主体不得沿用历史默认值。 |
| FR-11 分类账单、服务费与对账 | [收费唯一文档](商业模式与收费标准-v0.1.md)、[资金流程](资金账户与支付指令流程-v0.1.md) | 工资/返费/供应商结算/平台费分账单；争议量、有效计费人天及实收分开显示。 | 已批准档位可按约定配置；合同、收取结算及争议规则未批准前不得实收。 |
| FR-12 第三方支付指令、状态与恢复 | [资金流程](资金账户与支付指令流程-v0.1.md) | 无授权审批不执行；余额不足暂停；未知结果先查询，回调/重试不重复支付，机构回执可对账。 | 账户产品、机构能力、资金权属及合同法律结构须验证，模拟不能充当真实验收。 |
| FR-12A 线下回款与账期核对 | [资金闭环与账期分析](资金流转闭环与账期模型分析-v0.1.md)、[资金流程](资金账户与支付指令流程-v0.1.md) | 用工方可线下支付至劳务公司对公账户；平台记录应收、到期、部分回款、凭证核对、短款和逾期，不把线下回款显示为平台已收款。 | 回款凭证来源、流水接入、核销权限、逾期规则和跨账单匹配待评审；工资/协同/平台费到期日不得由项目回款日自动推导。 |
| FR-12B 机构支付与保理融资协同 | [未来平台支付与保理资金架构建议](未来平台支付与保理资金架构建议-v0.1.md)、[战略路线](产品战略路线与可选增值渠道-v0.1.md) | 平台可统一编排支付批次；银行/持牌支付机构执行收付；保理机构独立决定融资、回款和风险；平台普通运营主体不直接持有客户资金。 | 受监管账户、支付授权、融资合同、债权转让/通知、资金瀑布、支付白名单和机构接口能力必须专项评审；未经确认不得开发自营资金池或平台直接放款。 |
| FR-13 提醒、逾期、保证金与风控 | [PRD](PRD-v0.1.md)、[表单设计](招标需求与应标承诺表单设计-v0.1.md) | 暂停新应标不阻断存量工时/申诉/补发；未知支付不触发错误风险标签。 | 预警阈值、保证金类型/处理与托管边界待定。 |
| FR-14 跨组织投递、审计与导出 | [PRD](PRD-v0.1.md)、[多端职责](多端功能清单与职责边界-v0.1.md) | 旧事件不复活撤回需求，重复事件不双建项目，审计和导出不越权。 | 投递契约、事件版本与可见范围由产品/技术共同定稿。 |

PRD 第 13 节有更完整的跨功能场景；上表的短句不替代该节，也不证明测试已通过。对每条需求建立评审记录：`FR 编号 / 业务规则版本 / 决策状态 / 决策人及日期 / 技术依赖 / 验收用例 / 证据链接`。无证据时填写“待确认”，不要推断为“已通过”。

## 2. 优先决策清单与阻断范围

| 决策包 | 应作的产品/项目决策 | 未决时可做 / 不可做 |
| --- | --- | --- |
| G-01 组织与需求准入 | 谁审核、所需材料、角色授权、需求可见性、补正与版本再审。 | 可梳理状态和权限原型；**不可**将建议字段门槛写死并让未审需求进入真实应标。 |
| G-02 应标与中标 | 配额/承诺确认、工价、时限、异常回退及中标快照。 | 可设计版本与测试样例；**不可**以历史默认规则锁定合同或自动建项目。 |
| G-03 履约与有效计量 | 供给关系、现场/用工方复核权限、工时差异、有效人天及返费口径。 | 可保留数据来源并编写异常用例；**不可**用单一打卡或未确认人天自动产生无争议账单。 |
| G-04 收费与合同 | 与[收费唯一文档](商业模式与收费标准-v0.1.md)逐项核对收费对象、计费量、合同、收取时点和结算方式。 | 可实现已批准规则的配置与演算；**不可**因费率获批就开启实收或收取未来保理规划费。 |
| G-05 资金和对外联调 | 机构能力、责任主体、账户/资金权属、授权、回执与异常恢复。 | 可隔离环境设计适配器与模拟场景；**不可**在缺乏机构/合同/合规结论时启用真实资金通道。 |
| G-06 多端与上线 | 端间交接、关键权限、真实场景验收、严重风险修复和运维责任。 | 可依业务依赖并行设计各端；**不可**因某端页面未完成而单方面删去独立 App 或完整履约/资金范围。 |

以上是**评审/上线门禁，不是把产品拆成缩减交付版本的里程碑**。项目经理记录负责人、预期决策日期与依赖；当规则变化时先更新唯一来源和 PRD，再同步本矩阵、原型、技术设计与测试用例。

## 3. 交接签收清单

- 产品：逐条确认当前范围、角色、主/异常流程、来源与规则状态；未决项有记录和决策人。
- 技术：指出实体/版本、跨组织投递、权限和外部集成的技术依赖；不能用技术实现倒推业务授权或收费许可。
- 测试：每个 FR 至少关联正向、拒绝或异常的可观察断言；关键资金/权限/跨组织场景须覆盖 PRD 第 13 节。
- 项目：保留评审纪要与变更记录；把“产品规则通过评审”“开发完成”“联调验证”“允许真实上线”四个状态分别记录。
