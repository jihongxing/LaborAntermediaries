## 1. 试点边界

试点只使用新建的合成账号、合成组织、合成审核事项和合成监察发现。不得导入真实手机号、身份证件、组织登记材料、合同、银行卡、报价或生产审计事件。认证使用 `local`/`test` profile 的 Mock SMS；生产 profile 禁止 Mock SMS。材料扫描未配置真实 ClamAV 时保持失败关闭，不能用模拟扫描结果证明生产扫描服务已经部署。

首期可验证的业务范围是：组织申请提交、组织审核任务认领与决定、监察查询/覆盖/事项历史、监察发现创建/回应/独立复核，以及平台岗位授予、双人审批和撤销。平台岗位管理完整页面、投诉案件、高影响措施、原件下载/导出、支付/收费、履约和真实外部身份适配均不在本试点。

## 2. 开始前检查

1. 从仓库根目录检查 `3000` 监听进程的完整命令行。只有确认是本项目 `frontend/web-admin` 的旧 Vite 服务时才停止并重启；其他进程占用时报告冲突，不改用 `3001`、`3002`。
2. 检查后端 `8080` 是否空闲。后端启动必须明确绑定 `127.0.0.1:8080`；仅在完整命令行确认是本项目旧服务时停止旧进程并在原端口重启。其他进程或归属不明时报告冲突，不自动递增端口。
3. 测试库名称必须以 `_test` 结尾，并通过 Podman 独立 PostgreSQL 连接。集成测试会清空技术测试表和隔离业务表，禁止指向开发库或生产库。
4. 检查 `AUTH_ENABLED`、私钥、公钥、手机号 HMAC 密钥和加密密钥来自运行环境外部；不要把凭据、验证码、令牌或密钥写入仓库、截图或工单。
5. 生产或预生产不得设置 `AUTH_MOCK_SMS_ENABLED=true`，不得启用未完成专业评审的材料类别、原件下载/导出或真实跨组织监察范围。

## 3. 授权与撤销演练

使用正式注册流程创建合成账号后，按以下顺序验证：

1. 通过一次性离线引导建立首个 `AUTHORIZATION_ADMIN`；目标账号必须已存在、为 `ACTIVE` 且没有组织成员关系。
2. 由首位授权管理员授予第二位 `AUTHORIZATION_ADMIN`。
3. 由授权管理员为监察员申请 `INDEPENDENT_AUDITOR`，由另一位无冲突授权管理员批准；申请人自批必须返回 403。
4. 使用监察员会话验证查询、覆盖、事项历史和发现页面；普通账号和错误岗位必须返回 403。
5. 通过双人流程撤销监察岗位。撤销后，旧 Access Token 的受保护请求必须立即失效；新会话的 `platform-context` 必须返回 403。
6. 记录授权申请、批准、拒绝、撤销、旧令牌拒绝和新会话拒绝的 `requestId` 与数据库审计事件编号。记录中不得保存令牌正文、密码或验证码。

## 4. 审计与恢复演练

在独立 `_test` 库执行完整门禁：

```powershell
cd backend
$env:TEST_DATABASE_URL = 'jdbc:postgresql://127.0.0.1:55444/<独立_test库>'
$env:TEST_DATABASE_USERNAME = '<测试账号>'
$env:TEST_DATABASE_PASSWORD = '<测试密码>'
mvn -Pintegration clean verify
```

应保留以下结果：Flyway 全序列成功；单元和集成测试无失败；Checkstyle、JaCoCo 和 `mvn validate` 通过；审计故障文件可强制刷盘；数据库恢复后对账补记幂等；哈希链核对能发现篡改、缺失、重复和链头不一致；ClamAV 测试容器健康且 INSTREAM 对合成 clean 样本返回 `OK`、EICAR 测试样本返回 `FOUND`，应用 `ClamAvEvidenceContentScanner` 对同一两类样本分别返回 clean=`true` 和 `false`。`AUDIT_FAILURE_RECOVERY_ENABLED=true` 只在数据库恢复后的受控启动中使用一次，核对完成后立即关闭。

故障文件通过 `AUDIT_FAILURE_LOG_PATH` 指向与数据库故障域隔离的持久卷。故障文件容量、写入失败、数据库恢复、哈希链核对失败和 readiness 失败都必须进入已有监控或值守告警；未配置独立故障域时不得声称生产审计恢复可用。

异常解除认领演练须核对：独立恢复岗位无事项详情或材料权限；原认领关闭理由和时间保留；任务回到同岗位队列且原总历时不重置；同一事务创建原认领人的最小站内通知，其他账号读取为空，匿名读取拒绝，岗位撤销后个人账号仍可读取；通知与操作分别可在审计中定位。生产对外通知方式和留存期限仍待法律、隐私与运营签核。

## 5. 值守与问题上报

每次试点执行指定一名运行负责人、一名安全复核人和一名产品联络人；具体姓名、联系方式和轮值安排在启用前由运营负责人填写。问题上报至少包含：发生时间、环境、功能范围、`requestId`、是否阻断、合成数据编号、当前授权状态和已采取的回退动作。禁止附带手机号、密码、验证码、Access Token、Refresh Token、私钥、原件或完整请求体。

收到授权越权、跨组织泄露、审计无法写入/恢复、材料扫描失败开放、端口或数据库指向错误环境等问题时，立即停止试点相关操作，撤销相关岗位或关闭认证开关，保留最小诊断证据并通知安全复核人。严重等级、通知时限、法律报告和外部服务目标不在本文件中预设，须由专业责任人确认。

## 7. 回退

发现未授权访问、审计链不一致、故障恢复失败或数据边界不确定时，先停止相关工作台路由和岗位授权，撤销新授岗位，关闭 `AUTH_ENABLED` 或回退到仅健康检查模式；保留审计故障文件和必要的请求标识，禁止删除证据掩盖问题。恢复前重新执行独立 `_test` 验证、权限拒绝检查和审计完整性核对。任何真实启用回退都必须由有权负责人确认并留下决定记录。
